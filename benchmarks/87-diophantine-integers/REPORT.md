# Diophantine solving: Mathilda `Solve[..., Integers]` vs sympy

Experiment 87. Generated by `run.py` (edit `cases.py`, not this file).

- Mathilda: `Solve[eqns && constraints, vars, Integers]` (integer pre-pass, `src/solveint.c`).
- sympy 1.14.0: `sympy.solvers.diophantine.diophantine`, plus a same-box Python search as the fallback a sympy user writes when `diophantine` cannot answer.
- Timing: Mathilda = min of the case's reps via `AbsoluteTiming` (in-process, excludes binary start-up); sympy/Python = one `perf_counter` run. Python search budget 25s.
- Run date: 2026-08-18

## Headline

- **Mathilda** returns the finite, constraint-satisfying set for **19 of 19** cases; **19 of 19** match the known count.
- **sympy `diophantine`**: **3** answered directly & comparably (all sum-of-squares), 1 only after manual elimination + box-filtering (*), 1 ruled empty via gcd, 3 parametric-only (no bounded answer), **11 NotImplementedError** (every mixed/cubic/exponential form, and every *system* -- diophantine takes one equation).
- `*` = the finite count sympy returns is **not** the answer to the constrained problem; it still needs hand-elimination and/or filtering (see Notes).

## Notes

- **two-squares-25** -- x^2+y^2=N: fixed by even-only symmetric bound (was {} before).
- **two-squares-1e6** -- Gaussian-integer count; Mathilda enumerates the exact leaf.
- **three-squares-29** -- sympy needs permute=True to expand base reps to all 72 tuples.
- **linear-3var-box** -- diophantine returns a 2-parameter family; the positive count needs a search on top.
- **linear-huge-coeff** -- gcd(coeffs)=3 does not divide 1: no solution. sympy sees it via gcd instantly.
- **pell-61** -- D=61 has a famously large fundamental solution (1766319049, 226153980).
- **pell-negative** -- Negative Pell is solvable iff the sqrt(D) CF period is odd; D=2 qualifies.
- **pythagorean-perimeter** -- A 2-equation system: diophantine takes one equation, so z is eliminated by hand, then the 252 conic points are filtered down to the 3 triangles.
- **motivating** -- The motivating case: {15,12},{41,10},{57,6}.
- **two-quadratics** -- Positivity of the first equation bounds the whole box; no solution. sympy cannot express the coupled system at all.
- **egyptian-4/2027** -- Unit-fraction expansion; 73 ordered decompositions.
- **markov-1000** -- A naive triple loop is 10^9; both Mathilda and the Python column instead solve the quadratic in z by its discriminant (O(bound^2)). One of the few cases the tuned Python search edges Mathilda -- sympy still has no Markov solver at all.
- **sum3cubes-3** -- Only {1,1,1} in the positive box (the other, {4,4,-5}, is negative).
- **sum3cubes-42-bigbox** -- 8x10^15-point box: infeasible to brute; Mathilda uses the s=x+y | m divisor method.
- **mordell-10000** -- Elliptic curve; sympy reports cubic_thue NotImplemented.
- **taxicab-1729** -- Naive 4-index search; Mathilda uses meet-in-the-middle.
- **euler-5th-powers** -- The Lander-Parkin counterexample 27^5+84^5+110^5+133^5 = 144^5.
- **catalan** -- Variable exponents: not a polynomial at all. Only 3^2 - 2^3 = 1 (Mihailescu).
- **boxed-power** -- Explicit box + perfect-square leaf.

## Method

`cases.py` is the single source of truth: one row per family with the exact Mathilda expression, the sympy polynomial, and a Python search over the *same* box. `run.py` emits `diophantine.m`, runs it once, then runs the sympy and Python columns in-process and joins by label. Solution **counts** are the invariant compared (ordering and radical spelling are not); sum-of-squares cases pass `permute=True` so sympy expands its base representatives to the full signed/ordered set Mathilda enumerates.
