# 256 — the integration shootout

Every applicable Mathilda `Integrate` method, and four other systems, on one corpus
of 1151 indefinite integrals. Every answer is verified by the system that produced
it.

```bash
make bench-integrate                                   # everything installed, ~2 h at 6 jobs
python3 tools/integration_shootout/shootout.py --quick --systems mathilda,fricas --check
python3 tools/integration_shootout/shootout.py --classes M --families lccontent --fresh
python3 tools/integration_shootout/test_shootout.py    # the harness's own unit tests
```

## What runs

| run | on |
|---|---|
| `Mathilda:Automatic` | every case: the full cascade |
| `Mathilda:ParallelMixedTower` | every case: the Risch–Norman heuristic |
| `Mathilda:RischTranscendental` | R and T: the transcendental Risch–Bronstein decision procedure |
| `Mathilda:Trager` | A: Trager's algebraic algorithm |
| `Mathilda:Bronstein` | M and B: Bronstein's mixed algebraic–transcendental algorithm |
| `FriCAS`, `Maxima`, `sympy`, `Wolfram` | every case, when installed (`fricas`, `maxima`, python3.11 with sympy, `wolframscript`) |

## The corpus (`corpus.tsv`, generated by `tools/integration_shootout/gen.m`, seeds 1–3, 12 per family)

| class | | families |
|---|---|---|
| R | rational | Hermite-heavy repeated poles; logarithms of irreducible cubics (RootSum) and ArcTan |
| T | transcendental | log, exp, mixed, nested (`Log[Log x]`, `E^(E^x)`), trigonometric, constant factors in kernels; perturbed |
| A | algebraic | all of `tests/data/trager_stress_corpus.m` (Chebyshev, Goursat, pseudo-elliptic, genus 0–3, torsion-heavy, …) and generated `b(x) y + c Log[p + q y]` |
| M | mixed, radical on top | the ten Bronstein stress families (`tools/integration_shootout/families.m`); random and perturbed |
| B | radical at the bottom | `Log[x] Sqrt[x^2+a]`, `E^x Sqrt[1+x^2]`, …; perturbed |

Every integrand has an `expect` label:
- `elem`: it is `D[F]` for the recorded F, or the corpus (Trager's) cites a theorem.
- `nonelem`: a theorem says so. Examples are Liouville's `E^(x^2)`, `E^x/x`,
  `1/Log x`; Chebyshev's binomial criterion; a holomorphic differential.
- `unknown`: a perturbed or random integrand, decided only by the runs themselves.

## Verification

Each case carries three rational points where f is finite and real, and every
radicand and log argument is positive. Each system differentiates **its own**
answer and evaluates `D[F] - f` there, in its own arithmetic, to at least 30 digits.
An answer passes when `|D[F] - f| <= 10^-20 max(1, |f|)` at every point that
evaluates.

Nothing is translated back between systems, and branch cuts cannot interfere,
since derivatives are compared at real points. Integrands reach each system through
`translate.py`, from Mathilda FullForm. `test_shootout.py` evaluates the
translated integrand in sympy and Maxima at the corpus points and compares the
result with the corpus's own 40-digit `f(p)`. So a mistranslation cannot pass as a
system failure.

The Wolfram column is a comparison column like the others. It is never an
oracle: its answers pass or fail by the same check.

## Classes and verdicts

Per run:
- `ELEM`: verified, elementary.
- `SPECIAL`: verified, but it uses Erf, Ei, an elliptic function, a
  hypergeometric function, …
- `CERT`: Mathilda proved the integrand non-elementary (`Integrate::nonelem`).
- `WRONG`: the run's own derivative check fails.
- `UNVERIFIED`: the answer could not be evaluated at any point.
- `UNEVAL`, `TIMEOUT`, `ERROR`.

Across runs, for Mathilda:
- **hard failures**:
  - `WRONG`;
  - `FALSE_CERT`: a CERT on an `elem` case;
  - `DISAGREE`: a CERT while some other run has a verified ELEM answer;
- **reported**:
  - `AUTO-GAP`: a dedicated method closes the case but Automatic does not;
  - `ONLY-<system>`: only one system closes it.

Another system's WRONG is listed as that system's bug.

`--check` fails on any hard failure. It also fails when a Mathilda method's closed
count for a class falls below `baseline.json` (a ratchet; `--update-baseline`
records the current counts). The nightly ctest `integration_shootout_stress` runs
`--quick --systems mathilda,fricas --check`.

## Output

- `REPORT.md` (full runs; partial runs write `REPORT-partial.md`):
  - closed % by class, for every run;
  - outcome counts with median times;
  - a per-family table;
  - every hard verdict, AUTO-GAP and ONLY-X, with integrands;
  - the other systems' wrong answers.
- `results/<date>.json`: every run of a full shootout. `results/cache.jsonl`:
  the resumable run cache (untracked).
- `history.jsonl`: one line per full run, the closed count per run, for the arc.
