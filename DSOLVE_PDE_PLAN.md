# DSolve for PDEs: implementation plan

This is the roadmap for symbolic PDE solving in `DSolve`. It is the PDE
counterpart of [`docs/notes/DSOLVE_PLAN.md`](docs/notes/DSOLVE_PLAN.md), which
covers ODEs, and it is measured against a corpus the same way the ODE campaign is.

- **Corpus:** N. Abbasi's *PDE in CAS*, 2011 problems, in
  [`DSolve_test_status/pde/`](DSolve_test_status/pde/README.md).
- **Dashboard:** [`DSolve_test_status/pde/STATUS.md`](DSolve_test_status/pde/STATUS.md),
  regenerated by `tools/dsolve_pde_corpus_report.py`.
- **Method buckets:** [`DSolve_test_status/pde/classes.tsv`](DSolve_test_status/pde/classes.tsv),
  written by `tools/pde_corpus/classify_pde_corpus.m`. Each record is classified
  structurally from the equation alone, with no `DSolve` call. That joins every gap
  to the method that would close it.

The wave order below comes from the measured gaps, not from guesswork. Every
number here is reproducible from the files above.

## 1. Where PDE DSolve stands

### 1.1 Implemented methods

Dispatch order is in `src/calculus/dsolve.c` (the `P.is_pde` branch). The first
verified result wins.

|---|---|---|---|---|---|
| 1 | `DSolve`PDELinearFirstOrder` | `dsolve_pde1.c` | `a u_x + b u_y + c(x,y) u == f(x,y)`, with **a, b constant**, by characteristics and an integrating factor | none | explicit `C[1][a y − b x]` |

**Shared limits.** Every method except 6 requires `nfun == 1 && nind == 2 && neq == 1`.

- `ds_is_condition` recognises only single-variable conditions, so methods 6–8 each
  sort their own two-argument conditions.
- The arbitrary-function pinning in `dsolve_verify_pde` covers `C[1..4][z_]`, i.e.
  one argument only.
- The PDE branch ignores `Method -> …`.
- `Inactive[Sum]` (series) answers do not exist yet.

### 1.3 Wrong answers the corpus found on day one

The PDE gate tracks FAIL separately and drives it to 0 (§3). The first run found
11 wrong answers in shipped methods, plus two harness-surfaced defects (v0.6501). All were
fixed the same day, each with a regression test:

| Version | Defect | Fix |
|---|---|---|
| v0.6497 | `D[f, {x}]` gave `D::dvar` and stayed unevaluated. The corpus spells almost every PDE this way. | `{x}` now means `{x, 1}` (`tests/test_deriv_array.c`). |
| v0.6498 | d'Alembert and the heat kernel **dropped forcing and extra derivative terms**: `u_tt == 4 u_xx + Cos[t]` and `u_t == u_xx + Sin[x]` got the homogeneous answer (pde-381, pde-391). | Each method now requires the residual to equal its model operator exactly. |
| v0.6499 | `DSolve`FirstOrderSubstitution` returned `Integrate[g, x + y[x]]`, integrating with respect to an *expression*. The characteristic invariant of `w_x + f(a x + b y + c) w_y == 0` and its 8 Polyanin siblings were therefore meaningless (pde-615 … pde-804). | A definite `Inactive[Integrate][g(K), {K, 1, v}]`, which D differentiates. |
| v0.6499 | `PossibleZeroQ[f[2 (x + 1)] - f[2 x + 2]]` was **False**: inert calls were keyed on spelling, not value. | Opaque atoms are equal when their heads match and their arguments are proved equal. |
| v0.6501 | A `TimeConstrained` timeout inside a lazily loaded package (Integrate's Roach engine) left the session in `Roach`Private`` with `$ContextPath = {System`}`, so later bare symbols, including a script's own globals, resolved to new private symbols. | The timeout recovery restores the context stack and the `$Context`/`$ContextPath` values. |
| v0.6501 | A failed `dsolve_parse` leaked its residual and condition arrays; eight pinned wrappers returned without freeing. | `dsolve_parse` frees on failure. |

## 2. Waves

Waves are ordered by measured gap per unit of work. W0 is a prerequisite for every
later wave, because it lifts the shared limits in §1.1.

### W0: Shared PDE infrastructure

The goal is to give every method the same substrate the ODE methods have. Today
each PDE file re-implements derivative placeholders and condition sorting.

1. **n independent variables.** Generalise `DSolveProblem` PDE handling, the
   `pde_deriv` placeholder substitution (one copy in each `dsolve_pde*.c`), and
   `dsolve_verify_pde`/`dsolve_assemble_pde` to n ≥ 2. Then delete the per-file
   copies in favour of a single `ds_pde_placeholders()` in `dsolve_common.c`.
2. **Multi-variable conditions.** Teach `dsolve_parse`/`ds_is_condition` to split
   off `u[x, 0] == g(x)` and `Derivative[1, 0][u][0, t] == h(t)` into a single
   `PDECondition` struct (line, fixed slots, derivative order, data). This promotes
   `pv_classify`/`PVCond` from `dsolve_pde_ivp.c`. Methods 6–8 drop their private
   sorters.
3. **Arbitrary functions of several arguments.** Generate `C[k][ξ1, …, ξm]`, and
   pin them in `dsolve_verify_pde` with nonlinear test functions of every arity,
   following the corpus prelude's `pdPinA`/`pdPinB`.
4. **Inert quadrature.** A non-elementary integral along a characteristic becomes a
   definite `Inactive[Integrate][g(K, ξ), {K, 1, s}]` over a *symbol* dummy, which
   D differentiates by the Leibniz rule (see `dsolve_fos.c`, v0.6499). This alone
   reopens **49** constant-coefficient first-order records whose right-hand side is
   an arbitrary `f[x]` or `Log[λx]^k` (pde-982 … pde-999), where `pde1` declines
   today. Also fix D for an indexed dummy `K[1]`, which is Mathematica's spelling
   (§5).
5. **`Method -> "…"`** names that pin PDE methods, with one table shared with the
   ODE `ds_method_from_string`.
6. **Per-method budgets.** Every method runs its cheap structural test before any
   `Solve`/`DSolve`/`Integrate`, under a `TimeConstrained` clamp, so a decline
   costs microseconds.

*Corpus effect:* enables W1–W3. It also closes the 49 records above directly.

### W1: n-variable first-order linear PDEs by characteristics (gap ≈ 453 + 23)

`a1(x) w_{x1} + … + an(x) w_{xn} == c(x) w + f(x)`, with variable coefficients and
n ≥ 3. These are chapters 6.6–6.9 of Polyanin's handbook, and the largest bucket.

- **Characteristic system:** `dx1/a1 = … = dxn/an`. Find n − 1 functionally
  independent first integrals ξ1 … ξ(n−1) in this order:
  1. **Decoupled pairs.** When `a_k` depends only on `x1` and `x_k`, the integral
     comes from the scalar ODE cascade `dx_k/dx1 = a_k/a1`. This is the common
     handbook shape.
  2. **Triangular chains.** Solve in dependency order, substituting earlier
     integrals.
  3. **Integrable combinations.** Ratios and multipliers λ_k with Σ λ_k a_k = 0 and
     Σ λ_k dx_k exact, found by a linear solve over a monomial ansatz.
  4. **The ODE-system cascade** (`dsolve_run_system`) as the general fallback.
- **Answer:** `w = μ · (C[1][ξ1, …, ξ(n−1)] + Inactive[Integrate][μ⁻¹ f/a1 …])`,
  with integrating factor `μ = Exp[∫ c/a1 dx1]` along the characteristic.
- **Reuse:** `pdequasi_invariant` (2-variable case), `dsolve_run_system`,
  `ds_integrate_or_inert`, and W0 items 1, 3 and 4.
- **New file:** `dsolve_pde_char_n.c`, pinned as `DSolve`PDECharacteristics`.

### W2: Two-variable variable-coefficient first order and quasilinear (gap ≈ 391 + 11)

Most of chapters 6.2–6.5 are already *structurally* inside `pdequasi`'s semilinear
class (A). They fail because the characteristic ODE `y' = Q/P` is not solved by the
ODE cascade, or because the integrating-factor quadrature is non-elementary.

- Route the characteristic ODE through the full scalar cascade, and accept an
  **implicit** first integral `Φ(x, y) == C` from it (Riccati, Abel and Chini
  forms appear throughout the handbook). The invariant is then `ξ = Φ`.
- Apply W0's inert quadrature to the u-equation along the characteristic.
- **General quasilinear** (u in P and Q with R ≠ 0): Lagrange's system with u as a
  coordinate, two first integrals, and an implicit answer `F(φ1, φ2) == 0`, written
  `φ2 == C[1][φ1]`.
- Measure first: the ODE-cascade failures on the characteristic equations are ODE
  work, so log each one as an ODE gap rather than special-casing it here.

### W3: First-order Cauchy problems (gap ≈ 14 + 6 + 5)

Fit the arbitrary function from data on a curve Γ. Restrict the invariant to Γ,
invert `ξ|_Γ = s` for the curve parameter, and substitute:
`C[1][s] = data(Γ(s))`, or the n-variable analogue.

- This generalises the `pde_ivp` invariant families. Families remain the fast path
  for nonlinear equations.
- It needs W0 item 2 (conditions) and `Solve` for the inversion. When the inversion
  is not single-valued, decline rather than pick a branch.

### W4: Fully nonlinear first order (chapter 7, chapter 2.13, part of chapter 6)

- **General Lagrange–Charpit.** Search the characteristic strip for one integrable
  combination giving a second first integral `G(x, y, u, p, q) = a`, solve `F = 0`
  and `G = a` for p and q, then integrate `du = p dx + q dy`.
- **Hamilton–Jacobi.** Additive separation `u = X(x) + Y(y)` and multiplicative
  separation.
- **Complete integral to general integral** by the envelope, and **singular
  solutions** (`IncludeSingularSolutions`).
- **Cauchy problems** for nonlinear first-order equations by characteristic strips
  (needs W3).

### W5: Second-order linear beyond constant-coefficient factoring (gap ≈ 11 + 9 + 7 + 4)

- **Inhomogeneous constant-coefficient equations:** a particular solution by
  operator inversion of polynomial × exponential × trigonometric right-hand sides,
  or by undetermined coefficients, plus `pde2`'s homogeneous solution.
- **Exponential shift** `u = e^{αx + βy} v` to remove first-order terms. This covers
  the general telegraph equation's reduction to Klein–Gordon.
- **Canonical form for variable coefficients.** For hyperbolic and parabolic
  equations, characteristic coordinates from `A dy² − B dx dy + C dx² = 0` (two ODEs
  through the cascade), then transform. This covers Euler–Poisson–Darboux,
  Chaplygin and equidimensional (Euler) equations.
- The **Laplace cascade method** (Laplace invariants h and k) for
  `u_xy + a u_x + b u_y + c u = 0`.
- **Higher-order constant-coefficient equations:** factor the symbol into
  first-order factors where possible (generalising `pde2`).

### W6: Eigenfunction-expansion IBVPs and BVPs (gap ≈ 108 + 33 + 25 + 22)

These are chapters 3–5: heat, wave, Laplace, Poisson and Helmholtz on bounded
domains. Mathematica solves about 93% of them, so this is the largest classical
gap.

- **Sturm–Liouville engine:** harden `dsolve_eigenvalue.c` with Robin and periodic
  BCs and the Neumann zero mode, and add singular endpoints (Bessel at r = 0,
  Legendre at ±1).
- **Separation of variables driven by the BCs:** promote `dsolve_pdesep.c` from a
  pinned single mode into the cascade. Separate, solve the eigenproblem in the
  variable with homogeneous BCs, then solve the other factor's ODE per mode.
- **Coefficients by orthogonal projection** of the data. Needs a
  `FourierSinCoefficient`/`FourierCosCoefficient`/`FourierCoefficient` family (W7
  builtins).
- **Inhomogeneous BCs** lifted by a steady state, or by a linear-in-x function for
  time-dependent BCs. **Sources** handled by expanding the forcing in
  eigenfunctions (Duhamel per mode).
- **Domains:** interval, rectangle, disk/annulus/wedge (polar, BesselJ, with
  `BesselJZero`), sphere (Legendre).
- **Answer:** `Inactive[Sum][c[K[1]] X_{K[1]}(x) T_{K[1]}(t), {K[1], 1, ∞}]`, which
  is Mathematica's form, verified as `PASS-SERIES` (mode by mode plus projection).

### W7: Transform methods and the missing transform builtins

- **Builtins first,** each with its spec, docstring, attributes and tests:
  `InverseLaplaceTransform`, `FourierTransform`, `InverseFourierTransform`,
  `FourierSinTransform`, `FourierCosTransform` and their inverses, plus the
  `Fourier*Coefficient` family that W6 shares. Only `LaplaceTransform`
  (`src/calculus/laplace.c`) exists today.
- **Methods:**
  - **Laplace in t** for half-line problems (heat and wave on x > 0 with a boundary
    condition).
  - **Fourier in x** for whole-line constant-coefficient problems. This generalises
    `dsolve_heat.c` to advection–diffusion and reaction, and gives the Poisson
    kernel in the half-plane.
  - **Sine and cosine transforms** for half-line Dirichlet and Neumann problems.
  - **Method of images.**
  - **Duhamel** for forced heat and wave, the class v0.6498 made `dsolve_wave.c` and
    `dsolve_heat.c` decline.

### W8: Nonlinear special classes (gap ≈ 9 + 7)

- **Cole–Hopf** for Burgers' equation, in general form and with an IVP.
- **Travelling-wave reductions** `u = U(x − ct)` for KdV, mKdV, sine-Gordon and
  Fisher equations, in general form. (`pde_ivp`'s shift family handles only the
  IVP.)
- **Lie point-symmetry reductions** for PDEs, reusing the determining-system
  machinery of the ODE `DSolve`LieSymmetry` (`docs/design/dsolve_lie_symmetry.md`).
- **Functional separable solutions,** additive and multiplicative (Polyanin &
  Zaitsev), for chapter 7.

### W9: Systems and named equations

- **First-order linear systems** by diagonalisation, starting with Cauchy–Riemann.
- **Black–Scholes** by the change of variables to the heat equation.
- **Schrödinger, Tricomi, Keldysh and Airy PDEs** via W5 canonical forms and
  special functions.

## 3. Definition of done (every method)

1. **Tests.** A dedicated `tests/test_dsolve_pde_<method>.c` with at least 30 cases:
   positive cases, declines (including the shapes it must *not* claim), the pinned
   builtin, conditions, and malformed input. It is registered automatically by the
   `*_tests` sweep in `tests/CMakeLists.txt`. Add generated cases to
   `tests/test_dsolve_stress.c`.
2. **Correctness.** Every answer is verified by back-substitution inside the method:
   the PDE residual **and every condition**, against the user's actual equation, not
   rebuilt test data (v0.6498).
3. **Corpus.** The method's buckets improve, the chapter's `nonpass` baseline in
   `tests/CMakeLists.txt` goes down, and **FAIL stays 0**.
4. **Memory.** The unit suite and the method's corpus records are clean under
   `valgrind --leak-check=full ./Mathilda -file …`, compared against the fixed
   startup baseline (≈ 12.8 KB / 400 blocks on macOS). Totals must not grow with the
   number of calls (1× vs 3×).
   Use `DSolve_test_status/pde/valgrind_dsolve_only.m`, which runs with no
   `TimeConstrained`, because a timeout abandons the aborted computation's nodes by
   design. The 2026-11-11 baseline is 17.5 KB at 1× and 19.1 KB at 3×.
5. **Performance.** The cheap structural test runs before any `Solve`, `DSolve` or
   `Integrate` call, the method runs under a `TimeConstrained` clamp, and there is no
   `evaluate()` in a loop where a direct C walk suffices. The corpus runner's
   per-record time is the regression signal.
6. **Docs.** A docstring and attributes for the pinned builtin, the
   `docs/spec/builtins/calculus.md` method table, a weekly changelog entry, and a
   version bump and tag.

## 4. The corpus harness

The full description is in [`DSolve_test_status/pde/README.md`](DSolve_test_status/pde/README.md).

**Verdicts:** PASS, PASS-IMPLICIT, PASS-SERIES, UNK, FAIL, UNFIT, UNEVAL.
`PossibleZeroQ` is the only judge, and there is no numeric acceptance.

**Gates:** each chapter's ctest (`dsolve_pde_corpus_<chap>_tests`, nightly) checks
two baselines:

- `nonpass ≤ baseline`;
- `FAIL ≤ fail_baseline`, separately, so a new wrong answer cannot hide behind a
  new solve.

**Verifier self-test:** `./Mathilda -file DSolve_test_status/pde/prelude_selftest.m`
runs hand-made answers with known verdicts, including wrong answers the verifier
must refuse.

## 5. Open issues found while building the harness

These are logged in `tasks/todo.md`. They are outside this plan's waves but block or
blur its measurements.

- `D[Integrate[g[K[1]], {K[1], 1, x + y}], x]` returns a malformed List, and D
  leaves `Inactive[Integrate]` with an indexed dummy unevaluated. That blocks
  Mathematica's `K[1]` spelling (W0 item 4).
- The 4-argument `FirstCase[e, p, default, levelspec]` is not implemented.
- ODE corpus §2.2.1 is red at v0.6496 (2.2.1-28 and 2.2.1-32 newly UNEVAL), and the
  Chini stress case (`tests/test_dsolve_stress.c:247`) fails. Both pre-date this
  work.
- The ODE corpus prelude accepts implicit answers as "UNK", counted as PASS. That is
  how `Integrate[g, x + y[x]]` (§1.3) went unnoticed in the ODE corpus. It should
  verify implicit answers with the PDE prelude's implicit-function rule.
