# Changelog: week of 2026-09-14 (Mon) – 2026-09-20 (Sun)

## Read + a first-class input/output stream layer (`src/io/`)

The `src/io/` subsystem grows from `ReadList` into Mathilda's first **stream
layer**: files can now be opened, read/written through a persistent *current
point*, and closed, via handle objects. `Read` is the single-object primitive
with a moving current point, and `ReadList` is refactored to be exactly a
sequence of `Read` calls over one shared reading engine (`src/io/read.c`) — so
the two can never diverge on read types, separators, or `EndOfFile` padding.
`ReadList`'s 27-test suite is unchanged and passes as the behaviour-preserving
guard.

**New builtins** (all `Protected`), registered from `src/io/streams.c`
(registry + management + output) and `src/io/read.c` (engine + `Read`):

- `Read[stream]` / `Read[stream, type]` / `Read[stream, {type_1, ...}]` /
  `Read[stream, structure]` — reads one object, or one **nested type structure**
  filled depth-first, advancing the stream. Any head works, so
  `Read[s, {{Number, Number}, {Number, Number}}]` reads a 2×2 matrix and
  `Read[s, Hold[Expression]]` reads an expression without evaluating it. Returns
  `EndOfFile` past end of file and `$Failed` for a closed stream or a token that
  is not of the requested numeric type. The read types
  (`Byte`/`Character`/`Expression`/`Number`/`Real`/`Record`/`String`/`Word`) and
  the `RecordSeparators`/`WordSeparators`/`TokenWords`/`NullRecords`/`NullWords`
  options are those of `ReadList`, with defaults in `Options[Read]`.
- `OpenRead["file"]` → `InputStream["file", n]`; `OpenWrite` / `OpenAppend` →
  `OutputStream["file", n]`. All accept `File["file"]`.
- `Write[stream, e_1, ...]` (input-form text + newline) and
  `WriteString[stream, s_1, ...]` (raw strings, no newline); output is flushed so
  it round-trips with `Read`/`ReadList`.
- `Close[stream]` returns the file name; `Streams[]` / `Streams["file"]` list
  open streams; `StreamPosition` / `SetStreamPosition[..., n | Infinity]` query
  and move the current point (input buffer offset, or `fseek`/`ftell` for
  output).

A stream is handed to the language as an inert `InputStream["name", id]` /
`OutputStream["name", id]` object (`Protected` head, no builtin) whose integer
`id` addresses a process-global registry of `{name, buffer, pos}` (input) or
`{name, FILE*}` (output). The registry grows by doubling and is freed by `Close`
or, for anything still open, by an `atexit` hook, so valgrind matches the
no-stream baseline. A bare `"file"` / `File["file"]` given to `Read`/`Write` is
auto-opened and left open, so successive calls share a current point;
`ReadList` on a name it opened itself closes it again.

One semantic refinement: the `Expression` leaf is now read **unevaluated** and
the surrounding evaluator evaluates the constructed result, which is what makes
`Read[s, Hold[Expression]]` stay held while `Read[s, Expression]` evaluates. This
is behaviour-preserving for `ReadList` (its result list is evaluated to the same
normal form). New gate `streams_tests` (every read type, nested structures,
grouping/`EndOfFile` padding, options + `SetOptions[Read]`, the filename/`File`
forms, stream persistence, positioning, `Write`/`WriteString` round-trips, and
the missing-file / malformed-number / read-after-`Close` paths). `Read` and the
stream builtins are structural/I-O heads (returning objects/lists, not numeric
kernels), so no NDArray/`Compile[]` fast-path surface applies.

Every symbol introduced for `Read`/`ReadList` now also carries a docstring (via
`symtab_set_docstring` in `src/info.c`): the read-type tags (`Byte`, `Character`,
`Expression`, `Number`, `Real`, `Record`, `String`, `Word`), `EndOfFile`, the
tokenisation options (`RecordSeparators`, `WordSeparators`, `TokenWords`,
`NullRecords`, `NullWords`), and the stream objects (`InputStream`,
`OutputStream`, `File`), so `?Byte` / `Information["RecordSeparators"]` and the
rest resolve to usage text.

## ReadList — type-directed file reading (new `src/io/` subsystem)

New builtin `ReadList` (new directory `src/io/readlist.c`, wired into `core_init` via
`readlist_init`) reads the objects contained in a file and returns them as a `List` —
the first "read objects from a file into data" builtin in the tree (`Get` only evaluates
for the last value; `Import` handles raster images). It reuses the whole-file slurp +
`parse_next_expression` loop that backs `Get`, but collects each object rather than
discarding all but the last.

Forms: `ReadList["file"]` (all remaining Expressions), `ReadList["file", type]`
(flat list of one type until EOF), `ReadList["file", {t_1, ..., t_k}]` (one of each type
per pass, grouped into sublists; a pass truncated by EOF is padded with `EndOfFile`), and
a trailing count `ReadList["file", types, n]`. Read types: `Byte`, `Character`,
`Expression`, `Number`, `Real`, `Record`, `String`, `Word`. `Number`/`Real` accept the
C/Fortran scientific forms (`2.e5`, `2E5`, `1.5e-3`, `2.*10^5`); `Number` yields an integer
only for a token with no decimal point or exponent, `Real` is always approximate.

Separator options are the full Mathematica set, resolved through the shared
`options_extract` helper with defaults registered in `Options[ReadList]` (so
`SetOptions[ReadList, ...]` works): `RecordSeparators` (default `{"\r\n", "\n", "\r"}`),
`WordSeparators` (`{" ", "\t"}`; record separators also end words), `TokenWords` (`{}`),
`NullRecords` (`False`), `NullWords` (`False`). A missing file prints `ReadList::noopen`
and returns `$Failed`; a malformed number prints `ReadList::readn`, contributes `$Failed`
in place, and continues.

Attributes: `Protected`. Docstring in `src/info.c`; interned names (`ReadList`,
`EndOfFile`, and the type/option tags) added to `src/sym_names.{h,c}`. `ReadList` is a
structural/I-O head returning a `List`, not a numeric kernel, so the NDArray/`Compile[]`
fast-path surfaces do not apply (no `AWARE`/kernel/`EXEMPT` entry). New gate
`readlist_tests` (27 cases: every type, grouping + `EndOfFile` padding, the `n` limit,
each option, `SetOptions`, and the missing-file / malformed-number / empty-file paths);
valgrind shows the leak profile identical to the no-`ReadList` baseline.

## TeXForm: generated constant `C[k]` renders as `c_k` (`src/print.c`, `src/print_latex.c`)

Both LaTeX renderers now typeset the `DSolve`/`Reduce`/`Integrate` generated constant
`C[k]` as the subscripted lowercase `c_k`, matching Mathematica, instead of the old
`C(k)` (`print_tex`, used by `TeXForm`) / `C[k]` (`expr_to_latex`, used by the notebook
NDJSON pipe and the FFI). A single-character subscript stays bare (`C[1] -> c_1`,
`C[n] -> c_n`); anything longer is braced so LaTeX groups the whole subscript
(`C[10] -> c_{10}`, `C[i+1] -> c_{1+i}`). So `TeXForm[DSolve[y'[x] + x Sin[x] == 3, y[x], x]]`
now reads `\{\{y(x)\to c_1+3 x+x \cos(x)-\sin(x)\}\}`. The special-case is keyed on the
displayed head name `C` and arity 1, so a symbol used for anything else is unaffected.
Regression coverage added to `tostring_toexpression_tests` (`ToString[C[1], TeXForm]` and
`ToString[C[10], TeXForm]`).

## DSolve M45 — §2.2.26 corpus (Problems 2501–2600) + Bernoulli integrating-factor symbol-leak fix + new polynomial-solution 2nd-order method

The DSolve ODE corpus gains Nasser Abbasi's 12000.org **§2.2.26** (Problems 2501–2600;
100 scalar, 50 IVP, 0 systems), a Braun-textbook MIXED section: a first-order-nonlinear-heavy
front half (homogeneous class A/C, dAlembert, Bernoulli, Abel, exact, separable, Riccati) and a
second-order block (constant-coefficient `_missing_x`, Euler–Cauchy, Emden–Fowler, Gegenbauer,
`_with_linear_symmetries`). Baseline **87/100, 0 FAIL, 0 crash** → **89/100** with two general
root-cause fixes and **0 regression**. New gate `dsolve_corpus_2_2_26_tests` (baseline 11).

### Bernoulli integrating-factor ``DSolve`Y`` leak (`src/calculus/dsolve_bernoulli.c`)

The Bernoulli reduction `v = y^{1-n}` linearises `y' == A(x) y + B(x) y^n` to `v' + P v == Q`,
whose coefficients A, B are recovered from `Q = F − Y F_Y = (1-n) B Y^n`. A, B are mathematically
free of the reduction variable ``DSolve`Y``, but stored TEXTUALLY they still carry it: `Q` is an
undistributed difference (`Times` does not distribute over `Plus`), so `B = Q/((1-n) Y^n)` keeps a
frozen `Y`. When the reduced integrating-factor integral `∫ mu Q dx` is ELEMENTARY the evaluator
collapses the frozen `Y` away; when it is NON-elementary the integral stays an unevaluated
`Integrate[...]` and the frozen ``DSolve`Y`` LEAKS into the answer — e.g.
`y' == (1+cos 4t)/4·y − (1−cos 4t)/800·y²` (§2.2.26-2532), whose integrating factor
`E^(t/4 + sin(4t)/16)` has no elementary `∫ mu Q`. Back-substitution scored that malformed answer
UNEVAL. Fix: `Cancel` each linearised coefficient to lowest terms in `Y` before handing them to the
linear solver — the same cheap rational-GCD already used to recover the exponent `n` (never
`Simplify`, which hangs on radical coefficients). Intercepts the whole non-elementary-integrating-
factor Bernoulli class; mathematically Y-free coefficients are unchanged.

### New method: ``DSolve`PolynomialSolution`` (`src/calculus/dsolve_ratsol2.c`)

A homogeneous second-order linear ODE with rational coefficients whose fundamental set is
polynomial — e.g. `(t²+1) y'' − 2t y' + 2 y == 0`, fundamental set `{t, t²−1}` — is now solved
directly by a degree-bounded undetermined-coefficient search: substitute the ansatz
`y = a_0 + a_1 x + … + a_D x^D`, clear the common denominator, and `Solve` the coefficient
equations `Coefficient[·, x, j] == 0` for the `a_k`; the null space is the polynomial solution
space, and a 2-dimensional space gives the clean fundamental set. When the equation is forced, the
particular is built by variation of parameters over that basis.

The method runs BEFORE `Kovacic` in the 2nd-order cascade. Kovacic solves the same homogeneous
equation but returns the fundamental set wrapped in a complex-radical basis
(`x √(x−i) √(x+i) / √(x²+1)`, …) that does not reduce to the rational form, so a downstream
`VariationOfParameters` for a forcing term cannot close its integrals — the exact residue that had
left `§2.2.26-2592` (`y'' − 2t/(t²+1) y' + 2/(t²+1) y == t²+1`) and `§2.2.25-2410`
(`(t²+1) y'' − 2t y' + 2 y == t²+1`) unsolved despite an elementary answer. Producing the clean
polynomial basis here closes both, so **§2.2.25 rises 96 → 97/100** (gate 4→3) alongside §2.2.26.
Constant-coefficient / Euler / special-function families remain claimed by their specialists
earlier in the cascade (`y''−y==0`, `x²y''−2y==0`, `y''==0` unchanged). Every returned solution is
numerically self-verified (`ds_branch_num_ok`) before acceptance.

### Residue (documented honest declines)

The §2.2.26 residue of 11 is all `sympySolved=False` (SymPy/Mathematica fail them too), bounded
declines with no wrong answers: non-integrable Riccati `y'=e^{−t²}+y²` (2524/2525/2526), Abel
