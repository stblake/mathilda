# Changelog: week of 2026-09-14 (Mon) – 2026-09-20 (Sun)

## `AlgebraicNumber` and `ToNumberField`

New heads **`AlgebraicNumber[theta, {c0, ..., cn}]`** (an element of `Q(theta)` in
the power basis of `theta`) and **`ToNumberField`** (express algebraic numbers in a
named or common number field). Faithful to the Wolfram Language, backed by FLINT's
exact `qqbar` engine (both heads are inert without FLINT).

- **`AlgebraicNumber`** canonicalises so `theta` is an **algebraic integer** and the
  coefficient list has length `deg(minpoly theta)`: short lists zero-pad, over-length
  lists fold modulo the minimal polynomial (`AlgebraicNumber[3^(1/5), {1,2,1,3,3,1}]`
  → `{4,2,1,3,3}`), a non-integer generator rescales (`(1+I)/2` → `1+I`), and objects
  representing a rational reduce to explicit form. Attributes `{NHoldAll, Protected}`.
- **Number-field arithmetic**: same-generator `AlgebraicNumber` objects combine under
  `+`, `*`, `/`, and integer powers (hooks in `src/plus.c`, `src/times.c`,
  `src/power.c`); a single generator also absorbs loose rational terms/factors.
- **Operations**: `N` (any precision), `RootReduce` (→ `Root`), `Less`/`Greater`,
  `Round`, `Equal`/`Unequal`, `NumericQ`, and `Re`/`Im`/`Abs` (which return the object
  itself, or `0`, only for a **real** algebraic number).
- **`ToNumberField[a, theta]`**, `[{a1,..}, theta]`, `[{a1,..}]`/`Automatic`, `[.., All]`
  (common field via a primitive element), and `[x]` (explicit `AlgebraicNumber`).
  Attribute `Protected`.
- **`RootReduce` bonus**: `to_qqbar` now recognises `Re`/`Im`/`Abs`/`Conjugate` of a
  constant algebraic number and `E^(I Pi r)` (a root of unity), so e.g.
  `RootReduce[E^(Pi I/4)]` → `Root[1 + #1^4 &, 4]`.

Implementation: `src/poly/flint_qqbar.c` (Expr-level entry points + `to_qqbar`
recognition), `src/poly/algebraicnumber.c`, `src/poly/tonumberfield.c`, a
`numericalize` branch in `src/numeric.c`, and an `is_numeric_quantity` clause in
`src/core.c`. Tests: `tests/test_algebraicnumber.c` (spec examples pinned, plus
independent `RootReduce` value-preservation cross-checks). Valgrind-clean (no new
lost blocks vs. the macOS baseline).

## `FirstPosition`

New head **`FirstPosition[expr, pattern, default, levelspec]`** — the position (a
list of indices) of the *first* element of `expr` matching `pattern` in depth-first
order, or `Missing["NotFound"]` (or a supplied `default`) when nothing matches.

- `FirstPosition[expr, pattern]` → e.g. `FirstPosition[{a,b,a,a,b,c,b}, b]` is `{2}`.
- `FirstPosition[expr, pattern, default]` → `default` on a miss; over an association
  the position is a key, e.g. `FirstPosition[<|"a"->1,"b"->2|>, _?PrimeQ]` is
  `{Key["b"]}`.
- `FirstPosition[expr, pattern, default, levelspec]` with the usual level specs and a
  `Heads -> True|False` option; the default is `{0, Infinity}` with `Heads -> True`,
  so a whole-expression match is the position `{}`.

Attributes `{HoldRest, Protected}` — `default` is held and evaluated **only when it is
returned** (a matching hit never touches it). Implemented in
`src/patterns.c` (`builtin_first_position`) by **delegating to `Position`** with the
first-match cap, so it reuses Position's traversal, level-spec parsing, `Heads`
handling, and association `Key[...]` remapping unchanged — a structural head, so (like
`Position`) it carries no ND/`Compile[]` obligation and materialises a visible
`NDArray` argument via `patterns_delist_visible`. Symbol `SYM_FirstPosition`
(`src/sym_names.{h,c}`), docstring (`src/info.c`), `Heads -> True` default
(`src/options_builtin.c`). Tests: `tests/test_firstposition.c` (23 cases, 0 leaks
under `leaks`). Docs: `docs/spec/builtins/pattern-matching.md` and `data-structures.md`.
Version 0.154 → 0.155.

## `BitLength` + new `src/bitwise/` module

New head **`BitLength[n]`** — the number of binary bits needed to represent the
integer `n`. For `n > 0` it is an exact `Floor[Log[2, n]] + 1` (via GMP
`mpz_sizeinbase` in base 2); `BitLength[0]` is `0`; for `n < 0` it equals
`BitLength[BitNot[n]]` (with `BitNot[n] = -n - 1`, so `BitLength[-2^k]` is `k`).

This seeds a new `src/bitwise/` subsystem (hub `bitwise.c` + one file per builtin
+ `bitwise.h`) that the rest of the Bit* family will join. `BitLength` is
`Protected`, `Listable`, and fully wired across all numeric surfaces:

- **Interpreter**: `src/bitwise/bitlength.c`, GMP-backed (machine ints + bignums
  uniformly). Non-integer args emit `BitLength::int`, wrong arity `BitLength::argx`.
- **Packed / `NDArray` fast path**: `int64` kernel `ndk_BitLength_ii`
  (`src/ndinteger.c`), on the `AWARE` and `INT64_OK` lists (`src/pack.c`). The
  kernel complements the unsigned magnitude, so it is exact for the whole `int64`
  range including `INT64_MIN` (`BitLength[-2^63]` is `63`) with no overflow.
- **`Compile[]`**: new unary opcode `OP_BLEN_I`; lowers at both scalar and rank-1
  array shapes (`CompileDiagnostics[...]` reports `Compiled -> True`), so
  auto-compilation (`Table`/`Sum`/`NIntegrate`) picks it up for free.

Docs: new [`builtins/bitwise.md`](../builtins/bitwise.md) category (+ overview row
in `Mathilda_spec.md`). Tests: `tests/test_bitwise.c` (29 cases) +
`tests/scripts/bitwise_leakcheck.sh` (0 leaks under `leaks`).

## `PolynomialReduce` + `GroebnerBasis` `DegreeLexicographic`

New head **`PolynomialReduce[poly, {p1, ..., pn}, {x1, ..., xk}]`** — multivariate
polynomial division with cofactors, the third pillar of the Gröbner toolkit
alongside `GroebnerBasis` and `CoefficientRules`. Returns `{{a1, ..., an}, b}`
with `a1 p1 + ... + an pn + b == poly` and `b` fully reduced (no term divisible
by any leading term of the `pi`); modulo a Gröbner basis, `b == 0` is an exact
ideal-membership test.

```
PolynomialReduce[x^3+y^3, {x^2-y^2-1, x+2y-7}, {x,y}]  -> {{x, 1+y^2}, 7-2y+7y^2-y^3}
PolynomialReduce[2x^3+y^3+3y, {x^2+y^2-1, x y-2}, {x,y}] -> {{2x,-2y}, 2x-y+y^3}
PolynomialReduce[x^3, {x^2+1}, {x}, Modulus->7]         -> {{x}, 6x}
```

- **Engines.** Over Q the divisor is `gb_divmod` (`src/poly/groebner.c`), the
  same normal-form division Buchberger uses; the `Lexicographic` pure-Q case
  dispatches to FLINT's `fmpq_mpoly_divrem_ideal` (`flint_polynomial_reduce`,
  cross-checked to match `gb_divmod`). `Modulus -> p` reduces over `GF(p)` via a
  new cofactor-tracking `gfp_divmod` (`src/poly/gbmod.c`).
- **RationalFunctions (default).** A free symbol outside the variable list is a
  coefficient-field parameter, so cofactors may carry parameter denominators
  (e.g. `y/(4a)`); this case runs an Expr-coefficient division whose field
  arithmetic is `Together`/`Cancel` over `Q(params)` (exact, no numeric oracle).
  Reuses `CoefficientRules` for term extraction.
- **Options** (as for `GroebnerBasis`): `MonomialOrder`, `CoefficientDomain`
  (`RationalFunctions` default, `Rationals`), `Modulus`, `ParameterVariables`,
  `Tolerance`. `CoefficientDomain -> Integers`/`InexactNumbers` and nonzero
  `Tolerance` are deferred — accepted, then the head declines with a note.
- **`GroebnerBasis` fix.** `MonomialOrder -> DegreeLexicographic` (and the
  `Negative*` family) are now honoured through a shared named-order → weight-
  matrix helper (`gb_build_order_matrix` / `gb_classify_named_order` in
  `src/poly/groebner.c`, also used by `PolynomialReduce` and the
  `CoefficientRules`/`MonomialList` family). Previously `DegreeLexicographic`
  silently fell back to `Lexicographic`. A named order now returns the identical
  basis to its explicit weight-matrix spelling.
- Attributes: `Protected`. Docstring in `src/info.c`; default `Options` in
  `src/options_builtin.c`; `SYM_PolynomialReduce` interned. Symbolic/structural
  head — genuinely exempt from the packed/NDArray and `Compile[]` surfaces.
- Tests: `tests/test_polynomialreduce.c` (Wolfram-exact `===` checks, the
  reconstruction invariant `q.p + b == poly`, params/GF(p) cases, declines, and
  a `GroebnerBasis` `DegreeLexicographic` regression). Valgrind-clean.

## `MonomialList`, `CoefficientRules`, `FromCoefficientRules`

Three new structural-polynomial heads giving a sparse `{exponent-vector -> coefficient}`
view of a multivariate polynomial — the sparse counterpart to the dense, per-variable
`CoefficientList`:

```
CoefficientRules[(x + y)^3]                       -> {{3,0}->1, {2,1}->3, {1,2}->3, {0,3}->1}
MonomialList[(x + y)^3]                            -> {x^3, 3 x^2 y, 3 x y^2, y^3}
FromCoefficientRules[{{2,0}->a,{0,2}->c}, {x,y}]   -> a x^2 + c y^2
```

- `CoefficientRules[poly, vars, order]` returns the monomials as `expvec -> coeff` rules;
  `MonomialList[poly, vars, order]` returns them as monomial expressions;
  `FromCoefficientRules[rules, vars]` inverts `CoefficientRules`.
- No-variable forms default to `Variables[poly]`; `vars` may also be `All`. Inputs need
  not be expanded (expanded internally). Like monomials are merged and zero coefficients
  dropped, so symbolic coefficients combine (`CoefficientRules[a x + b x, {x}]` →
  `{{1} -> a + b}`).
- **Monomial orders**: all six named orders (`"Lexicographic"` (default),
  `"DegreeLexicographic"`, `"DegreeReverseLexicographic"`, `"NegativeLexicographic"`,
  `"NegativeDegreeLexicographic"`, `"NegativeDegreeReverseLexicographic"`) plus an explicit
  weight matrix, driven by one unified "descending lex of the weighted exponent vectors"
  comparator. The synthesized matrices reproduce Wolfram's explicit-matrix spellings
  exactly (e.g. `"DegreeLexicographic"` on `{x,y}` = `{{1,1},{1,0}}`).
- `Modulus -> m` reduces coefficients modulo `m` (via `PolynomialMod`), dropping vanishing
  monomials.
- New module `src/poly/monomials.c` (self-contained, reusing the public
  `internal_variables`/`internal_polynomialmod`/`internal_plus`/`internal_times`/
  `internal_power` wrappers and `expr_expand`); attributes `Protected`; symbols
  `SYM_MonomialList`/`SYM_CoefficientRules`/`SYM_FromCoefficientRules`; docstrings in
  `src/info.c`; tests in `tests/test_coefficient_rules.c`. This satisfies the
  previously-undefined `CoefficientRules` reference in `mixed/ParallelMixed.m`.
- These are symbolic/structural heads (they return rules and symbolic monomials, not
  machine numbers), so they have no packed/NDArray/`Compile[]` numeric surface by design;
  a bare numeric `List`/`NDArray` argument declines rather than being treated as a
  polynomial. `check-fastpath-sweep` records `CoefficientRules`/`MonomialList` in its
  `OFF_BUFFER` list with a reason: the gate materialises only when a packed vector is
  handed as the *variable-list* argument (boxed to iterate its elements as variables),
  which is inherent, not a missed numeric fast path.
- Deviation from Wolfram: the no-variable form uses Mathilda's `Variables[poly]`, which is
  canonically **sorted**, so `CoefficientRules[y + x z]` uses variable order `{x, y, z}`
  (Wolfram's `Variables` returns the unsorted `{y, x, z}` there).

## `FactorSquareFreeList` + `Extension` option on `FactorSquareFree`

New builtin `FactorSquareFreeList[poly]` gives the square-free factors of a polynomial with
their multiplicities as `{factor, exponent}` pairs — exactly as `FactorList` relates to `Factor`:

```
FactorSquareFreeList[x^5 - x^3 - x^2 + 1]  ->  {{1, 1}, {-1 + x, 2}, {1 + 2 x + 2 x^2 + x^3, 1}}
```

It is a thin wrapper over `FactorSquareFree` (`src/poly/facpoly_list.c`, sharing the new
`product_to_pair_list` splitter with `FactorList`), attributes `Listable, Protected`, leading
`{c, 1}` numerical factor. Unlike `FactorList`, the square-free factors are not further reduced
to irreducibles. This head was already **referenced but undefined** in the Trager/ParallelMixed
`.m` packages (`packages/trager/src/Hermite.m`, `SchultzHermite.m`, `mixed/ParallelMixed.m`);
those callers are now satisfied.

`FactorSquareFree` also gains the **`Extension` option** (default `Extension -> None`, factor
over Q), forwarded through `FactorSquareFreeList`. `FactorSquareFree[poly, Extension -> alpha]`
performs the square-free decomposition over Q(alpha) by reducing to `Factor[poly, Extension ->
alpha]` (the existing Trager engine) and grouping the irreducible-over-Q(alpha) factors by
multiplicity — needing no new square-free-over-Q(alpha) primitive. It accepts algebraic-number
coefficients, e.g. `FactorSquareFree[x^2 - 2 Sqrt[2] x + 2, Extension -> Sqrt[2]]` →
`(-Sqrt[2] + x)^2`. The fast over-Q Yun path is untouched for the default. Docstrings in
`src/info.c`, symbol `SYM_FactorSquareFreeList`, docs in
`docs/spec/builtins/structural-manipulation.md`, and a ctest-wired suite
`tests/test_factorsquarefreelist.c` (both surfaces, round-trip invariants, leak-free).

## DSolve Kovacic — purely-imaginary complex-pole fix (repairs a masked regression)

`DSolve\`Kovacic[y'' - ((3+2x²)/(1+x²)²) y == 0]` (poles at ±i) **declined** where it should

(`src/calculus/dsolve_kovacic.c`) **blanket-declined every non-real pole** — a guard added to
avoid a `ds_simplify(theta)` hang on genuinely-Heun complex-pole equations

whose √-discriminant radical is what makes `ds_simplify(theta)` spin; a **purely imaginary**
conjugate pair (`x²+c`, roots `±b I`) combines into a clean real rational and is now solved.
The Heun cases still decline fast (0.0 s, no hang) and fall through to the Frobenius series
(§2.2.14-1392/1393 PASS via that fallback). §2.1.2: **564 → 568 PASS, 0 FAIL** (gate 648 → 644);
§2.2.14 unchanged at 99/100, 0 FAIL. `t_kovacic_complex_poles` passes. Version 0.153 → 0.154.

## DSolve M55 — §2.1.2 method wave: generalised power-potential recogniser (Bessel + Whittaker/1F1)

First gap-driven method wave on the master §2.1.2 corpus's largest bucket (2nd-order linear).
`DSolve\`SpecialFunctionForm` (`src/calculus/dsolve_specialform.c`) now recognises two
power-potential families at **symbolic exponent** — the corpus shape the pre-existing
numeric-exponent Bessel row could not reach:

- **Single power** `y'' + A x^m y == 0` → `Sqrt[x] (C[1] BesselJ + C[2] BesselY)[1/(m+2),
  κ x^((m+2)/2)]`, `κ = 2 Sqrt[A]/(m+2)`. At a symbolic `m` this equation previously fell to the
  power-series fallback and emitted `0^n` / `ComplexInfinity` garbage; it now returns the closed
  Bessel form.
- **Two-term** `y'' + (α x^(2c) + β x^(c-1)) y == 0`. This is NOT Bessel — under `ξ = x^(c+1)` it
  reduces to a Coulomb equation and is solved by `y = x^((1-d)/2) WhittakerM[κ, ±μ, z]` (`d = c+1`,
  `μ = 1/(2d)`, `κ = β/(2 d Sqrt[-α])`, `z = (2 Sqrt[-α]/d) x^d`), emitted as the verifiable
  confluent form `Exp[-z/2] z^(1/2±μ) Hypergeometric1F1[1/2±μ-κ, 1±2μ, z]`. The recogniser groups
  the potential's terms by their symbolic exponent (`e = x T'/T`, after `Expand`) and matches the
  structural constraint `P_big − 2 P_sm == 2`. The `y'`-carrying members
  (`y'' + a x^n y' + b x^(n-1) y == 0`) are reached through the existing Liouville normal-form
  pre-pass.

Both families emit heads that numericize, so the in-method `sf_num_ok` gate and the corpus
back-substitution are genuine — the 0-FAIL invariant holds by construction.

### Root-cause verify fix (`ds_residual_numeric_zero`, protects every DSolve method)

The generic verify's numeric KEEP short-circuit declined *any* residual flagged by
`ds_has_undefined_function`, which is true for a `Derivative` head — including the derivative of a
DEFINED special function (Bessel/pFq/Airy) produced by differentiating a special-function
solution. That false decline routed a symbolic-exponent special-function residual to `zero_test`,
whose precision ladder spins for many seconds — **name-sensitively**: it hung on the exponent
symbol `n`/`nn` yet was fast on `c`/`k`/`m`. The short-circuit now declines only inert `Integrate`;
a genuinely arbitrary forcing `f[x]` still fails to numericize (its samples come back non-real →
skipped → the same `zero_test` fallback, which is fast for an arbitrary-function residual). This
removed the hang and is what makes the `n`-exponent corpus members solvable.

Tests: pinned unit `t_m55_generalized_power_potential` (`tests/test_dsolve.c`) and four
forward-generator families in the new `tests/test_dsolve_m55_stress.c` (single power a>0/a<0 +
integer/fractional exponent; two-term Whittaker; `y'`-carrying via the pre-pass; and an
`n`/`nn`-named-exponent guard for the verify fix), all `Head === List` + numeric-back-substitution
verified. §2.1.2: **557 → 564 PASS (+7), 640 non-PASS, 0 FAIL** (gate baseline 655 → 648); the
2nd-order-linear bucket rises to 239/414 (57.7%). `make check-c99` green; no regression.
Version 0.152 → 0.153.

## DSolve M54 — Kovacic `Q==0` early-decline (fixes a reducible-ODE hang)

`DSolve[(1-x²) y''[x] + x y'[x] == 1, y, x]` (§2.2.33-3256) **hung** (>120 s at the REPL; the
8 s corpus TimeConstrained masked it as UNEVAL). Root cause: the equation has **no y-term**

`ReductionOfOrder` never runs.

uniquely-needed method for a y-free equation, so the cascade reaches `ReductionOfOrder` at once.
3256 now solves in ~0.05 s and back-substitutes. Verified: new unit
`t_m54_kovacic_missing_y_no_churn` (`tests/test_dsolve.c`); genuine Kovacic cases (nonzero
y-term: `z''==(x²+3)z`, Pöschl-Teller, Euler `2/x²`, Airy) still solve fast and are untouched by
the gate; §2.2.33 re-measured **78/100 PASS (+1), 0 FAIL** (3256 UNEVAL → PASS, nothing else
changed), gate baseline lowered 23 → 22. `make check-c99` green. Version 0.151 → 0.152.

### IVP condition-verification: a spurious 2nd-order fit no longer ships a wrong answer

Case 3279 (`y''==(y')² Sin[x]`, `y[0]==0`, `y'[0]==1/2`) initially **FAILed** — DSolve shipped
`y==0`, which satisfies the ODE and `y[0]==0` but **violates `y'[0]==1/2`** (correct answer is
`y==Tan[x/2]`). Root cause (pre-existing, unrelated to M52): the general solution carries
`√(-16+16 C[1]²)` and `(-4+4 C[1]²)` in denominators, and `Solve` returns the degenerate
`C[1]→1` at a *removable singularity* of the fit system (where `y'(0)` is `0/0`, not `1/2`); the
IVP constant-fitter accepted it. The existing spurious-fit backstop
(`dsolve_fit_constants`, `src/calculus/dsolve_common.c`) verified only the ODE **residual** (which
`y==0` passes) and was scoped to **first-order** ODEs. New helper `ds_fit_meets_conditions`
numerically verifies that a fitted body satisfies every point **condition** (initial/boundary
value) at **any** order; the backstop now rejects a fit that violates a condition (→ honest
decline / UNEVAL) instead of shipping a wrong answer. Conservative — it rejects only a
robustly-nonzero condition residual, so a genuine fit (residual identically 0) is never dropped.
Verified: 3279 now declines; §2.2.33 has **0 FAIL**; the nonhomogeneous zero-IC `y''+y==x` and
all first-/second-order + BVP + M24 control IVPs still solve; IVP-heavy §2.2.12 (3≤3) and
§2.2.14 (1≤1) re-run within baseline (no regression). `make check-c99` green.

## DSolve M52 — symbolic complex-root wrong answer FIXED (narrow, latency-safe)

The M51-deferred wrong answer is now fixed. `DSolve[y''[x] + a² y[x] == Sec[a x], y[x], x]`
(and the whole `y'' + (symbol)² y` variation-of-parameters class) returned `Sec[a x]/a² + Re/Im`
mush for a symbolic coefficient; it now returns the correct
`C[1] Cos[a x] + C[2] Sin[a x] + (a x Sin[a x] + Cos[a x] (…logs…))/a²` (residual `Simplify`s to 0).
Two independent causes, each fixed narrowly so the M51 latency regression does not recur.

- **Homogeneous basis** (`dsolve_homog_basis`, `src/calculus/dsolve_common.c`). A symbolic complex
  conjugate pair was realified to `Exp[Re x] (Cos, Sin)[Im x]` with `Re`/`Im` left **unevaluated**
  (they do not concretize on a radical root), so the basis did not back-substitute. For the
  **pure-imaginary** pair (`r_c == -r`, the `y'' + (symbol)² y` class) the real frequency is now
  computed by field arithmetic — `β = Simplify[PowerExpand[√(-r²)]]`, whose square evaluates to `-r²`
  exactly — giving the real `Cos[a x]`/`Sin[a x]` basis. `PowerExpand` collapses `√(a²)→a` so the
  frequency matches the forcing and VoP integrates. Restricted to the pure-imaginary pair, so the
  general complex-root cases (α ≠ 0) stay byte-identical — the 13 symbolic-coefficient §2.1.2 cases
  (58/439/877/… Pöschl-Teller, shifted-Euler, exponential-potential) that the M51-reverted
  whole-branch `Exp[r x]` swap pushed past the 8 s cold budget are untouched (re-timed cold at
  ≈5–6 s, all still solving). The numeric-root path (`NumericQ` → `ComplexExpand`) is unchanged, so
  the M24 complex-cube-root IVP (`y'''==y`) still fits.
- **Undetermined coefficients** (`dsolve_undetcoeff.c`). Independently, `UndeterminedCoefficients`
  **accepted** the non-UC forcing `Sec[a x]` and shipped `y_p = Sec[a x]/a²`, winning the cascade
  ahead of `LinearConstantCoefficients`' correct VoP. UC's residual zero-test gate (its intended
  safety net) was defeated by a `zero_test` **false positive**: `PossibleZeroQ` of the unsimplified
  residual `D[Sec[a x],{x,2}]/a²` is `True` for a symbolic parameter though the term is genuinely
  nonzero (the numeric coefficient case already declined correctly). The gate now `Simplify`s the
  residual before the zero test, so the non-UC term declines to VoP; genuine UC residuals are provably
  zero either way, so real accepts (polynomial/exponential/sinusoid, incl. resonance) are unchanged.

Verified: new unit `t_m52_symbolic_complex_root` (`tests/test_dsolve.c`) — symbolic homogeneous basis
back-substitutes, the flagship nonhomogeneous case is correct, UC declines `Sec` forcing, and symbolic

## Read + a first-class input/output stream layer (`src/io/`)

The `src/io/` subsystem grows from `ReadList` into Mathilda's first **stream
layer**: files can now be opened, read/written through a persistent *current
point*, and closed, via handle objects. `Read` is the single-object primitive
with a moving current point, and `ReadList` is refactored to be exactly a
sequence of `Read` calls over one shared reading engine (`src/io/read.c`) — so
the two can never diverge on read types, separators, or `EndOfFile` padding.
`ReadList`'s 27-test suite is unchanged and passes as the behaviour-preserving
guard.

**New builtins** (all `Protected`), registered from `src/io/streams.c`
(registry + management + output) and `src/io/read.c` (engine + `Read`):

- `Read[stream]` / `Read[stream, type]` / `Read[stream, {type_1, ...}]` /
  `Read[stream, structure]` — reads one object, or one **nested type structure**
  filled depth-first, advancing the stream. Any head works, so
  `Read[s, {{Number, Number}, {Number, Number}}]` reads a 2×2 matrix and
  `Read[s, Hold[Expression]]` reads an expression without evaluating it. Returns
  `EndOfFile` past end of file and `$Failed` for a closed stream or a token that
  is not of the requested numeric type. The read types
  (`Byte`/`Character`/`Expression`/`Number`/`Real`/`Record`/`String`/`Word`) and
  the `RecordSeparators`/`WordSeparators`/`TokenWords`/`NullRecords`/`NullWords`
  options are those of `ReadList`, with defaults in `Options[Read]`.
- `OpenRead["file"]` → `InputStream["file", n]`; `OpenWrite` / `OpenAppend` →
  `OutputStream["file", n]`. All accept `File["file"]`.
- `Write[stream, e_1, ...]` (input-form text + newline) and
  `WriteString[stream, s_1, ...]` (raw strings, no newline); output is flushed so
  it round-trips with `Read`/`ReadList`.
- `Close[stream]` returns the file name; `Streams[]` / `Streams["file"]` list
  open streams; `StreamPosition` / `SetStreamPosition[..., n | Infinity]` query
  and move the current point (input buffer offset, or `fseek`/`ftell` for
  output).

A stream is handed to the language as an inert `InputStream["name", id]` /
`OutputStream["name", id]` object (`Protected` head, no builtin) whose integer
`id` addresses a process-global registry of `{name, buffer, pos}` (input) or
`{name, FILE*}` (output). The registry grows by doubling and is freed by `Close`
or, for anything still open, by an `atexit` hook, so valgrind matches the
no-stream baseline. A bare `"file"` / `File["file"]` given to `Read`/`Write` is
auto-opened and left open, so successive calls share a current point;
`ReadList` on a name it opened itself closes it again.

One semantic refinement: the `Expression` leaf is now read **unevaluated** and
the surrounding evaluator evaluates the constructed result, which is what makes
`Read[s, Hold[Expression]]` stay held while `Read[s, Expression]` evaluates. This
is behaviour-preserving for `ReadList` (its result list is evaluated to the same
normal form). New gate `streams_tests` (every read type, nested structures,
grouping/`EndOfFile` padding, options + `SetOptions[Read]`, the filename/`File`
forms, stream persistence, positioning, `Write`/`WriteString` round-trips, and
the missing-file / malformed-number / read-after-`Close` paths). `Read` and the
stream builtins are structural/I-O heads (returning objects/lists, not numeric
kernels), so no NDArray/`Compile[]` fast-path surface applies.

Every symbol introduced for `Read`/`ReadList` now also carries a docstring (via

## ReadList — type-directed file reading (new `src/io/` subsystem)

New builtin `ReadList` (new directory `src/io/readlist.c`, wired into `core_init` via
`readlist_init`) reads the objects contained in a file and returns them as a `List` —
the first "read objects from a file into data" builtin in the tree (`Get` only evaluates
for the last value; `Import` handles raster images). It reuses the whole-file slurp +
`parse_next_expression` loop that backs `Get`, but collects each object rather than
discarding all but the last.

Forms: `ReadList["file"]` (all remaining Expressions), `ReadList["file", type]`
(flat list of one type until EOF), `ReadList["file", {t_1, ..., t_k}]` (one of each type
per pass, grouped into sublists; a pass truncated by EOF is padded with `EndOfFile`), and
a trailing count `ReadList["file", types, n]`. Read types: `Byte`, `Character`,
`Expression`, `Number`, `Real`, `Record`, `String`, `Word`. `Number`/`Real` accept the
C/Fortran scientific forms (`2.e5`, `2E5`, `1.5e-3`, `2.*10^5`); `Number` yields an integer
only for a token with no decimal point or exponent, `Real` is always approximate.

Separator options are the full Mathematica set, resolved through the shared
`options_extract` helper with defaults registered in `Options[ReadList]` (so
`SetOptions[ReadList, ...]` works): `RecordSeparators` (default `{"\r\n", "\n", "\r"}`),
`WordSeparators` (`{" ", "\t"}`; record separators also end words), `TokenWords` (`{}`),
`NullRecords` (`False`), `NullWords` (`False`). A missing file prints `ReadList::noopen`
and returns `$Failed`; a malformed number prints `ReadList::readn`, contributes `$Failed`
in place, and continues.

Attributes: `Protected`. Docstring in `src/info.c`; interned names (`ReadList`,
`EndOfFile`, and the type/option tags) added to `src/sym_names.{h,c}`. `ReadList` is a
structural/I-O head returning a `List`, not a numeric kernel, so the NDArray/`Compile[]`
fast-path surfaces do not apply (no `AWARE`/kernel/`EXEMPT` entry). New gate
`readlist_tests` (27 cases: every type, grouping + `EndOfFile` padding, the `n` limit,
each option, `SetOptions`, and the missing-file / malformed-number / empty-file paths);
valgrind shows the leak profile identical to the no-`ReadList` baseline.

## TeXForm: generated constant `C[k]` renders as `c_k` (`src/print.c`, `src/print_latex.c`)

Both LaTeX renderers now typeset the `DSolve`/`Reduce`/`Integrate` generated constant

displayed head name `C` and arity 1, so a symbol used for anything else is unaffected.
Regression coverage added to `tostring_toexpression_tests` (`ToString[C[1], TeXForm]` and

### Bernoulli integrating-factor ``DSolve`Y`` leak (`src/calculus/dsolve_bernoulli.c`)

The Bernoulli reduction `v = y^{1-n}` linearises `y' == A(x) y + B(x) y^n` to `v' + P v == Q`,
whose coefficients A, B are recovered from `Q = F − Y F_Y = (1-n) B Y^n`. A, B are mathematically
free of the reduction variable ``DSolve`Y``, but stored TEXTUALLY they still carry it: `Q` is an
undistributed difference (`Times` does not distribute over `Plus`), so `B = Q/((1-n) Y^n)` keeps a
frozen `Y`. When the reduced integrating-factor integral `∫ mu Q dx` is ELEMENTARY the evaluator
collapses the frozen `Y` away; when it is NON-elementary the integral stays an unevaluated
`Integrate[...]` and the frozen ``DSolve`Y`` LEAKS into the answer — e.g.
`y' == (1+cos 4t)/4·y − (1−cos 4t)/800·y²` (§2.2.26-2532), whose integrating factor
`E^(t/4 + sin(4t)/16)` has no elementary `∫ mu Q`. Back-substitution scored that malformed answer
UNEVAL. Fix: `Cancel` each linearised coefficient to lowest terms in `Y` before handing them to the
linear solver — the same cheap rational-GCD already used to recover the exponent `n` (never
`Simplify`, which hangs on radical coefficients). Intercepts the whole non-elementary-integrating-
factor Bernoulli class; mathematically Y-free coefficients are unchanged.

### New method: ``DSolve`PolynomialSolution`` (`src/calculus/dsolve_ratsol2.c`)

A homogeneous second-order linear ODE with rational coefficients whose fundamental set is
polynomial — e.g. `(t²+1) y'' − 2t y' + 2 y == 0`, fundamental set `{t, t²−1}` — is now solved
directly by a degree-bounded undetermined-coefficient search: substitute the ansatz
`y = a_0 + a_1 x + … + a_D x^D`, clear the common denominator, and `Solve` the coefficient
equations `Coefficient[·, x, j] == 0` for the `a_k`; the null space is the polynomial solution
space, and a 2-dimensional space gives the clean fundamental set. When the equation is forced, the
particular is built by variation of parameters over that basis.

The method runs BEFORE `Kovacic` in the 2nd-order cascade. Kovacic solves the same homogeneous
equation but returns the fundamental set wrapped in a complex-radical basis
(`x √(x−i) √(x+i) / √(x²+1)`, …) that does not reduce to the rational form, so a downstream
`VariationOfParameters` for a forcing term cannot close its integrals — the exact residue that had
left `§2.2.26-2592` (`y'' − 2t/(t²+1) y' + 2/(t²+1) y == t²+1`) and `§2.2.25-2410`
(`(t²+1) y'' − 2t y' + 2 y == t²+1`) unsolved despite an elementary answer. Producing the clean
polynomial basis here closes both, so **§2.2.25 rises 96 → 97/100** (gate 4→3) alongside §2.2.26.
Constant-coefficient / Euler / special-function families remain claimed by their specialists
earlier in the cascade (`y''−y==0`, `x²y''−2y==0`, `y''==0` unchanged). Every returned solution is
numerically self-verified (`ds_branch_num_ok`) before acceptance.
