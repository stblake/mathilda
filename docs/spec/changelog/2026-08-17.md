# Changelog: week of 2026-08-17 (Mon) – 2026-08-23 (Sun)

Feature additions and fixes recorded during this week.

## Compile[]: Which / Switch / Piecewise now lower to bytecode (2026-08-17)

`Which`, `Switch` and `Piecewise` compile under `Compile[]` and every
auto-compilation path (`Plot`, `Table`, `NIntegrate`, `FindRoot`, …); before this
each bailed the **whole** enclosing body to the interpreter (the compilable subset
is a cliff, not a slope). All three lower to a single first-match-wins ladder — the
`If` branch structure repeated — sharing one `collect_ladder`/`emit_ladder` pair in
`src/compile/compile_emit_ctrl.c`, with matching type inference in
`compile_infer.c` (so the head types correctly inside a larger expression such as
`10 Which[…] + 1`).

- **Semantics preserved.** A literal-`True` guard becomes the unconditional final
  case and a literal-`False` guard is dropped, exactly as the interpreter reduces
  them, so a dead clause of an incompatible type does not force a fallback.
  `Piecewise` always yields a value (its explicit or implied-`0` default);
  `Switch` compares the discriminant to numeric-literal forms (or the bare `_`
  catch-all) with machine equality at the common numeric type. A run that matches
  nothing and has no catch-all aborts the compiled call and hands back to the
  interpreter — the `Null` (Which) or unevaluated `Switch` it would return anyway.
- **The `Round`/`Floor`/`Ceiling`/`IntegerPart`/`FractionalPart` group already
  compiled** — scalar (Real/Integer), rank-1 arrays, and directly over an
  `NDArray` object or a packed-`List` argument, both at the REPL (Listable
  ndkernel path) and through `Compile[]`; this was verified across all those
  shapes.
- `Switch` joined the CSE impure-head set, so a `Switch` subtree is never hoisted
  to program entry and evaluated unconditionally (its branches must stay guarded).
- **Tests.** Eleven randomised parity cases in `tests/test_compile.c` (Which /
  Switch / Piecewise standalone, nested, and inside arithmetic), plus a fix to the
  test harness: the interpreter reference now substitutes structurally
  (`replace_bindings`) instead of via `ReplaceAll`, which pre-evaluated a held
  `Switch` and collapsed it to its `_` catch-all before any value was bound. macOS
  `leaks`-clean over the compiled ladders including the interpreter-fallback path.

## Build fix: stb image decoders no longer collide with raylib at link time (2026-08-17, issue #65)

Linking `Mathilda` with `USE_GRAPHICS=1` on Linux failed with dozens of
`multiple definition of 'stbi_load' / 'stbi_failure_reason' / 'stbi_image_free' …`
errors. Both `src/imageio.o` and raylib's `libraylib.a` (`rtextures.c.o`) bake in
their own copy of the vendored `stb_image` implementation, and each exported the
`stbi_*` symbols with external linkage, so the two copies clashed. The reporter
worked around it with the linker flag `-z muldefs`, which merely silences the
error by keeping whichever definition the linker sees first — an ODR violation
that can mix two possibly-different stb versions across the program.

**Fix.** `src/imageio.c` now defines `STB_IMAGE_STATIC` / `STB_IMAGE_WRITE_STATIC`
before including the headers, giving every stb function *internal* linkage so its
code lives in `imageio.o` alone and exports no `stbi_*` symbols at all. This is
sound because `imageio.c` is the only translation unit that both defines and calls
these functions (as its file header already notes). The collision is removed at
the root with no linker flag. `-Wunused-function` is added to the file's existing
scoped `#pragma GCC diagnostic` block, since with internal linkage any stb entry
point `imageio.c` never calls becomes an "unused static function".

Verified against raylib 5.5: full `make` (USE_GRAPHICS=1) now links cleanly, all
`stbi_*` symbols in `imageio.o` are local (`nm` shows `t`, not `T`), and PNG/JPEG
`Export`/`Import` still round-trip correctly.

## NMinimize: Method sub-options are now scoped to the selected method (2026-08-17)

`NMinimize` / `NMaximize` accept a method with sub-options in the
`Method -> {"Name", "opt" -> val, …}` form. Previously the sub-option parser
`nm_parse_method` (`src/numerical_calculus/findmin.c`) was one flat, method-agnostic
`strcmp` table with no fall-through: a key belonging to a *different* method was
accepted and written into its shared config slot but never read by the selected
engine (e.g. `Method -> {"SHGO", "VisitingParameter" -> 2.5}` stored DualAnnealing's
`q_v`, which SHGO never consults), and a misspelled / scipy-style key
(`"Visit"`, `"Seed"`) or a top-level-only option placed inside the list
(`MaxIterations`) was dropped with **no diagnostic at all**. This was inconsistent
with top-level options, which already warn on an unrecognised name.

**What changed.** Each sub-option is now scoped to the method(s) that actually read
its `NmConfig` field. A new classifier `nm_option_owner` returns the owning-method
bitmask for a key (or "unknown"), and `nm_parse_method` consults it before the parse
chain: a key that is unrecognised, or valid only for another method, is reported with
`NMinimize::optx` and skipped — never stored. A helper `nm_method_name` gives the
method's display name for the message. Ownership was derived from the engines' actual
field reads, not guessed:

- **Every method** (generic): `"SearchPoints"`, `"RandomSeed"`, `"PostProcess"`,
  `"PenaltyFunction"`.
- **DifferentialEvolution + NelderMead**: `"Tolerance"`, `"InitialPoints"`.
- **DifferentialEvolution**: `"ScalingFactor"`, `"CrossProbability"`.
- **NelderMead**: `"ReflectRatio"`, `"ExpandRatio"`, `"ContractRatio"`, `"ShrinkRatio"`.
- **SimulatedAnnealing**: `"PerturbationScale"`, `"LevelIterations"`, `"BoltzmannExponent"`.
- **SHGO**: `"SamplingMethod"`, `"Iterations"`.
- **DualAnnealing**: `"VisitingParameter"`, `"AcceptanceParameter"`,
  `"InitialTemperature"`, `"RestartTemperatureRatio"`, `"LocalSearch"`.

The change is diagnostics-only: no computed result changes, and every valid
sub-option is parsed exactly as before. In particular the recently-added SHGO and
DualAnnealing methods keep every option they already honored — the fix closes the
"silently accepted a wrong-method or misspelled key" gap, it does not add or remove
any wired option.

**Tests.** `tests/test_shgo.c` and `tests/test_dual_annealing.c` each gain a
`test_option_scoping` case asserting that a cross-method key, an unknown key, and
`MaxIterations` inside the Method list are dropped (warning muted to stderr) so the
seed-deterministic result is identical to omitting them, while a valid-for-method key
is still honored.

**Docs.** `docs/spec/builtins/numerical-calculus.md` (NMinimize Method sub-options
section) now documents the per-method scoping and the `NMinimize::optx` message.

## Refactor: findmin.c split into one file per optimizer (2026-08-17)

`src/numerical_calculus/findmin.c` had grown to ~9.7k lines holding every
FindMinimum/FindMaximum local solver, every NMinimize/NMaximize global engine, and
all the shared evaluation / constraint / option infrastructure in a single
translation unit. It is now split one-method-per-file, mirroring the
`ndsolve_common.{c,h}` + per-method + registration-hub pattern already used in this
directory (and `src/numbertheory/`, `src/stats/`). No behavior change — a pure
reorganization; all 16 optimizer test suites pass unchanged.

New layout under `src/numerical_calculus/`:

- **`findmin_internal.h`** — shared types, tuning constants, the `extern` file-static
  registries (compile fast-path `g_fm_obj_*`/`g_fm_grad_*`, the quiet/name/augmented-
  Lagrangian state), and prototypes for every symbol used across the split units.
  Method-internal helpers stay `static` in their own file and are not declared here.
- **`findmin_common.c`** — shared local core: objective/gradient/Hessian evaluation
  (machine + MPFR, incl. the register-machine fast path), option/variable/constraint
  parsing, penalty/augmented-Lagrangian evaluators, Armijo line search, Brent 1-D,
  modified Cholesky, result packaging.
- **`findmin_nm_common.c`** — shared global core: the deterministic RNG, point
  evaluation/comparison, the global→local polish bridge (`nm_continuous_solve`), the
  method/option/variable parsing (`nm_parse_method` et al.), and result construction.
- **one local-solver file each**: `findmin_bfgs.c`, `findmin_cg.c`, `findmin_newton.c`,
  `findmin_lbfgsb.c`, `findmin_tnc.c`, `findmin_trust.c` (dogleg / trust-ncg /
  trust-exact / trust-krylov / Newton-CG), `findmin_slsqp.c`, `findmin_powell.c`,
  `findmin_neldermead.c`, `findmin_cobyla.c`, `findmin_cobyqa.c`, `findmin_penalty.c`.
- **one global-engine file each**: `nm_de.c`, `nm_neldermead.c`, `nm_randomsearch.c`,
  `nm_sa.c`, `nm_dual_annealing.c`, `nm_shgo.c`.
- **drivers**: `findmin_driver.c` (FindMinimum/FindMaximum), `nm_driver.c`
  (NMinimize/NMaximize).
- **`findmin.c`** — reduced to the registration hub (`findmin_init` only), like
  `numbertheory.c`.

The makefile already globs `src/numerical_calculus/*.c`, so the new files compile with
no build-system change; `tests/CMakeLists.txt`'s explicit source list was extended to
match. `findmin.h` (the public header) and `core.c`'s `findmin_init()` call are
unchanged.

## NMinimize: DIRECT — DIviding RECTangles global optimization method (2026-08-17)

Added `Method -> "DIRECT"` to `NMinimize` / `NMaximize`: the deterministic
Lipschitzian global optimizer of Jones, Perttunen & Stuckman (1993), with the
locally-biased variant DIRECT-L of Gablonsky & Kelley (2001), reproducing the
reference `DIRECTv2.04` Fortran / `scipy.optimize.direct`.

**What it does.** `nm_direct` (new file `src/numerical_calculus/nm_direct.c`)
normalizes the search box to the unit hypercube, groups cells by an integer size
class (longest-side count for DIRECT-L, a `k·n+q` half-diagonal key for the
original variant) with one sorted linked list per class, and each iteration
subdivides the "potentially optimal" cells — the lower-right convex hull of the
`(size, value)` class minima passing Jones's epsilon improvement test — by
trisecting their longest sides. It is deterministic (no RNG) and requires only a
bounded box. Every center is scored through the shared `nm_eval` (compiled
machine-code objective + integer rounding + constraint penalty) and incumbents
chosen by `nm_better` (Deb rules), so box / general-constraint / mixed-integer
problems work unchanged; unlike `scipy.optimize.direct` (box-only) this makes
DIRECT usable on constrained problems. The raw incumbent is returned and then
polished by the driver's exact local optimizer unless `"PostProcess" -> False`.
The store is a realloc-doubled structure of arrays with O(1) head removal and
per-class sorted insertion, matching the Fortran's efficiency; zero leaks
(macOS `leaks`).

**Sub-options** (full `scipy.optimize.direct` parity, all scoped to DIRECT):
`"LocallyBiased"` (True = DIRECT-L default / False = original DIRECT),
`"Epsilon"` (eps, default 1e-4), `"MaxFunctionEvaluations"` (default 1000·n),
`"MaxIterations"` (default 1000), `"VolumeTolerance"` (1e-16),
`"LengthTolerance"` (1e-6), `"MinValue"` / `"MinValueTolerance"` (known-optimum
early stop). Wired through the method enum, `nm_method_from_string` /
`nm_method_name`, `nm_option_owner` + `nm_parse_method` (respecting the
owner/parse invariant), and the `nm_driver.c` dispatch + config defaults
(`findmin_internal.h`).

**Tests.** New `tests/test_direct.c` (`direct_tests`, 29 test groups): result
shape, convex/unimodal exact minima, the standard multimodal suite (Himmelblau,
Rastrigin, Ackley, Branin, six-hump camel, Styblinski-Tang 2-D/4-D,
Cross-in-tray, Shubert, Eggholder), DIRECT/DIRECT-L parity, constrained (disk,
Mishra's Bird), every sub-option, determinism, option scoping, 8-D sphere, a 5-D
Rastrigin stress case, and a memory-hygiene loop. All pass; zero leaks; no
regression in the sibling `shgo_tests` / `dual_annealing_tests` /
`nminimize_tests`.

**Benchmark.** `benchmarks/83-direct` races `scipy.optimize.direct` on nine
standard bounded multimodal problems (raw-vs-raw, scipy defaults): identical
basin on all nine (0 CHECK-FAIL), Mathilda AHEAD on all nine, ~1.5×–20× faster
per solve (its compiled objective avoids scipy's Python-callback-per-evaluation).

**Testbed benchmark.** `benchmarks/84-direct-testbed` sweeps the whole
`tests/test_nminimize.c` corpus through DIRECT with per-problem parameterisation.
The `.m`/`.py` race is the raceable subset — 18 continuous box-bounded problems
(1-D to 10-D: quartic, Gamma, Schwefel, Schaffer, Eggholder, Griewank-5/10,
scaled-quadratic, Katsuura, Rastrigin-5/8, Rosenbrock-10, modified Ackley,
Gaussian well, …): 0 CHECK-FAIL, 15 of 18 AHEAD (up to 11× on the origin-centred
high-D globals). The three losses are objective-evaluation cost, not the DIRECT
algorithm — two cheap few-hundred-eval objectives, and Katsuura-8D (29×), whose
`Round`/nested-`Sum` objective does not take the compiled fast path (a
compile-coverage gap that would slow any method equally). The README additionally
documents the non-raceable remainder: `Method -> "DIRECT"` solves 16 constrained
/ equality / disjunctive / small-integer corpus problems that scipy's box-only
`direct` cannot express (disk −4.2426, LP 3.25, equality 2.333, Himmelblau-over-
two-disks 0, integer LP 1, …), and the high-D-equality A-series and combinatorial
B-series are documented as beyond DIRECT in either system (solved by Mathilda's
DE / SLSQP / integer engines).

**Portability.** Fixed a pre-existing latent Linux-portability bug surfaced by
`make check-c99`: `src/numerical_calculus/nm_dual_annealing.c` used `M_PI`
without the C99 `#ifndef` fallback (glibc hides it under `-std=c99`); added the
guard.

**Docs.** `src/info.c` NMinimize docstring (Methods + sub-options),
`docs/spec/builtins/numerical-calculus.md` (Methods-table row, eight sub-option
rows, and a dedicated `#### DIRECT` subsection with algorithm, fidelity note,
worked examples, and benchmark results).
