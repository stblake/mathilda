# Changelog: week of 2026-08-17 (Mon) – 2026-08-23 (Sun)

Feature additions and fixes recorded during this week.

## ContourPlot: MaxRecursion adaptive grid refinement (2026-08-18)

- ContourPlot previously had no adaptive-refinement mechanism at all -- it
  sampled one fixed `(PlotPoints+1)x(PlotPoints+1)` grid and ran marching
  squares once, unlike `Plot`/`Plot3D`/`ParametricPlot`/`ParametricPlot3D`,
  which all already expose `MaxRecursion`. It now accepts `MaxRecursion`
  (default 2): the whole grid's resolution doubles -- up to `MaxRecursion`
  times, hard-capped at 200 points/axis -- while a cheap bilinear flatness
  spot-check (cell-centre `f` value vs. the bilinear average of the cell's
  4 corners, tolerance 0.25%) fails. This mirrors `plot3d.c`'s
  `sample_surface`/`surface_is_flat` design exactly: doubling the *whole*
  grid rather than subdividing individual cells into a quadtree, since a
  quadtree would leave T-junction cracks in the marching-squares output
  where differently-refined cells meet. `MaxRecursion -> 0` recovers
  today's fixed-grid behaviour exactly. Applies to both the single-function
  form and each equation of the `ContourPlot[{eq1, eq2, ...}, ...]` list
  form (each equation refines independently, since they may have different
  curvature).
- `tests/test_autocompile.c`'s `test_contourplot_parity` now pins
  `MaxRecursion -> 0` on both the compiled and interpreted expressions it
  compares (matching the same convention `tests/test_plot3d.c` already
  uses throughout), since flatness-driven doubling is a data-dependent
  decision made independently by each evaluation path and the test verifies
  grid-evaluation parity, not refinement parity. New tests in
  `tests/test_graphics.c` cover the `MaxRecursion -> 0` baseline, refinement
  being live by default, and rejection of negative `MaxRecursion` values.
