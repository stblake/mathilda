# Changelog: week of 2026-11-02 (Mon) – 2026-11-08 (Sun)

## Comparisons numericalise only numeric quantities; NumericQ of an algebraic Root (v0.6129)

- **`Equal` and the other comparisons** (`comparisons.c`). The value fallback ran `N` on a side that was not a numeric quantity. `N` maps into the arguments of an inert call, so `ff[5] == x` evaluated `ff[5.]` and fired a definition the reference never reaches.
  - FeynCalc guards `GA[5.]` with a message, so `GA::noint` was printed inside every `... == x` test that carries a `GA[5]`.
  - The fallback now runs only when `expr_is_numeric_quantity` holds. `Sqrt[2] == 1.4142135623730951` and `Sin[1] == Sin[1.]` are still `True`.
- **`NumericQ[Root[f, k]]`** (`core.c`). An algebraic Root with a polynomial pure-function body and numeric coefficients is now a numeric quantity, as in the reference (it was `False`; only transcendental `Root[{f, x0}]` was recognised). Without this, the gate above stopped `Minimize` from comparing its Lagrange candidates, `Root` objects, against numbers.
- **Measured.**
  - The FeynCalc pass set is 13,286, up 9 and a superset, all with the right answer and no extra message: `Anti5ToTheRight-ID32`, `Chisholm-ID30`, `DiracSubstitute5-ID4`, `DiracSubstitute67-ID5` (two variants), `EpsChisholm-ID11`, `SirlinSimplify-ID29`, `SpinorChainChiralSplit-ID7` and `ToDiracGamma67-ID17`.
  - New `equal_symbolic_sides_tests` (13 checks, reference values).
  - Unit suites as in v0.6128.

## A patterned head backtracks when its arguments or guard fail (v0.6128)

- **Matcher** (`match.c`). A pattern whose head carries patterns of its own was matched head-first with no continuation, so the head committed to its first assignment. A SubValue LHS like FeynCalc's `R[nN_, k_][i___Integer, mm:(_Integer)..][a_List] := ... /; ({mm}[[1]] === getm[a])` is an example: when the guard failed for the first split of the inner sequence, the match failed instead of trying `i = {0, 0}`, `mm = {1, 1}`.
  - The argument level, and the guard, are now the head match's continuation, at both head-matching sites (the guarded and the plain function pattern).
  - The OneIdentity fall-through keeps its old trigger.
  - `h[n_][i___Integer, mm:(_Integer)..][a_List] := {{i}, {mm}} /; {mm}[[1]] === 1` gives `{{0, 0}, {1, 1}}` on `h[2][0, 0, 1, 1][{x}]`, as in the reference (it was unevaluated). Plain DownValues already backtracked.
- **Measured.**
  - The FeynCalc pass set is 13,277, up 20 and a superset: `PaVeReduceBFunctions` ID21 and ID23, `PaVeReduceCFunctions` ID19–24, `PaVeReduceDFunctions` ID12–22 and `PaVeReduce-ID2`. PaVeReduce had left `R[2, 1][0, 0, 1, 1][{0, m1^2, m2^2}]` unevaluated.
  - The matcher stress corpora pass in full (311 and 11,385 cases).
  - New `patterned_head_backtrack_tests` (7 checks, reference values).
  - Unit suites as in v0.6127: the two working-directory suites and the `DSolve`EigenvalueProblem` stop in `dsolve_tests` still fail.

## Parametric Solve and Gröbner bases over Q(params), Solve without variables, PossibleZeroQ on inert calls (v0.6127)

FeynCalc's momentum-shift and topology-mapping finders (`FCLoopFindMomentumShifts`, `FCLoopFindTopologyMappings`) solve `lhs^2 == rhs^2` systems in the shifted loop momenta, with the momenta as parameters. Bisecting them turned up six kernel causes.

- **`Solve[eqns]` and `Solve[eqns, {}]`** (`solve/solve.c`) solve for every variable the system mentions. A variable is a maximal non-numeric subexpression not built by a numeric function, sorted canonically: `Solve[{f[a] + b == 1, b == 2}, {}]` is `{{b -> 2, f[a] -> -1}}`. A system with no variable is `{{}}` or `{}`, so `Solve[{}, {}]` is `{{}}` (it was `Solve::ivar`).
- **A wrong answer fixed: `GroebnerBasis[..., CoefficientDomain -> RationalFunctions]`** (`poly/groebner.c`, `poly/groebnerbasis.c`).
  - The reduction over Q(params) was a fraction-free pseudo-division. It scaled the remainder by the reducer's leading coefficient but not the part already retired, and it stripped content from one half only, so the "reduced" polynomial left the ideal. On the 5-equation shift system that produced a parameter-only generator: a false unit ideal, so Solve saw no solution.
  - The reduction now runs on FLINT rational functions (`fmpz_mpoly_q`), each generator monic. Denominators are cleared and the content in Z[params] is divided out at the end, so `Q x2 - p1 Q` is reported as `-p1 + x2`, as in the reference. The old routine stays as the fallback without FLINT.
  - The ring basis now uses a block order: lex on the main variables, then degree-reverse-lex on the parameters. A 4-unknown, 4-parameter system went from over a minute under full lex to 0.1 s. This also fixed a use-after-free: the weight matrix was freed before the reduction that orders by it.
- **No parameter cap in Solve's nonlinear-system path** (`solve/solvenlsys.c`). It declined above three parameters, so a routing system in four momenta stayed unevaluated (memory: no arbitrary caps). Back-substituted roots are `Cancel`-ed on the parametric path: `(p1 p4 q1 + p4^2 q1 + p4 q1^2)/(p1 q1 + p4 q1 + q1^2)` is `p4`.
- **Univariate Solve factors symbolic polynomials at every degree** (`poly/solvepoly.c`). Previously only quadratics were factored. A quartic `(d^2 - q1^2)(d^2 - (2 l2 + q1)^2)`, expanded, went to the biquadratic formula and came back as nested radicals; it now gives `d -> +-q1, +-(2 l2 + q1)`, as in the reference.
- **A wrong answer fixed: `PossibleZeroQ[f[a]]` was `True`** (`zero_test.c`).
  - The sampler substitutes numbers for symbols only, so an inert call stayed symbolic, the test ended UNKNOWN, and the builtin answered `True`. FeynCalc therefore accepted the shift `l1 -> l1` between two different propagators.
  - The builtin now abstracts each distinct maximal call to a fresh symbol, in the expression and its assumptions. A call is abstracted when its head is not a symbol, or names neither a builtin nor a `NumericFunction`. So `PossibleZeroQ[f[a]]` and `PossibleZeroQ[C[1] - 1]` are `False`, and `PossibleZeroQ[f[a] - f[a]]` is `True`, all as in the reference.
  - `zero_test_decide`, which the solvers use internally, is unchanged.
  - Three unit tests asserted the old answer and now check what they meant to check: the zero-test trip-wire expects the reference's `False`, a Solve check substitutes its integer `C[2]`, and the PowerSeries residual is tested through `Normal`.
- **`AssociationThread[keys -> scalar]`** (`assoc.c`) gives the scalar to every key. Lists of different lengths emit `AssociationThread::idim`. FeynCalc's preferred-topology filter builds its set this way, so every mapping was being filtered out.
- **Measured.**
  - The FeynCalc pass set is 13,257, up 40 and a superset of the last run.
  - All 48 `FCLoopFindMomentumShifts`, `FCLoopFindTopologyMappings` and `FCLoopApplyTopologyMappings` tests pass. `FCCompareNumbers` ID2, ID3 and ID12 and `FourSeries` ID10–12 pass as a side effect.
  - An interleaved A/B against v0.6126 on `TID` and `FCMultiLoopTID` gave 45.3/44.5 s against 48.3/44.0 s, so no slowdown. The full-corpus timing ran while the machine was under load (load average 11) and is not comparable.
  - New `parametric_solve_tests` (29 checks, reference values).
  - Unit suites pass except `mixed_numericalize_tests` and `match_exhaustive_observe`, which depend on the working directory, and `dsolve_tests`. The latter stops at a `DSolve`EigenvalueProblem` check that also fails on v0.6126.

## Simplify splits powers over assumed-positive factors; OptionValue is resolved only where the definition wrote it (v0.6126)

- **`(a b)^c = a^c b^c` for `a > 0` by assumption** (`simp/simp_power.c`). Simplify's power split took off only literal positive constants. It now also splits a factor provably positive under the assumptions; an assumed-positive power `b^p` (with `b > 0` and `p` real) goes straight to `b^(p c)`, so the following evaluation cannot merge it back.
  - `Simplify[(-la^4)^s la^(-4 s), Assumptions -> la > 0]` is `(-1)^s`, and `Simplify[(-la^4 x)^s la^(-4 s), la > 0]` is `(-x)^s`, both as in the reference.
  - **A wrong answer fixed.** FeynCalc's `FCFeynmanProjectivize` scales the Feynman parameters by `la` times random primes and checks that `la` drops out of Simplify. Whenever the primes made the F polynomial negative, `la` survived. `FCFeynmanFindDivergences` then treated the integral as non-projective and reported divergent regions that are not there. That was the run-to-run flakiness of its ID16, ID19 and ID20.
  - Three tests that had never passed now pass: FCFeynmanFindDivergences-ID8, FCFeynmanProjectiveQ-ID5 and FCFeynmanProjectivize-ID5.
  - Still open: `Refine[(-la^4)^s, la > 0]` and `FullSimplify` do not yet split this way.
- **OptionValue only where the definition wrote it** (`symtab.c`, `Rule.ov_tmpl`). The rewrite of `OptionValue[name]` after an `OptionsPattern` rule fires is skipped when the rule's replacement mentions no `OptionValue`. The flag is computed once per rule.
  - This saves walking the substituted result.
  - It no longer rewrites an `OptionValue` that arrived inside an argument: `fo[x_, OptionsPattern[]] := {x}` leaves `fo[Hold[OptionValue[aa]]]` as `{Hold[OptionValue[aa]]}`, as the reference does.
  - Still open: a replacement that does mention `OptionValue` still rewrites the arguments' copies too.
- **Measured.** The FeynCalc pass set is 13,217, up 3 and a superset of the last run. Corpus geometric mean is 1.43x and total compute 186 s (the reference takes 272 s). Unit suites pass except the two that depend on the working directory. `exponent_generators_tests` gains 6 checks, with reference values.

## Fixed points survive Block, Dispatch and held arguments; UpValues keyed on their outer head; Det memoises minors (v0.6124)

Three bisections of FeynCalc cliffs (Chisholm, FCFADiracChainJoin, FCFeynmanPrepare, PaVeReduce) found three kernel causes.

- **A certified "no rule fires" verdict survives a Block** (`eval.c`, `core.c`, `modular.c`, `symtab.h`). FeynCalc's `DiracChain` rule calls `FCI` in its condition. `FCI` uses `Block`, `Dispatch` and assignments to its Block locals. Every failed dispatch was therefore tainted, so an evaluated chain re-ran the 100 µs condition whenever it was wrapped again. In Chisholm that meant 18 times as many `FCI` calls as the reference. Four changes, each sound on its own:
  - `Dispatch`, `With` and `Block` are on the `eval_pure` list. Block saves and restores what it scopes; its body's reads are recorded as for any expression.
  - **Frame-scoped bindings.** A symbol scoped by a Block entered inside an open dispatch frame carries that frame's depth `s` (`SymbolDef.dep_scoped`).
    - A clock bump for such a symbol is discounted by the frames at depth `s` or less, which enclose the Block. Their certificate does not depend on it: the Block puts the symbol back before they end.
    - A `Set`/`SetDelayed` to it taints only frames nested inside the Block (`g_dep_taint_above`).
    - Reading it records no dependency for those frames. Recording it had made the next Block's binding of `FCI`'s locals advance the INERT epoch: 18,545 global invalidations in the FCFADiracChainJoin tests, now 497.
  - An argument held by its head no longer enters an INERT verdict, so `lhs :> DiracGamma[7]` and `Hold[...]` can be fixed points. Before, `FCI`'s rule lists carried only exact-clock stamps, and reusing them tainted every frame that read them.
  - `MATHILDA_DISPATCH_STATS` now also prints why frames were tainted.
- **UpValues are skipped by the pattern's own head** (`symtab.c`, `Rule.outer_head`). `SPD`'s UpValues are `SPD[a_, b_] = c_`, so they can only match a `Set`. They were tried inside every `Times`, `Plus` and `Power` holding an `SPD`: 210k failed matches in 31 `PaVeReduce` calls. The UpValue filter also uses the per-slot shape keys now.
- **Symbolic `Det` memoises minors** (`linalg/det.c`). FCFeynmanPrepare's 10×10 block-diagonal check went from 1.8–4 s to 0.6 ms (the reference takes 1.1 ms).
- **Tests.**
  - `eval_timestamps_tests` gains 8 scenarios for frame-scoped bindings and held arguments, agreeing with `MATHILDA_NO_DEP_CERT=1` and with v0.6120.
  - `dispatch_slot_keys_tests` gains the UpValue cases, with reference values.
  - The `Det` results were checked against the permutation formula.
- **Measured.**
  - FCFADiracChainJoin-ID5 went from 1.01 s to 0.39 s (the reference takes 0.16 s); ID12 from 0.41 s to 0.058 s (reference 0.071 s).
  - FeynCalc corpus geometric mean went from 1.296x to **1.443x**, and total compute from 206 s to 188 s (the reference takes 272 s).
  - The pass set is identical (13,214 ids). The unit suites pass except the two that depend on the working directory.

## OptionValue resolution no longer copies a definition's arguments (v0.6123)

- **What changed** (`options_builtin.c`, `optionvalue_inject_context`). When a definition with `OptionsPattern[]` fires, each `OptionValue[name]` in the right-hand side is rewritten to name its head and options. That rewrite rebuilt the whole substituted body, including every argument bound into it.
  - A 50,000-term sum passed to `f[x_, OptionsPattern[]]` was copied node by node on every call.
  - The copies carried no fixed-point stamps, so all 50,000 terms were evaluated and dispatched again: FeynCalc's `FCTraceExpand` spent 0.17 s per call doing nothing.
  - Only the path down to each `OptionValue` is rebuilt now; every other subtree is shared.
- **Results.** Resolution is unchanged at every depth, in the head, and in a `/;` guard; checks were added to `dispatch_slot_keys_tests`, with reference values.
  - `FCTraceExpand` on that sum went from 176 ms to 10 ms per call.
  - `DummyIndexFreeQ` test ID5 went from 2.8 s to 0.88 s (the reference takes 1.27 s).
  - The FeynCalc corpus geometric mean went from 1.157x to **1.296x** the reference, and total compute from 257 s to 206 s (the reference takes 272 s).
  - The pass set is identical (13,214 ids). The unit suites pass except the two that depend on the working directory.

## FactorList2's check: exponent generators in Together, no trial division in Simplify (v0.6122)

- **Integer prime-power test** (`simp/simp_power.c`, `prime_rebase_check`).
  - Simplify rewrites a prime-power base, `64^x` to `2^(6 x)`. It decided whether an integer was `p^k` by trial division up to its square root.
  - FeynCalc's `FactorList2` checks its answer by substituting random primes below 10^8. That produces 16-digit bases, so each Simplify pass did 33 million divisions.
  - The test now takes the largest exact integer root (GMP `mpz_root`) and checks it for primality. Results are unchanged.
  - Simplify on the captured check went from 2.1 s to 0.9 ms (the reference takes 12 ms).
- **Exponent generators in Together and Cancel** (`rat.c`). These now use the `Factor` reading `b^(n + k t) = b^n (b^t)^k` when two powers of one base have exponents differing by a nonzero integer, and keep the result only if it is strictly smaller.
  - `Together[2 x^(-2 e) - 2 x x^(-1 - 2 e)]` is `0`. Before, it combined over `x^(1 + 4 e)`.
  - `Simplify[2 (5 + 7 s)^(-2 e) - (10 + 14 s) (5 + 7 s)^(-1 - 2 e)]` is `0`.
  - `Together[2^n + 2^(n + 1)]` is `3 2^n`, as in the reference.
  - The reference's forms of `Cancel[x^(n - 1)/(1 + x^n)]` and of sums over `E^x` and `E^(2 x)` are kept.
- **Measured.**
  - `FactorList2` on the `FCFeynmanRegularizeDivergence-ID2` input went from 3.5–5.9 s to 5 ms. The test itself went from 6.5 s to 6.5 ms, and the file from 0.008x to 0.5x the reference.
  - Corpus total compute is 257 s (the reference takes 272 s). The pass set is 13,214 ids, a superset of the v0.6121 set.
  - The unit suites pass except the two that depend on the working directory. The new `exponent_generators_tests` has 9 checks, with reference values.

## FeynCalc cliffs: per-slot rule dispatch, no foreign-call group spans, FreeQ walk (v0.6121)

- **Per-slot DownValue dispatch keys** (`symtab.c`, `Rule.slot_keys`).
  - Each leading fixed-length slot of a stored rule records the heads a matching argument can have and, for a call slot, its argument count. That covers Alternatives heads and pattern-named heads such as `(a:h1|h2)[...]`.
  - A rule that no argument fits is skipped before the matcher runs: by position, or, for an Orderless head, when no assignment of the arguments fits.
  - The old filter keyed only the first argument, and never for an Orderless head. FeynCalc's `Pair` (Orderless, 36 rules) therefore ran the matcher 36 times per call.
  - On the 50,000-term `DummyIndexFreeQ` test, match attempts fell from 24.8M to 1.16M.
  - A Flat argument head relaxes the arity check. A `Verbatim` slot keys nothing, which fixes `v[Verbatim[_Integer]] := 1` never firing for `v[_Integer]`; the first-argument key had the same bug.
- **No group spans for a call on another head** (`match.c`).
  - Under a Flat head, an element that is a call on a different head takes exactly one operand, OneIdentity or not, as in the reference. `MatchQ[2 x y, y_^n_. x]` is now `False`, and `ReplaceList[a + b + c, n_ o1_. + o2_ :> ...]` gives the reference's 3 matches instead of 6.
  - The whole subject is still reached through the defaults (`{1, 2 x, 1}` for `x_. y_^n_.` against `2 x`).
  - The last element of a Flat pattern takes every remaining operand. In an Orderless Flat pattern a plain blank (`o2_`, `o2_:0`) is matched after the single-operand elements; an `x_:0` with its own default no longer blocks that reordering.
  - `n_?NumberQ o1_. + o2_:0` against a sum was about 3ⁿ: 20 s at 14 terms. It now takes microseconds at 20 terms.
  - That pattern is what FeynCalc's `DotSimplify` runs on every Dirac chain, so `Contract[DiracSimplify[DiracReduce[...].DiracReduce[...]]]` went from 9.9 s to 0.49 s (the reference takes 0.45 s).
  - The reference-graded observe corpus improved from 303 to 309 of 413, with no regressions. Both gating corpora pass in full: 11,385 and 311 cases.
- **FreeQ fast path** (`funcprog.c`). A form that is an atom, a `_h` blank, or an Alternatives of those is searched at the default levels by a pointer-comparing walk. Separately, `get_depth` is computed only when a negative level bound needs it; it had walked each subtree once per ancestor.
- **Measured.** These were measured on a quiet machine, at `--jobs 10`, per-dir.
  - The FeynCalc corpus geometric mean over files went from 1.072x to 1.157x the reference kernel.
  - Total compute went from 315 s to 261 s. The reference takes 272 s, so the total is now faster than the reference (1.04x).
  - Of the microbenchmarks (17 calls), measured against the v0.6120 binary in the same session, the warm geomean went from 1.00x to 1.09x and the cold one from 1.06x to 1.16x.
  - Pass set: 13,213 ids, the same as before apart from the two `FCFeynmanFindDivergences` ids (ID16 and ID20). Both flip between runs of the same binary. That function samples random primes, and the issue is logged in `tasks/todo.md`.
  - The unit suites pass except the two that depend on the working directory, as before.
- **Tests.** New `dispatch_slot_keys_tests` suite, 47 checks, every expected value from the reference kernel.
- **Next cliff found.** `Simplify[2 (5 + 7 s)^(-2 e) - (10 + 14 s) (5 + 7 s)^(-1 - 2 e)]` is 0 in the reference but stays unsimplified here. FactorList2's `Check` hits that shape, which is behind `FCFeynmanRegularizeDivergence-ID2` taking 3–6 s.

## Interned symbol names compared by pointer, system-wide (v0.6120)

- **What changed.** 1,137 comparisons of a symbol name against a string
  literal (`strcmp(e->data.symbol.name, "Sin") == 0`) now compare the interned
  pointer instead (`e->data.symbol.name == SYM_Sin`). The change covers 113
  files. Both forms give the same answer: two interned names are equal exactly
  when their pointers are, and the pointer compare skips scanning the name.
  That scan was measurable on FeynCalc, whose symbol names share a 30-character
  context prefix.
- **Which comparisons were converted.** A comparison was converted only where
  the string provably holds an interned symbol name: a symbol node's name, or
  a variable or same-file helper result traced back to one.
- **Which were left alone.** These keep `strcmp`:
  - string data (`EXPR_STRING`, such as option and method strings);
  - parameters of functions called from other files;
  - names built at run time;
  - context and prefix checks.
- **New `SYM_` names.** 54 were added in `sym_names.{h,c}`, each for a name
  that was already a System symbol at startup. That matters because
  `sym_names_init` runs before the step that marks every name interned so far
  as System.
- **Left for a decision.** 30 literals naming symbols that are currently
  Global stay as `strcmp`, since interning them early would make them System.
  Examples are box heads (`FractionBox`, `SqrtBox`), the
  `PositiveIntegers`-style domains, and `CompositeQ`.
- **Verification.**
  - The build is warning-free, and `check-c99` and `check-messages` pass.
  - A 13-expression smoke test matches the earlier binary byte for byte.
  - The unit suites and the FeynCalc corpus pass, the latter with its pass set
    unchanged. One id, `fcstFCFeynmanFindDivergences-ID16`, failed once and
    passed on every rerun: it probes with `RandomPrime`.
  - With the machine quiet, the corpus geometric mean is 1.07x the reference
    kernel over 254 files. Total compute is 315 s against the reference's
    272 s.
- **Tests.** `test_match.c` and `test_match_extensive.c` passed string
  literals to `env_get` / `env_set`. Since v0.6119 the keys compare by pointer
  alone, so a literal never matched. The tests now intern their keys, and
  `match.h` states the contract: keys are interned names.
