# Changelog: week of 2026-11-02 (Mon) – 2026-11-08 (Sun)

## OptionValue resolution no longer copies a definition's arguments (v0.6123)

- **What changed** (`options_builtin.c`, `optionvalue_inject_context`). When a definition with `OptionsPattern[]` fires, each `OptionValue[name]` in the right-hand side is rewritten to name its head and options. That rewrite rebuilt the whole substituted body, including every argument bound into it.
  - A 50,000-term sum passed to `f[x_, OptionsPattern[]]` was copied node by node on every call.
  - The copies carried no fixed-point stamps, so all 50,000 terms were evaluated and dispatched again: FeynCalc's `FCTraceExpand` spent 0.17 s per call doing nothing.
  - Only the path down to each `OptionValue` is rebuilt now; every other subtree is shared.
- **Results.** Resolution is unchanged at every depth, in the head, and in a `/;` guard; checks were added to `dispatch_slot_keys_tests`, with reference values.
  - `FCTraceExpand` on that sum went from 176 ms to 10 ms per call.
  - `DummyIndexFreeQ` test ID5 went from 2.8 s to 0.88 s (the reference takes 1.27 s).
  - The FeynCalc corpus geometric mean went from 1.157x to **1.296x** the reference, and total compute from 257 s to 206 s (the reference takes 272 s).
  - The pass set is identical (13,214 ids). The unit suites pass except the two that depend on the working directory.

## FactorList2's check: exponent generators in Together, no trial division in Simplify (v0.6122)

- **Integer prime-power test** (`simp/simp_power.c`, `prime_rebase_check`).
  - Simplify rewrites a prime-power base, `64^x` to `2^(6 x)`. It decided whether an integer was `p^k` by trial division up to its square root.
  - FeynCalc's `FactorList2` checks its answer by substituting random primes below 10^8. That produces 16-digit bases, so each Simplify pass did 33 million divisions.
  - The test now takes the largest exact integer root (GMP `mpz_root`) and checks it for primality. Results are unchanged.
  - Simplify on the captured check went from 2.1 s to 0.9 ms (the reference takes 12 ms).
- **Exponent generators in Together and Cancel** (`rat.c`). These now use the `Factor` reading `b^(n + k t) = b^n (b^t)^k` when two powers of one base have exponents differing by a nonzero integer, and keep the result only if it is strictly smaller.
  - `Together[2 x^(-2 e) - 2 x x^(-1 - 2 e)]` is `0`. Before, it combined over `x^(1 + 4 e)`.
  - `Simplify[2 (5 + 7 s)^(-2 e) - (10 + 14 s) (5 + 7 s)^(-1 - 2 e)]` is `0`.
  - `Together[2^n + 2^(n + 1)]` is `3 2^n`, as in the reference.
  - The reference's forms of `Cancel[x^(n - 1)/(1 + x^n)]` and of sums over `E^x` and `E^(2 x)` are kept.
- **Measured.**
  - `FactorList2` on the `FCFeynmanRegularizeDivergence-ID2` input went from 3.5–5.9 s to 5 ms. The test itself went from 6.5 s to 6.5 ms, and the file from 0.008x to 0.5x the reference.
  - Corpus total compute is 257 s (the reference takes 272 s). The pass set is 13,214 ids, a superset of the v0.6121 set.
  - The unit suites pass except the two that depend on the working directory. The new `exponent_generators_tests` has 9 checks, with reference values.

## FeynCalc cliffs: per-slot rule dispatch, no foreign-call group spans, FreeQ walk (v0.6121)

- **Per-slot DownValue dispatch keys** (`symtab.c`, `Rule.slot_keys`).
  - Each leading fixed-length slot of a stored rule records the heads a matching argument can have and, for a call slot, its argument count. That covers Alternatives heads and pattern-named heads such as `(a:h1|h2)[...]`.
  - A rule that no argument fits is skipped before the matcher runs: by position, or, for an Orderless head, when no assignment of the arguments fits.
  - The old filter keyed only the first argument, and never for an Orderless head. FeynCalc's `Pair` (Orderless, 36 rules) therefore ran the matcher 36 times per call.
  - On the 50,000-term `DummyIndexFreeQ` test, match attempts fell from 24.8M to 1.16M.
  - A Flat argument head relaxes the arity check. A `Verbatim` slot keys nothing, which fixes `v[Verbatim[_Integer]] := 1` never firing for `v[_Integer]`; the first-argument key had the same bug.
- **No group spans for a call on another head** (`match.c`).
  - Under a Flat head, an element that is a call on a different head takes exactly one operand, OneIdentity or not, as in the reference. `MatchQ[2 x y, y_^n_. x]` is now `False`, and `ReplaceList[a + b + c, n_ o1_. + o2_ :> ...]` gives the reference's 3 matches instead of 6.
  - The whole subject is still reached through the defaults (`{1, 2 x, 1}` for `x_. y_^n_.` against `2 x`).
  - The last element of a Flat pattern takes every remaining operand. In an Orderless Flat pattern a plain blank (`o2_`, `o2_:0`) is matched after the single-operand elements; an `x_:0` with its own default no longer blocks that reordering.
  - `n_?NumberQ o1_. + o2_:0` against a sum was about 3ⁿ: 20 s at 14 terms. It now takes microseconds at 20 terms.
  - That pattern is what FeynCalc's `DotSimplify` runs on every Dirac chain, so `Contract[DiracSimplify[DiracReduce[...].DiracReduce[...]]]` went from 9.9 s to 0.49 s (the reference takes 0.45 s).
  - The reference-graded observe corpus improved from 303 to 309 of 413, with no regressions. Both gating corpora pass in full: 11,385 and 311 cases.
- **FreeQ fast path** (`funcprog.c`). A form that is an atom, a `_h` blank, or an Alternatives of those is searched at the default levels by a pointer-comparing walk. Separately, `get_depth` is computed only when a negative level bound needs it; it had walked each subtree once per ancestor.
- **Measured.** These were measured on a quiet machine, at `--jobs 10`, per-dir.
  - The FeynCalc corpus geometric mean over files went from 1.072x to 1.157x the reference kernel.
  - Total compute went from 315 s to 261 s. The reference takes 272 s, so the total is now faster than the reference (1.04x).
  - Of the microbenchmarks (17 calls), measured against the v0.6120 binary in the same session, the warm geomean went from 1.00x to 1.09x and the cold one from 1.06x to 1.16x.
  - Pass set: 13,213 ids, the same as before apart from the two `FCFeynmanFindDivergences` ids (ID16 and ID20). Both flip between runs of the same binary. That function samples random primes, and the issue is logged in `tasks/todo.md`.
  - The unit suites pass except the two that depend on the working directory, as before.
- **Tests.** New `dispatch_slot_keys_tests` suite, 47 checks, every expected value from the reference kernel.
- **Next cliff found.** `Simplify[2 (5 + 7 s)^(-2 e) - (10 + 14 s) (5 + 7 s)^(-1 - 2 e)]` is 0 in the reference but stays unsimplified here. FactorList2's `Check` hits that shape, which is behind `FCFeynmanRegularizeDivergence-ID2` taking 3–6 s.

## Interned symbol names compared by pointer, system-wide (v0.6120)

- **What changed.** 1,137 comparisons of a symbol name against a string
  literal (`strcmp(e->data.symbol.name, "Sin") == 0`) now compare the interned
  pointer instead (`e->data.symbol.name == SYM_Sin`). The change covers 113
  files. Both forms give the same answer: two interned names are equal exactly
  when their pointers are, and the pointer compare skips scanning the name.
  That scan was measurable on FeynCalc, whose symbol names share a 30-character
  context prefix.
- **Which comparisons were converted.** A comparison was converted only where
  the string provably holds an interned symbol name: a symbol node's name, or
  a variable or same-file helper result traced back to one.
- **Which were left alone.** These keep `strcmp`:
  - string data (`EXPR_STRING`, such as option and method strings);
  - parameters of functions called from other files;
  - names built at run time;
  - context and prefix checks.
- **New `SYM_` names.** 54 were added in `sym_names.{h,c}`, each for a name
  that was already a System symbol at startup. That matters because
  `sym_names_init` runs before the step that marks every name interned so far
  as System.
- **Left for a decision.** 30 literals naming symbols that are currently
  Global stay as `strcmp`, since interning them early would make them System.
  Examples are box heads (`FractionBox`, `SqrtBox`), the
  `PositiveIntegers`-style domains, and `CompositeQ`.
- **Verification.**
  - The build is warning-free, and `check-c99` and `check-messages` pass.
  - A 13-expression smoke test matches the earlier binary byte for byte.
  - The unit suites and the FeynCalc corpus pass, the latter with its pass set
    unchanged. One id, `fcstFCFeynmanFindDivergences-ID16`, failed once and
    passed on every rerun: it probes with `RandomPrime`.
  - With the machine quiet, the corpus geometric mean is 1.07x the reference
    kernel over 254 files. Total compute is 315 s against the reference's
    272 s.
- **Tests.** `test_match.c` and `test_match_extensive.c` passed string
  literals to `env_get` / `env_set`. Since v0.6119 the keys compare by pointer
  alone, so a literal never matched. The tests now intern their keys, and
  `match.h` states the contract: keys are interned names.
