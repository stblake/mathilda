## Pure-function application skips subtrees with no parameter and no slot (v0.6657)

`substitute_names` (named parameters) and `substitute_slots` (`#`, `##`) consult the
binder summaries:
- The parameters are registered as binders, and so are `Slot` and `SlotSequence`, as
  pseudo-binders.
- A subtree whose summary has none of their bits is returned shared without being
  visited.

**A shared parent counts as frozen.** A body's own refcount is 1, because only its
Function node (or Module/With node) holds it; the parent is the shared one. The walkers
therefore take a `frozen` flag from the call site: `head->refcount >= 2` in
`apply_pure_function`, and `res->refcount >= 2` in Module and With. Without that, a
Function stored in an OwnValue never had its body summarised.

Measured, all with identical answer hashes:
- Function micro row, 10k leaves: 84 µs → 0.7 µs.
- Every micro row (rule-only, Module, With, Block, Function) is now 0.6–2.4 µs at any
  body size.

|---|---|
| Trager | −14.4% |
| `cM-1-292` | −12.8% |
| the other nine | −2.6% to +1.7% |

## The capture-avoidance danger set is built only when a clash is possible (v0.6656)

When a rule application meets a binding scope, it used to build the danger set by walking
every binding value. On the Trager case that walk ran 119,197 times and found something
to rename 30 times. `rb_scope_may_clash` now decides first:
- It registers the scope's locals as binders.
- It ORs the binding values' summaries. For a node with no summary, such as an indexed
  Association like Trager's `ctx`, it ORs its children's, one level down.
- It leaves the scope alone when no local shares a bit with a value or with a pattern
  variable.
- Any doubt (a value with no valid summary, or a bit in common) falls back to the exact
  path.

Under `MATHILDA_SYMSUM_DIFF=1`, rule applications now also compare the *number* of
renames between the fast and slow walks, so a skip that dropped a needed rename fails
there. Previously such applications were not compared at all.

Measured: Trager −0.5% instructions on top of v0.6655, hashes identical. The unit tier
passes under `MATHILDA_SYMSUM_DIFF=1`.

## Rule application skips subtrees with no pattern variable and no scope (v0.6655)

`replace_bindings` (`rb_rec`), which every DownValue, OwnValue, SubValue, UpValue and
`ReplaceAll` application ends in, consults the binder summaries. The mask is the pattern
variables' bits plus the SCOPE bit, and a subtree whose summary misses it is returned
shared without being visited.

- **Why SCOPE is in the mask.** Capture avoidance renames any binding scope whose local
  collides with an injected value, even one with no pattern variable inside:
  `f[x_] := {x, Module[{e}, e]}; f[e + 1]` renames the Module's `e`. With SCOPE in the
  mask, a skipped subtree contains neither a pattern variable nor a binding scope, which
  is exactly what the slow walk returns untouched. The proposal's prototype masked only
  the pattern variables and would have changed that output (`scoping_semantics_tests`
  pins it).
- **Stored rules.** The four stored-rule call sites in `symtab.c` use
  `replace_bindings_stored`, so summaries are filled on the stored right-hand side.
  Other callers fill only below shared nodes.
- **Registration.** Pattern variables are registered as binders when a rule is stored
  (`symsum_register_pattern` in `add_rule_in`), while packages load.

| Modules nested 8 deep | 20 µs | 8.5 µs |

## Module and With skip subtrees that hold none of their locals (v0.6654)

`substitute_scoping`, the Module/With renaming walk, consults the binder summaries
(`src/symsum.h`; design in `docs/design/scoping_substitution.md`).
- **Skipping subtrees.** A subtree whose valid summary holds none of the env's bits is
  returned shared without being visited.
- **Symbol visits.** A symbol without one of those bits skips the env scan.
- **Filling summaries.** The walk fills summaries bottom-up on frozen nodes: those below
  a shared node, which copy-on-write makes immutable.
- **Registration.** The wrapper registers the env's names as binders first.

This covers the main cost the proposal found: a large value a rule injects into a Module
body, such as Trager's `goodPrime` context Association, is skipped at its root instead of
being walked on every call.

## Module no longer moves the evaluation clock; scoping-summary substrate (v0.6653)

Design: `docs/design/scoping_substitution.md`. Proposal and measurements:
`EVAL_CHANGE_PROPOSAL.md`.

- **A fresh local's first binding bumps no clock.** `Module` binds the initial value of a
  local whose name it just minted through `symtab_bind_fresh_local`, an OwnValue store
  with no `eval_clock_bump_binding`. No node named the symbol before, so no stamp or
  dependency frame can depend on it. A pre-existing `x$n` and every later `Set` still
  bump.
- **`$ModuleNumber` is read, not rewritten.** The C counter is authoritative. The
  symbol holds `$ModuleNumber :> Internal`ModuleNumber[]`, and that builtin is not
  `eval_pure`, so a frame that reads the counter is tainted rather than certified.
  - A user `Set` or `Clear` is noticed on the next `Module` or `Unique` and adopted.
  - `Module`, `Unique` and `Unique[{...}]` share one helper, so the counter cannot run
    backwards. That trap is what broke the proposal's first prototype.
  - Before this change, every Module call ran `add_rule_in` for `$ModuleNumber` and made
    two global clock bumps. Each bump invalidated every exact-clock fixed point and
    failed every open dependency frame.
- **Measured** (instructions retired, `tools/scope_bench/ab.sh`; every answer hash
  identical):
  - Trager `((1+x^2)(2+x^4)^(1/6))/x`: 75.46 G → 72.78 G (−3.6%).
  - `cM-1-292`: 25.95 G → 23.36 G (−10.0%).
  - The other nine cases: −2.2% to +0.1%.

  `MATHILDA_MODULE_CLOCK_BUMP=1` restores the old bumps.
- **Substrate for per-node binder summaries (dormant).** `src/symsum.{c,h}`:
  - a summary word in the `data.function.index` slot, tagged by bit 0, so
    `sizeof(Expr)` is unchanged;
  - a 16-bit epoch, advanced only when a summary of the current epoch has already seen
    the new binder;
  - the SCOPE bit, shared by `Module`, `With` and `Function`;
  - `MATHILDA_NO_SYMSUM`, `MATHILDA_SYMSUM_DIFF`, `-DMATHILDA_SYMSUM_VERIFY`,
    `-DMTH_SCOPE_STATS`.

  The Association index is now read only through `expr_fn_assoc_index()`.
  `expr_invalidate_hash` and `expr_unshare` clear a summary. No walker consults
  summaries yet.
- **Tests.**
  - `tests/test_scoping_semantics.c`: the scoping probes, with expected values from the
    v0.6652 binary. They include the capture case `f[x_] := {x, Module[{e}, e]}`,
    epoch probes, and the `$ModuleNumber`/`Unique` interplay.
  - `tests/test_symsum.c`: the substrate.
  - `tools/scope_bench/`: micro-benchmarks and the corpus A/B.

## Transcendental Risch: a primitive directly above its exponential, and the exponent lattice (Campaign D4, D5, v0.6652)

Theory: `docs/notes/bronstein_extensions.tex` §T20.

- **D4: reordering independent levels.** LimitedIntegrate's decoupled step over
  an `Erf`/`Erfi`/`Erfc`/`Ei` level needs the level's exponential directly below
  it. The containment order put `Log[x]` between them, so
  `Erf[x^2] Log[x]`, `Erfi[x] Log[x]/x` and `x Erf[x] Log[x]` were undecided.
  Two adjacent levels where neither needs the other can be exchanged without
  changing the top field. The builder now moves the exponential up, then the
  primitive down, past such levels. All three are now `False`, and so is
  `x Erf[x^2] Log[x]`. FriCAS leaves each of them unevaluated. Elementary
  integrands over the same towers are still `True`.
- **D5: the Z-lattice of the exponents.** f12-elem-7 has the exponents
  `x + x^2`, `5x/2 + x^2`, `x` and `x^2`, which span `(x/2) Z + x^2 Z`. The
  tower had no level `E^(x/2)`, so it stayed dependent and the verdict was
  undecided. `rt_exp_lattice` takes the Hermite normal form of the exponents'
  coordinates modulo rational constants. Its generators are exact integer
  combinations of the exponents, which avoids constants like `E^(1/2)`. An
  exponent whose relation to the others holds only up to a nonzero constant is
  kept out of the lattice and handled as before. The lattice is computed only
  when the tower built without it is dependent. Independence is tested on the
  derivatives, which means modulo all constants. The first version tested the
  exponents against `{1}`, which only sees rational offsets. It produced a
  constant generator `E^(-I)` and certified an elementary integrand from the
  Gaussian hunt `False`. The builder now also refuses any tower that has a
  level of derivative 0. f12-elem-7 is now `True` with a verified
  antiderivative. `E^u (1 - Tanh[1 + u]^2)`,
  `(1 + I) E^(I + 4 I u) Tan[u]` and `Log[1 + E^u] (1 - Tanh[2 u]^2)` stay
  `True`.
## Bronstein: two monomials over the curve -- transcendental Risch over Q(x)(y) (Phase 5 M1, Campaign D3, v0.6651) -- and two false certificates fixed

**Two false certificates fixed, both in released versions:**
- **The Galois split (`brKummerSplit`, since v0.6645, C3.2)** treated a kernel whose
  argument involves a radical as fixed by that radical's sign change.
  - `D[Sqrt[1 + x^2] Log[x + Sqrt[x]]]` and `D[Sqrt[x] Log[1 + Sqrt[1 + x^3]]]` were
    certified "not elementary".
  - A stress of 200 elementary integrands of the form `y1 K(y2) + y2 K(y1)` gave 39 false
    certificates at v0.6650 and 0 now.
- **The one-monomial curve case (`brBCLogPart`)** took Rothstein-Trager residues of the
  monic denominator with the un-normalised numerator.
  - `D[Log[x Log[x + Sqrt[1 + x^3]] + 1]]` was certified "not elementary" through
    `Method -> "Bronstein"`; the Automatic cascade still answered it at a later stage.


`Method -> "Bronstein"` now decides integrands in `k0(t1)(t2)`, `k0 = Q(x)(y)` with `y` one
radical, each `t_i` a logarithm or exponential of an element of the field below it (the
arguments may involve `y`). Until now a second monomial beside a kernel with a radical
argument was refused (`Tower:curve-monomial-tower`, `Tower:radical-in-kernel`). The
specification is theory note sections E2 and E1 (`docs/notes/bronstein_extensions.tex`) and
their M1 scope; the code is `src/internal/bronstein/BaseTower.m`.

- **Admission** (E2.2). Every kernel above a monomial over the curve is admitted by the
  structure theorem on normal forms (`brDFSpan`, `Risch`RationalSpan` with `Y` reduced modulo
  `Y^n - b`). A dependent kernel is eliminated only with a zero offset (A3): a logarithm when
  `kappa = 1` exactly and the branch multiple is 0 at every sample point
  (`Log[1 + x^3] = 2 Log[Sqrt[1 + x^3]]`); an exponential when the constant is 0 and the
  coefficients are integers.
- **One level** (Thm E2level). BaseCurve.m's Hermite and Rothstein-Trager run on a level
  record (the derivation of every monomial, the constant test against all of them). The
  polynomial part is `RDE_1` over `k0(t1)` for an exponential top (`[SI]` Ch. 6: normal and
  special denominators, degree bounds through LD_0/PLD_0/LI_0, SPDE, the no-cancellation and
  cancellation cases) and `LI_1` for a logarithmic top (integrate over `k1`, then the span of
  the structure generators, Cor 9.3.1). Level 0 is Trager.
- **The note's examples.** Example 2 (`bgenusp-2-9`) is certified: `RDE_0(Dy, 1)` has no
  solution. Example 1 put over one denominator is certified without the D1 split. `g3`
  declines (`Tower:dependent-log-offset`).
- **M1 declines** (each Unimplemented, never a certificate): `Tower:three-monomials`,

  `BaseTower:radical-spelling`, `BaseTower:radicand-in-tower`, `BaseTower:curve-not-reduced`,
  `BaseTower:constants`, `BaseTower:irrational-log`, `BaseTower:rootsum-logand`,

  `BaseTower:cancellation-homogeneous`, and `RDEAlgebraic:undecided` as before.

## Integrate: special-function answers -- Ei/Erf/li factors by parts, the exponential ladder on exponentials and affine arguments (Campaign D7, v0.6650)

FriCAS closed 18 integrals of benchmarks 256 and 259 that Mathilda only proved
non-elementary or left open. Two causes, two fixes.

- **A special-function factor.** `E^x Ei[x]`, `Log[x] li(x)`, `x Log[x] li(x)`,
  `E^x x Erf[x]`, `x Erf[x^2]/E^(x^2)`: the Risch decision over the tower with `S` as a
  primitive monomial has no closed form to offer. One integration by parts,
  `S V - INT V S'` with `V = INT K` elementary, leaves an elementary integrand that the
  cascade closes with `Ei`, `Erf` or `li`. New stage `15b SpecialByParts`, after `LogByParts`,
  `PossibleZeroQ`-verified, sub-integrals with the tail stages suppressed: 0.01-0.1 s per
  answer, 0.1-0.2 s per decline.
- **The exponential polylogarithm ladder.** Its gate wanted a trig/hyperbolic head and
  arguments `c x`. It now takes:
  - exponentials `E^(a x + b)` alone: `x E^(2 x)/(1 + E^x) -> E^x (x - 1) - x^2/2 -
    x Log[1 + E^-x] + PolyLog[2, -E^-x]`;
  - affine arguments: `x^2 Tanh[1 + x]^2` and `I x^2 Tan[1 + x]^2` are integrated in
    `y = 1 + x` (with the shift kept as `E^b` factors the roots came out as
    `Sqrt[-E^(-2 I)]`, whose branches did not verify).

  Seven definite integrals over these shapes, across `x = 0`, agree with `NIntegrate` to 30
  digits.

- **The exponential-only route answers the user's integrand only** (cascade depth 1).
  Through a substitution `x = E^u`, a non-elementary piece of an elementary integrand
  took a dilog answer. Linearity then closed `prim-elem-3` with uncombined cancelling
  PolyLogs, and `Integrate[Log[t]/(1 + t^2)^3, {t, 0, 1}]` got a `PolyLog[2, I/t]` form
  whose limit failed. Both regressions were caught by the unit suite and 259, and both
  are fixed.
- **`LogByParts` accepts on `PossibleZeroQ`** when `Simplify` leaves the residual
  uncombined (Cosh/Sinh beside `E^x`): `Log[1 + E^x] Tanh[x]^2` closes in 0.1 s.
- **`DerivativeDivides` writes `ArcTan[Tan[u]]`, `ArcTanh[Tanh[u]]`, `ArcTanh[Coth[u]]`,
  ... back as `u`.** Each has derivative `u'`, so the antiderivative changes by a locally
  constant amount only. `Integrate[Tan[x]^2, x]` was `-ArcTan[Tan[x]] + Tan[x]`, a
  sawtooth with a jump at every `Pi/2 + k Pi`; it is now `-x + Tan[x]`.

Closed of the 18: 10 (the 5 above, the 2 ladders, `I x^2 Tan[1 + x]^2`,
`x E^(5 x/2)/(1 + E^x)`, `Log[1 + E^x] Tanh[x]^2`). Still open: Ei/erf of a `Tanh` argument
(`E^Tanh[x^2] x`), a log times a trig kernel whose by-parts `V` is itself a log
(`Log[I + Tan[1 + x]] Tan[1 + x]`, `x Log[Tan[x]] Tan[x] Sec[x]^2`, `Log[Tan[x]/x]`),
`Tanh[x^2]` (not affine), and `Log[1 + x]/(1 + Coth[x])` (an Ei of an affine log).

Six of seven integrands FriCAS decides and `Risch`ElementaryIntegralQ` did not:

|---|---|---|
| gauss-elem-27 | undecided, 0.6 s | True, 0.03 s |
| gauss-elem-19 | undecided | True, 0.05 s |
| gauss-elem-23 | timeout | True, 0.2 s |

- **The Q-span over Q(i)** (`risch_rational_span`). Matching coefficients over C(vars)

## Bronstein: a free square root splits f into its Galois components (Campaign D2, v0.6648)

Suppose a square root `Sqrt[b]` occurs in f only outside every logarithm, exponential and
other radical, and is independent of the other radicals. Then `y -> -y` is a differential
automorphism over the field generated by everything else, and theorem E8 applies over that
field: its proof never used that the base was a tower over Q(x). So f is elementary iff
`(f + σf)/2` (free of y) and `(f - σf)/2` both are, and each has one radical fewer.

- The Bronstein front end tries this split when the support groups (D1) leave two
  non-elementary groups or an undecided group.
- Guards: Kummer independence of all the radicals, every x-dependent exponent on `E`,
  and no exponent carrying a logarithm. These keep b a non-square in that field (§E9).

Results:
- Benchmark 260 decided: 81% -> 90% (377 of 420; FriCAS 95%). `pert-nonelem`
  (non-elementary by construction) 38 -> 60 of 60; `two-rand` 39 -> 53.
- 256 class B: 167 -> 168 of 169.
- A stress of 300 elementary-by-construction integrands from 260's `two` and `mid`
  generators (new seeds): 221 answered and verified, 78 undecided, no false certificate.

What is left in class B is Phase 5 (D3): a radical inside a kernel with further monomials
above it.

## Bronstein: support groups; held Integrate messages respect Quiet; benchmark 260 (Campaign D0, D1, v0.6647)

**Support groups (D1).** 47 class-B integrands of benchmark 256 were undecided by every
Mathilda method. 46 of them stopped at one restriction of the tower builder: a radical
inside a logarithm or exponential may only be the first monomial (Phase 5). Most are a
sum of pieces over different radicals, and each piece alone is decided. The Bronstein
front end now groups the terms of `Expand[f]`:
- first by the radicals they contain, at any depth;
- then, if a group is undecided, by their `Log`/`Exp` kernels.

Each group is integrated on its own.
- Every group elementary: the verified sum.
- One group certified, the others elementary: f is not elementary (linearity, theory note §E9).
- Two or more non-elementary groups: `Integrate::incomplete` (*several non-elementary
  support groups*), since that case needs a separation lemma not yet proved (D2).

On the 47: 39 decided (all certificates), 6 with two non-elementary groups, 2 still Phase 5.

**Held messages under Quiet.** `Integrate::nonelem` and `Integrate::incomplete` are held
until a cascade ends, so a later stage can still answer. A message raised under a `Quiet`
inside the cascade was held past that `Quiet` and then printed. The case: the Bronstein
code calls `Quiet[Integrate`RischTranscendental[g, u]]` after its genus-0 change of variable.
- `Integrate[Log[x + Sqrt[2 + x^2]]/x, x, Method -> "Bronstein"]` printed the message
  about the internal integrand in `brUf1`, and the de-dup then dropped the message about
  the user's integrand.
- Under the support split a group's held message could disagree with the overall
  verdict, and `Check` would return the wrong branch.

A message raised under a `Quiet` that covers it, entered inside the cascade, is now
emitted at once: silent, and seen only by the `Check`s inside that `Quiet`.
- A `Quiet` around the whole `Integrate` keeps the old behaviour: hold, then drop or flush.
  A first version that ignored where the `Quiet` was entered flushed `Integrate::incomplete`
  early, when a later stage would have dropped it for a certificate. Two suites caught it.
- The funnel gains `mth_msg_quiet_cover(head, tag)` and `mth_msg_quiet_depth()`. The
  cascade records the `Quiet` depth when it starts.

**Benchmark 260 (D0).** A corpus for radicals at the bottom
(`tools/integration_shootout/gen_bottom.m`, `make bench-integrate-bottom`). 420 cases in
seven halves:
- `one`, `mid` and `two` (one radical with kernels over Q(x); one radical also inside
  kernels; two independent radicals), each as `-elem` (`f = D[F]`, F recorded, a "no" is
  false) and `-rand`;
- `pert-nonelem`: a classically non-elementary erfi- or li-type integrand over `Sqrt[x]`,

## Bronstein: several independent square roots, by Galois components (FriCAS comparison C3.2, v0.6645)

An integrand with several square roots whose Kummer group is not cyclic (`Sqrt[x]` beside
`Sqrt[1 + x]`, `Sqrt[1 + x^3]` beside `Sqrt[2 + x^4]`) was "implementation incomplete" in
the Bronstein package. It was the larger of the two class-B gaps against FriCAS: 31
perturbed `bgenus`, `bcurve` and `bbottom` cases, all decided by FriCAS.

When the m square roots are independent (Kummer group of order 2^m), each sign change
`y_i -> -y_i` is a differential automorphism over the base field. The Galois
eigencomponents `f_e = 2^-m Sum chi_e(sigma) sigma(f)` satisfy:
- `f = Sum f_e`;
- each `f_e` is `c_e Prod y_i^e_i` with `c_e` in the base field, so it lies in the field
  of one radical, a cyclic compositum the single-radical front end handles pointwise;
- f has an elementary integral iff every `f_e` has one (theory note §E8).

`brKummerSplit` computes the components without rationalising: the denominator is
multiplied by its conjugates, and `Y_i^2k` is mapped to `b_i^k`. `brKummerSplitIntegrate`
answers with the sum of the components' antiderivatives, or certifies non-elementarity
when one component is certified.

- Benchmark 256 class B, decided out of 169: Bronstein 92 -> 121, Automatic 98 -> 122
  (FriCAS 158). No Bronstein certificate meets a verified FriCAS answer.
- Two pinned "incomplete" cases are now certified (`Sqrt[Log[x]] + Sqrt[Log[x] + 1]`,
  `1/Sqrt[2 x] + Sqrt[x^3 + 1]`).
- Gap log: E8-1, E8-2. Tests: `test_kummer_split`, `test_kummer_components`.

The other class-B cause, a radical inside a logarithm or exponential with further
monomials above it (47 cases), is Phase 5 (C3.1).

## Risch: dependent exponentials read downwards, RootSum of a rational body, Cancel over Q(i) with numeric constants (FriCAS comparison C2, v0.6644)

These come from the uncertain paths behind the transcendental decision's undecided cases
on benchmark 259 (theory note §T19).

- **Dependent exponentials read downwards (C2.1).** The tower orders its levels by
  containment, so `E^(1 + 2 x)` can sit below `E^x`. The relation found at `E^x` then has
  multiplier 1/2, while `E^(1 + 2 x) = E (E^x)^2` has an integer form. When one lower
  exponential has coefficient +-1/m and every other m k_i is an integer, the relation is
  inverted and that level is eliminated. Successive eliminations now compose: an earlier
  rule's value is rewritten structurally when a kernel it holds is eliminated later.
  `E^(1 + 2 I x)/(1 + E^(I x))`, `E^(I + 2 I x)/(1 + E^(I x))` and
  `E^(1 + 2 I x) Tan[x]` are decided.
- **`RootSum[p, R]` with R rational in the root (C2.2).** It is now summed exactly for any
  degree of R's denominator: R is reduced mod p through PolynomialExtendedGCD, then summed
  with Newton's power sums. Before, only a denominator linear in the root was handled.
  The derivative of a Risch log part over `E^(x^2)` is such a sum, and it had stopped
  the exponential top: `x E^(x^2)/(1 + E^(x^2) + E^(3 x^2))` and four elementary
  integrands of benchmark 257 are decided. The body must be plain arithmetic (at most
  400 nodes, p of degree <= 12), because RootSum is re-evaluated whenever the expression
  around it is. Without that gate, Trager's log-term suite went from 9 s to over 120 s.
- **`Cancel` and `Together` over Q(i) with a numeric constant (lower layer).**
  `Cancel[(-E + I E u)/(I + u)]` stayed uncancelled, and so did the same with `Pi` or
  `Log[2]`: the Gaussian field path rejected numeric constants, and its fallback treats I
  as a free variable. This produced a **false certificate** in the first version of C2.1:
  the base Risch DE `q' + I q = E (I u - 1)/(Z^4 (u + I))` has the constant solution
  `E/Z^4`. Numeric constants (constant symbols and `Log` of a rational) are now fresh
  symbols for the reduction. An identity in independent indeterminates holds for every
  value, so this is never wrong. Algebraic numbers are not abstracted (nested-radical
  Together depends on `Sqrt[2]^2 = 2`).

Hunts: no false certificate, no contradiction; Gaussian undecided 18 -> 8, limhunt 7 -> 6.
Benchmark 259: RischTranscendental decides 616 -> 625, Automatic 622 -> 626; no Mathilda
false "no". There are 3 more FriCAS false "no" (`gauss-rand`, e.g. `E^(1 + 2 I x) Tan[x]`)
that Mathilda answers. Tests: `test_fricas_c2_dependent_and_rootsum`,
`test_rootsum_rational_body`, `test_gaussian_numeric_constants`; gap log T19-1, T19-2.

## Integrate: the PolyLog stage's Log-of-a-trig answers hold on every interval (FriCAS comparison C0.1, v0.6642)

`Integrate[I x^2 Log[-I + Tan[2 x]], x]` was wrong past the pole of `Tan[2 x]` at `Pi/4`,
and `Integrate[Log[-I + Tan[2 x]], x]` was off by `2 Pi I` there. This was the one wrong
answer the FriCAS comparison found (benchmark 259, `tani-rand-9`), and it predates the
campaign.

The cause: PolyLogLadder integrates `P(x) Log[G]`, with `G` a trig rational, as
`D Q + INT P L`, where `L = e b x + Sum m Log[1 - T/rho]` (`T = E^(b x)`) and
`D = Log[G] - L` is piecewise constant. The stage replaced `D` by its value at
`x = 37/100`, which gives an antiderivative of that interval only. Its acceptance check
sampled `37/100` and `71/100`, both on the same interval.

- `D` now stays symbolic (`Log[G] - L`), so the antiderivative is correct on every
  interval (`D' = 0` wherever `D` is continuous). This is the standard published form:
  `INT Log[Cos[x]]` keeps `x Log[Cos[x]]`.
- A definite integral computes its antiderivative inside
  `Block[{Integrate`$DefiniteInterval = {a, b}}, ...]` (`integrate_newton_leibniz.c`).
  There the stage replaces `D` by its constant value on `(a, b)`, read at the midpoint
  and checked at 31 points, so the endpoint values stay finite:
  `Integrate[x Log[2 Cos[x]], {x, 0, Pi/2}] = -7/16 Zeta[3]` as before.
- When `D` jumps inside `(a, b)` the stage declines. Before, Newton–Leibniz telescoped
  across the jump, because `Limit` misses it. `Integrate[Log[-I + Tan[x]], {x, 0, 3},
  Method -> "NewtonLeibniz"]` gave `+4.2776 I` where the value is `-4.7024 I`; it is now
  unevaluated.
- The acceptance check samples five points on several intervals (`-17/10` to `39/10`),
  or three inside the interval of a definite integral.

(`test_integrate_polylog.c`).

## Risch: the Risch DE over a split tangent level -- Tanh, and Tan over k(i) (C completeness campaign, step 4, v0.6639)

The Risch DE had no solver for a hyperbolic-tangent level (`RDE: lower field outside the
recursive RDE (hyperbolic tangent)`, `tower: hyperbolic-tangent top`). Over a field
containing `I`, a tangent top was solved, but a "no" there proved nothing
(`tower: hypertangent top over a field containing I`). In both cases the special
polynomial splits: `t^2 - 1`, and `t^2 + 1 = (t - I)(t + I)`. A split special part is an
exponential in disguise (*Symbolic Integration I*, p. 166).

`rde_tower_mobius` (`integrate_risch_rde.c`) changes the variable:
- take `alpha = 1` for Tanh and `alpha = I` for Tan;
- `theta = (alpha + t)/(alpha - t)` has `D theta/theta = 2 alpha Dt/(alpha^2 - t^2)` in
  `k`, so `theta` is the exponential `E^(2 v)` or `E^(-2 I v)`;
- `k(t) = k(theta)`, with `t = alpha (theta - 1)/(theta + 1)`.

The equation is solved by the exponential stack over a copy of the tower whose level is
`theta`, and the answer is mapped back. This is an isomorphism of differential fields
over `k`, so the stack's authoritative "no solution" is one here. The field integrator
now sends a Tanh lower field to the Risch DE, and `Risch`RischDECertified` recognises the
hyperbolic kernels.

- `RischDECertified[1 - Tanh[x]^2, 1, x]` and `RischDECertified[1, Tanh[x], x]` are now
  `"NoSolution"`. The solutions need `E^(-Tanh[x]) Integrate[E^Tanh[x]]`, and `E^x`, the
  square root of `theta`; neither is in the field.
- `RischDECertified[I, Tan[x], x]` is `"NoSolution"`: the solution needs `E^(I x)`.
- A new hunt, `tools/bronstein_hunts/rdetanhunt.m`, takes `y` random in a Tanh or
  `Tan`-over-`Q(i)` tower and gives `g = D[y] + f y` (240 cases).
  - Over Tanh: 9 -> 120 solved. Over `Q(i)`: 112 -> 120 solved.
  - No false "NoSolution", and no wrong answer.
- Every other hunt is unchanged, with no false certificate; the Tanh hunt has one more
  True.

## Risch: Gaussian exponent offsets over k(i) -- `E^(I (1 + u))` beside `E^(I u)` (C completeness campaign, step 4, v0.6638)

v0.6633 made a dependent exponential a tower member when its offset `c` is an integer.
Over `k(i)` the offset is Gaussian: `TrigToExp[Tan[1 + u]]` brings `E^(I (1 + u))`, and
`E^(I (1 + u)) = E^I E^(I u)`.
- **A symbol for `E^I`.** `E^(a + b I)` is now `E^a Z^b`, with `Z` the symbol
  ``Risch`Private`rtEI``. By Lindemann-Weierstrass, `E` and `E^I` are algebraically
  independent (`1` and `I` are linearly independent over `Q`), so `Z` is a parameter, and
  powers are exact polynomial arithmetic. Left as atoms, `E^I` and `E^(2 I)` are unrelated
  to `Together`.
- **Every spelling of a constant maps to that symbol.** The tower substitution maps any
  `E^w` with `w` constant and equal to `a + b I` to `E^a Z^b`. Constant means `D[w] = 0`,
  not only x-free: `TrigToExp` spells `E^(-I)` as `E^(I u - I (1 + u))`. The collector no
  longer makes such an exponential a level. While this was being written it did, and that
  level of derivative 0 sat beside `Z` as an independent constant. Their relation went
  unseen, and the decision certified the elementary `E^(I u) Tan[1 + u]` non-elementary.
  The hunt below covers that spelling. Any other constant `E^c` in the integrand (`E^(1/2)`)
  stops the rebuild.
- **Answers come back with `Z -> E^I`.** One helper, `rt_tower_back_rules`, writes every
  tower answer back to the kernels; six call sites built that rule list by hand.

`E^(I u) Tan[1 + u]` and `E^(I u)/(1 + E^(I (1 + u)))` are now `True`; `E^(I (1 + u))/u +
E^(I u)` and `E^I E^(I u)/(u + I)` are `False` (`E^I` times an Ei).

A new hunt, `tools/bronstein_hunts/gausshunt.m`, mixes shifted complex exponentials,
shifted tangents, literal `E^I`-type constants and constants spelled with `u`. Results
against v0.6633:
- seeded (160 cases): 123 -> 131 True; undecided 24 -> 9; timeouts 13 -> 20;
- random (80): True 26 -> 32, False 34 -> 37, undecided 20 -> 11;
- no false certificate and no contradiction.

The hunt's contradiction check counts only an elementary antiderivative. An Ei answer is
the non-elementary form a `False` asserts.

## LinkedList: Compile[] lowering and auto-compiled loops (phase 5, v0.6634)

LinkedLists now compile, and an interpreted `Do`, `While` or `For` over a global list
runs compiled. `ll = LinkedList[]; Do[AppendTo[ll, N[i]], {i, 10^6}]` takes 37 ms,
against about 0.5 s interpreted.

- **Type.** `CT_LLIST + elem` (44..47). A list register holds the `EXPR_LINKEDLIST`
  node: owned in the array bank, borrowed in an argument register.
  `CompileDiagnostics` reports `ResultType -> "LinkedList"`.
- **Sources:**
  - `Module[{b = LinkedList[]}, …]` and `LinkedList[arr]` locals;
  - `{b, _LinkedList}` and `{b, _LinkedList, _Integer|_Real|_Complex}` arguments,
    which are the caller's own list, mutated in place;

- **Lowered heads:**
  - mutating: `AppendTo`, `PrependTo`, `Push`, `Pop`, `PopFirst`, `b[[i]] = v`;

## Risch: a dependent exponential is a member of the tower, not a level -- `E^Tanh[u]` is decided (C completeness campaign, step 4, v0.6633)

`Risch`ElementaryIntegralQ[E^Tanh[u], u]` stayed undecided. `TrigToExp` writes
`E^Tanh[u]` as `E^(E^u/(E^-u + E^u)) E^(-1/(E^u (E^-u + E^u)))`. With `s = E^(2 u)` the
two exponents are `1 - 1/(1 + s)` and `-1/(1 + s)`: they differ by exactly 1. The two
exponentials are therefore not independent monomials, and the structure theorem said so.
The tower builder's commensurability classes catch only rational multiples (`E^(2 u)` of
`E^u`), so both became levels. Every "no" over such a tower was demoted to undecided
(`decide: dependent monomials`). `Tanh[1 + u]` has the same problem in a plainer form:
`E^(2 + 2 u)` beside `E^u`.

`rt_dependent_exp_rule` (`risch_tower.c`) now handles it the way campaign step 8 handles
a dependent logarithm:
- The structure theorem gives `w' = Sum k_j Dcoef_j` over the lower levels.
- When every `k_j` is an integer, and `c = w - Sum k_j w_j` (read exactly in the tower
  variables) is an integer, `E^w = E^c Prod t_j^(k_j)` is no new monomial.
- The tower is rebuilt with `E^w` as a member of that value.

The rule uses the integrand's own spelling of `E^w`, so that the rebuild excludes and maps
the kernel that actually occurs. A non-integer `c` is left alone: rational arithmetic does
not see the relations between `E^(1/2)` and `E^(1/3)`. So is `E` beside `Pi`, since their
algebraic independence is open; the rebuild already stops when a second transcendental
constant would enter.

- `E^Tanh[u]`, `E^Tanh[1 + u]` and `E^(2 + 2 u)/u + E^u` are now `False` (non-elementary).
- `E^u Tanh[1 + u]` is `True`: `E^u - (2/E) ArcTan[E^(1 + u)]`.
- Tanh hunt, random half: 5 undecided -> 1. Seeded half: 1 undecided fewer. f12: 2 more
  True. No false certificate in any hunt; the other hunts are unchanged. Two f9 and f8
  seeds lost cases to timeouts, but a re-run with and without the rule showed identical
  timeout sets.
- Still open over `k(i)`: `E^(I u) Tan[1 + u]` needs the offset `I`. `E^I` and `E^(2 I)`
  are unrelated atoms to `Together`, so a "no" there would prove nothing.

Test: `test_campaign_step4_dependent_exp`.
## LinkedList: the copying heads, natively on the chunks (phase 4, v0.6632)

A head that gives a List for a List now gives a **new LinkedList** for a LinkedList,
and leaves its argument unchanged: `Take`, `Drop`, `Most`, `Rest`, `Reverse`, `Append`,
`Prepend`, `Join`, `Insert`, `Delete`, `ReplacePart`, `Map`, `Select`, and every

- **`ReplacePart`** now has a docstring and is `Protected`, as its spec page already

## LinkedList, Push, Pop, PopFirst: a mutable list object -- storage, constructor, stack and queue (v0.6625)

Phase 1 of `LINKED_LIST_DESIGN.md`.

- **New atom type `EXPR_LINKEDLIST`.** A reference-counted, *mutable* payload
  (`src/linkedlist.{c,h}`): assignment and argument passing share one list.
  `expr_eq`/`expr_hash`/`expr_compare` use the payload's stable id, so a
  mutation never makes a cached hash stale; `Head` is `LinkedList`, `AtomQ` is
  `True`, `_LinkedList` matches, and it prints as `LinkedList[<n>]`.
- **Storage.** A deque of two runs of doubling chunks, each run randomly
  addressable through a chunk directory: append, prepend, pop at either end,
  index and set are all `O(1)`, and elements never move on growth. A queue's
  dead prefix is reclaimed by an amortised rebase, so memory stays `O(live)`
  (10^6 push/pop pairs on a 10-element queue hold under 4 KB). All-machine
  integer, real or complex contents are stored raw; the first other element
  converts the list once.
- **`LinkedList[]`, `LinkedList[list]`, `LinkedList[ll]`.** The constructor takes
  a List, packed array or NDArray (packed buffers are memcpy'd: on the `AWARE`
  and `INT64_OK` lists, so `LinkedList[Range[10^6]]` costs ~8 ms including
  `Range`, not the 120 ms an unpacking gate cost), or a LinkedList to copy.
  `LinkedList::list` for anything else. `Normal[ll]` (packed when typed) and
  `Length[ll]` (`O(1)`) accept it.

  push at the back, pop the last or first element, all `O(1)` and in place. A

  evaluation clock (`eval_clock_tick`, which leaves the INERT and GROUND epochs
  alone); and a pure builtin called with a LinkedList argument taints its
  dependency frame, since its answer can change with no binding changing.

## Together: a numeric radical in a denominator is a unit -- sums with algebraic-constant denominators combine (v0.6624)

- **The bug.** `Together[b/(Sqrt[2] + 2 u) + a/(1 + Sqrt[2] u)]` came back as its
  input. `PolynomialLCM` of the denominators is `Sqrt[2] + 2 u`, and the strict
  divide-back in `together_recursive` (`src/rat.c`) needs
  `(Sqrt[2] + 2 u)/(1 + Sqrt[2] u)`, whose leading-coefficient step divides `2` by
  `Sqrt[2]`. `exact_poly_div`'s coefficient-ring base case (`src/poly/poly.c`)
  accepted only a rational, Gaussian or `AlgebraicNumber` divisor, so it failed, and
  `together_recursive` reassembled the sum. Every shape whose denominators share a
  factor up to a numeric algebraic unit failed this way, with or without symbolic
  numerators: `1/(Sqrt[2] + 2 u) + 1/(1 + Sqrt[2] u)`, `x (1/(1 + Sqrt[2] t) + 1/(1 - t))`.
- **The fix.** A numeric radical divisor (`Sqrt[2]`, `1 + Sqrt[2]`, `2^(1/3)`) is now a
  unit there. Its inverse is computed from its minimal polynomial (qqbar),
  `1/B = -(c1 + c2 B + ... + cn B^(n-1))/c0`, expanded into the radical basis, and
  certified by `B (1/B) == 1` before use. So the quotient is performed, not asserted. A
  symbolic radical (`Sqrt[c]`) still declines. So do `Root` and `AlgebraicNumber`
  (their own paths) and a nested radical (`Sqrt[3/4 - 1/Sqrt[2]]`, which the
  evaluator's radical products respell). The unit is off inside a Together/Cancel of an
  expression that has a nested radical, and in the exact linear-algebra divider
  (`src/linalg/util.c`). There, a rationalised `1/(a + b Sqrt[d])` cancels
  catastrophically under machine `N`: an exact SVD lost 3 digits. Those keep their old
  results.
- **A gcd's spurious unit.** The classical PRS gcd over `Q(Sqrt[2])` can carry a
  radical unit (`(1 - Sqrt[2]) (1 + u)`). That was harmless while the divide-back
  failed. Now it is removed in `poly_gcd_internal`: the gcd is rescaled by its leading
  or trailing coefficient when that makes it rational, or to trailing coefficient 1
  when neither end is rational. `PolynomialLCM[1 + u, 1 + Sqrt[2] u, 1 + 2 u + u^2,
  1 + 2 Sqrt[2] u + 2 u^2]` is the least `(1 + Sqrt[2] u)^2 (1 + 2 u + u^2)`, where it
  was the product of all four.
- **Risch.** The F9 hunt's `decide: integrand not rational in the tower` mark is gone
  from the undecided cases. It covered 54 of them: 27 alone, 15 + 12 with other marks.
  f9hunt2 undecided goes from 91 to 44, and True from 357 to 400 over the three seeds.
  There are 0 false certificates in every seeded hunt. hunt, hunt2, f12hunt, dephunt
  and primhunt are unchanged. f8hunt reported more timeouts in the batch runs (seeds
  802/803: 1 -> 5-6). Re-timed case by case on an idle machine, base and fix behave
  identically there (the same cases time out at 30 s in both), so this is load, not
  the change.
- **Printed forms.** `Cancel[(x^2 - 2 y^2)/(x - Sqrt[2] y)]` is `x + Sqrt[2] y`, as the
  univariate case already was. `Together[x/Sqrt[2] + y/Sqrt[3]]` is
  `(Sqrt[3] x + Sqrt[2] y)/Sqrt[6]` (it was uncombined).
  `Together[a/Sqrt[2] + b/(2 Sqrt[2])]` is `1/4 (2 Sqrt[2] a + Sqrt[2] b)` (it was
  uncombined). An exact `SingularValueDecomposition` of a rank-deficient integer matrix

## Risch: the parametric Risch DE, `Risch`ParametricRischDE` (C completeness campaign, step 3a, v0.6620)

- New: `Risch`ParametricRischDE[f, {g0, g1, ..., gm}, x]` solves
  `D[y] + f y == g0 + c1 g1 + ... + cm gm` for `y` and the constants `c_i` together
  (Bronstein [SI] ch. 7). It returns `{y, {c1, ...}}`, `"NoSolution"` (proved) or
  `$Failed` (undecided, with a reason). Examples: `{E^x/x, E^x/x^2}` gives
  `{E^x/x, {-1}}`, and `{1/Log[x], 1/x}` is `"NoSolution"`. It is the core that
  LimitedIntegrate over a Liouvillian primitive top (step 3b) needs, and that the
  generalised new-log certificate (step 2) and a C LimitedIntegrate (step 9) will reuse.
- Method: the ordinary C solver runs with the `c_i` as named constants in the
  right-hand side. The operator side never contains them, and no step divides by a
  right-hand-side quantity, so every bound (degree, valuation, normal denominator) is
  valid for every value of the constants. Each right-hand-side "no solution" exit drops
  its part and continues. The identity gate records the residual, linear in the `c_i`,
  as a constraint, and the constraints are solved at the end. An inconsistent system,
  or a failure at an exit free of the constants, is a proof.
- The cancellation case, which ordinary mode integrates in `K`, runs a linear
  top-down pass:
  - exponential tops decouple by degree;
  - primitive tops carry a fresh unknown `λ` times the homogeneous solution down the
    degrees, which is LimitedIntegrate.

  and an undecided log-derivative test on the pass.

## Overflow[] and Underflow[] are numbers: NumericQ, order, comparisons (v0.6618)

As in the reference, where each is a `Real`:

- **Predicates.** `NumericQ`, `NumberQ` and `InexactNumberQ` are `True` for both;
  `MachineNumberQ` and `ExactNumberQ` stay `False`.
- **Order.** They sort among the numbers by value: `Underflow[]` is a positive
  number below every positive number, `-Underflow[]` the negative one just below
  `0`, and `Overflow[]` follows every finite number. So `x + Overflow[]` is
  `Overflow[] + x`, and
  `Sort[{x, Overflow[], 2, Underflow[], -Underflow[], 0, -1}]` is
  `{-1, -Underflow[], 0, Underflow[], 2, Overflow[], x}`.
- **Comparisons.** `+-Underflow[]` is nonzero, with a sign:
  - `Underflow[] == 0` is `False`;
  - `Underflow[] > 0` and `Underflow[] < 1/10^400` are `True`;
  - `Positive[Underflow[]]` and `Negative[-Underflow[]]` are `True`;
  - `Sign[-Underflow[]]` is `-1`.

  `Overflow[]` has no sign: it is unequal to every finite number
  (`Overflow[] == 1` is `False`), but `Overflow[] > 1`, `Positive[Overflow[]]` and
  `Sign[Overflow[]]` stay unevaluated. Making `NumericQ` True without this would
  have numericalised `Underflow[]` to `0.` inside the comparisons, so
  `Underflow[] == 0` would have been `True`.
- **Functions.**
  - `Abs[Overflow[]]` is `Overflow[]`.
  - `Chop[+-Underflow[]]` is `0`.
  - `b^Underflow[]` is `1 + Underflow[]` for an exact positive `b` with
    `Log[b] > 0`, and `1 - Underflow[]` when `Log[b] < 0`. So `Exp[Underflow[]]` is
    `1 + Underflow[]`, as in the reference, and a positive machine `b` gives `1.`.
  - `b^Overflow[]` and `Exp[Overflow[]]` stay unevaluated. `Overflow[]` may stand
    for `-Exp[10.^10]`, whose exponential is below the range, not past it.

## Every buffer and compiled kernel lane is checked against the machine range by default (numeric-tower review G5, G6, v0.6612)

- **The bug.** The scalar path recomputes a degenerate machine result in MPFR:
  non-finite, subnormal, or `0.` from a nonzero argument. The packed, NDArray
  and Compile surfaces applied that check only to an opt-in list of nine
  "decaying" heads, and to no binary kernel at all. So every other head
  flushed or leaked silently:
  - `FresnelS[{-1.*^-200, 0.5}]` was `{0., ...}`;

  - packed `ArcTanh[{1.*^308}]` leaked a subnormal real part;

    treated as safe;
  - compiled `Csch`, `Sech` and `Erfc` at `+-1.*^308` were `0.`.
- **The fix.** The check is now the default, with two opt-outs, each a claim
  about the function:
  - `ND_LANE_NONE`: proven unable to leave the machine range (`Sin`, `Log`,

  - `ND_LANE_RANGE`: an exact zero is a value (`Mod`, `Log[b, 1.]`,

## Compile: a `_Real` argument with no machine representation goes to the interpreter (numeric-tower review E12, v0.6610)

Found by the Phase 8 `check-machine-boundary` gate, still in development.

- **The bug.** `Compile[{{x, _Real}, {y, _Real}}, x^y][0.5, 10^400]` was `0.`;

## Risch: dependent logarithms eliminated from the tower, with an exact constant (v0.6609)

Step 8 of the C completeness campaign.

## Risch: logarithms in tower variables folded by the structure theorem; integrals in the field decided three ways (v0.6605)

## Underflow[], demotion back to machine numbers, and machine printing (numeric-tower review phase 6) (v0.6604)

These are the policy items decided on 2026-11-17.

## Machine quotients are rounded once; machine complex `Sqrt` is `csqrt` (numeric-tower review phase 4c, K1 and K2) (v0.6600)

Two bugs from the Kahan-style corpus (`tests/test_numeric_kahan.c`).
- **K1: `a/b` was rounded twice.** It parses to `Times[a, Power[b, -1]]`. The reciprocal
  was rounded, then the product, so `-0.3/0.1` was `-3.0` instead of the correctly rounded
  `-2.9999999999999996`. `(1.*^16 + 1.)/3.` and `1.*^-10/7.` were off by one ulp, and
  `x/x` was not `1.` at `x = 1.*^-300`.
  - **Fix.** Times evaluates the base of a `Power[b, -1]` argument first. A machine divisor
    (a Real, a machine Complex, a float64/complex64 buffer, or a List of these) meets the
    machine numerator to its left as `Divide[a, b]`: one division per element.
    Several divisors are multiplied first: `a/b/c` is `Divide[a, b c]`. That is the same
    two roundings as a left fold, but it does not depend on the order of the divisors
    (Times is Orderless). A left fold broke the exact symmetry of `Correlation`'s
    `c/(s_i s_j)` matrix. Symbolic quotients and `(1/b) a` are unchanged.
  - **The other surfaces now agree.** `Divide` gained a machine complex branch
    (`mth_cdiv_machine`, C99 complex division, the operation `Compile` already used) and a
    buffer kernel (`ndarray_divide`: parallel, vectorised, with the lane test, and delisting
    on division by zero or under/overflow). `Compile` emits a true divide for `x/y`, for
    scalars and for real or complex arrays. So `0.3/0.1`, `{0.3}/0.1`, the packed and
    NDArray forms, and the compiled form are the same double.
    `(1. + 2. I)/(3. + 4. I)` is `0.44 + 0.08 I` (it was `0.07999999999999999`).
  - **Cost.** A packed `v/2.5` is a vector divide, not a multiply: 2.2 ms against 1.8 ms
    for 10^6 elements. That is the cost of a correctly rounded quotient (NumPy pays it too).
    Symbolic and exact division are unchanged within noise.
- **K2: machine complex `Sqrt`** went through `cpow`, i.e. `exp(log(z)/2)`, which lost
  about 220 ulps at `|z| ~ 10^+-200`. It is now libm `csqrt` on the scalar path, in the
  buffer power kernel and in `Compile` (`SQRT_C` already called it), so all three agree bit
  for bit.
- **S2** (`Exp[I Pi 1.] == -1` is `False`, because complex `Equal` compares parts
  separately) is accepted as it is.
- **Corpus.** 321 cases, 0 expected failures. It gains cross-surface quotient and `Sqrt`
  cases.

## $MinPrecision and $MaxPrecision (v0.6597)

arbitrary-precision number. They default to `0` and `Infinity`, are settable,
work under `Block`, and have docstrings. Spec:
`docs/spec/builtins/expression-information.md`.

- **Assignment** is validated (min a real `>= 0`, max a positive real or
  `Infinity`, min `<=` max). An invalid value gives `::precset` and the old
  value is kept.
- `$MaxExtraPrecision` has a docstring too.

  generated by `tools/numeric_tower_stress_cases.py`).

## Risch over symbolic parameters: identities solved over Q(params); a v0.6590 false certificate fixed (v0.6591)

- **A false certificate, introduced in v0.6590 and now fixed.**
  `Risch`ElementaryIntegralQ[D[a ArcTan[u] Log[1 + u]^2 - 2 u Log[1 + u]^3 + Log[1 + a u] Log[a + u^2], u], u]`
  was `False`, but the integrand is a derivative. Reproduced on a v0.6590 build; it is now
  `True`.
  - **Cause.** v0.6589's `rt_solve_always_params` made the integrand's parameters
    `SolveAlways` variables. The unknowns of these identities (residues, log coefficients,
    the fold's `c_k`) are constants of the derivation, and so are the parameters, so a
    solution may depend on them (`c = a` beside `a Log[1 + u]`, `c = 1/a` beside
    `Log[1 + a u]`). With the parameters as variables, `{}` only meant "no solution
    independent of a". The v0.6590 new-logarithm certificate read it as a proof. The v0.6589
    sites decline on failure, so they lost answers but gave none wrong.
  - **Fix.** With parameters present, the identity's coefficients in the tower variables
    are taken (`CoefficientList`) and solved for the unknowns only (`Solve`), with the
    parameters left as parameters. Solutions are generic in them, and `{}` means
    inconsistent for generic values: the E4.4 semantics of every parametric verdict.
    Without parameters this is plain `SolveAlways`, as before.
- **New-logarithm certificate.** The parameter scan reads the system (`A'`, `t_k'`), not
  `A`, so `Log[u]/(u + a)` and `Log[u]^2/(u + a)` get generic certificates. `Log[u]/(u + Sqrt[a])`
  stays undecided, which is conservative.
- **Checks.** No false certificate on 80 seeded parametric random towers or 100 numeric ones;
  `a Log[u] Log[1 + u]`, `a ArcTan[u]^2` and `Log[u] Log[u + a]` are True. The Risch suite
  gains the reproducer and a seeded parametric property test.
- Still open: `Log[a + u]/u` is undecided, with no mark, unlike `Log[2 + u]/u` (fixed in
  v0.6592: the cause was a parameter that appears only inside a tower kernel).

## Equality soundness: `22/7 == Pi` was True (v0.6584)

- **`22/7 == Pi` was `True`, and so was `22/7 != Pi`.** A sweep of
  continued-fraction convergents of 22 constants found 263 of 550 rational
  approximations judged equal to the constant, or ordered both ways or neither
  way. The false answers spread to `If`, `TrueQ`, `Max`, chains, complex
  equality, and to `Simplify[Pi == 22/7]` (`True`) and
  `Reduce[x == Pi && x == 22/7, x]` (`x == Pi`). There were three causes.
  - **PossibleZeroQ called a steady residual a zero.** `22/7 - Pi` sits
    2^-12.25 of scale, just under the machine "obviously non-zero" gate, so it
    climbs the precision ladder. A genuine value never shrinks, and the
    "never shrank" branch returned the lenient zero for every non-algebraic
    expression.
    - Now a rung whose value honoured its precision keeps climbing, and the top
      rung's floor decides. Only a rung whose head ignored the requested
      precision is still lenient. `pinned` now also flags an MPFR leaf far short
      of the rung.
    - A plateau on low rungs alone is not evidence, which keeps the |x| ~ 60
      Tanh identities true.
    - The deep-zero early exit now needs the residual below the floor of the
      rung that saw the shrink: `E^Pi - r` at 8.6 10^-29 had "shrunk" from
      machine noise to its true value.
    - A constant with an exact term below the ladder's reach
      (`I (Pi + 10^-400) - I Pi`) is read once at the precision that keeps it.
  - **Equal let the zero test override a clear inequality; Unequal did not.**
    Both now read every pair through one verdict, `equal_pair_decide`. An order
    reached exactly, or by the tolerance, is final. Only an order of exact
    operands read off doubles is confirmed by the zero test.
  - **The order of exact quantities.** `cmp_exact_order` now:
    - tries the exact difference first (`Pi + 10^-400 - Pi` is `10^-400`;
      `Pi + Exp[-Exp[10]] - Pi` is Plus-free);
    - measures MPFR resolution against the operands' structural magnitude;
    - returns "unresolved" instead of "equal".

    Doubles may decide only between operands that contain no `Plus`. Before,
    `Sign[PolyLog[2, 1/3] - 2006534954/5479143815]` was `-1` for a value of
    +6.9 10^-21. The ordering heads no longer let the zero test overrule an
    MPFR-resolved order: `Pi < r` and `Pi > r` had both been `False`.
- **``Internal`$EqualTolerance`` and ``Internal`$SameQTolerance``** are now
  real, `Block`-able variables (defaults 2.10721 and 0.30103 digits, that is 7
  bits and 1 bit).
  - The machine rule lives in `src/equal_tol.h` and replaces the hand-copied
    2^-46 in `comparisons.c`, `numloop.c` and `sparse_reduce.c`.
  - The compiled VM's real comparisons use it too, read at call time:
    `Compile[{x, y}, x == y][1., 1. + 2^-50]` is `True` and the matching `<` is
    `False`, as in the reference. Real comparisons are no longer
    constant-folded.
  - SameQ ignores its last bit, leaf-wise, at the lower precision:
    `1. === 1. + 2^-52`, `{1.} === {1. + 2^-52}` and ``1`30 === 1`20`` are
    `True`.
  - `DeleteDuplicates` and `Tally` defaults are still exact. This is a known
    gap, documented in `comparisons.md`.
- **Sign / Abs of a real exact constant the FLINT certificate declines**
  (`Zeta[3] - 1`) now take the sign the comparison heads decide. Only a
  nonzero sign is used, so a hidden zero keeps `Abs[...]` unevaluated, as in
  the reference.
- **Structural magnitude recurses** through `Times` and positive rational
  `Power`, and declines on any other head that wraps a sum. Without this,
  `169 (-1 + Sqrt[16 - 6 Sqrt[7]] + Sqrt[11 - 4 Sqrt[7]]) == 0` (a hidden zero
  at x = 7) read `False`, and Reduce lost the `4 <= x <= 9` branch of

- **Crash fixed.** `d = Pi - 22/7; Abs[d] == -d` segfaulted. Abs's negation
  moved the terms out of the refcount-shared argument, which left `d =
  Plus[Null, Null]`.
- **Gate.** `make check-equality` (`tools/check_equality_soundness.m`) runs 814

## DSolve: implicit IVPs over a y-integral that does not close; qqbar memos released at exit (v0.6583)

- **`DSolve[{y'[x] == Log[1 + y[x]^2], y[0] == 1}, y, x]` returned junk:**
  `Integrate[Log[5]/Log[1 + y[x]^2], y[x]] - x Log[5] == Integrate[Log[5]/Log[2], 1]`.
  There were two defects.
  - The y-side quadrature had stayed an *active*, unevaluated `Integrate[f, y[x]]`.
    The point-condition fit replaced `y[x] -> 1` everywhere, including the
    integration-variable slot. The rewrite to the definite form only recognised
    `Inactive[Integrate]`. Now, before the fit, such a node is turned into its inert
    twin, which is the same value, so the existing definite-form path applies and
    re-verifies through the Leibniz rule. The answer is now
    `Inactive[Integrate][1/Log[1 + t^2], {t, 1, y[x]}] - x == 0`.

    on both sides, so an autonomous `F(y)` fell through to the sampled split and
    took `g = F(x, 2)`. An empty side is now `1`, and the general solution is
    `Integrate[1/Log[1 + y[x]^2], y[x]] - x == C[1]`.

  were reachable cache entries.** `flint_qqbar.c` memoises qqbar values, Root forms,
  sorted roots and generator minimal polynomials in static tables, and nothing
  freed them at exit. Their fmpz bigints are referenced only through FLINT's
  tagged pointers, which `leaks` and valgrind cannot follow, so each entry showed
  up as an orphaned mpz page plus its limbs. Repeating the same call left the

  what showed it was a cache. `flint_bridge`'s exit handler now calls

## Bare names resolve to an existing Global` symbol at Global`'s position on $ContextPath (v0.6581)

### MatrixExp of an arbitrary-precision SparseArray: the reference's actual head rule

## Integrate: Chebyshev binomials whose base is a binomial only after expansion; Solve's nested-radical elimination

**Integrate`ChebychevAlgebraic.** The recogniser required the radicand to be
literally `a x^r + b`, so `Integrate[-1/Sqrt[2 c2 y^(5/2) + 4 c3 y^3], y]` (DSolve
2.1.2-267) stayed inert even though it is `y^(-5/4) (2 c2 + 4 c3 y^(1/2))^(-1/2)`,
elementary by Chebyshev (`(m+1)/n + p = -1`). The numeric-coefficient twin only
closed by another stage. A base that `Expand`s to monomials of exactly two exponents
`s < s + r` is now normalised to `x^(p + s q) (a x^r + b)^q`, times the locally
constant `W = base^q / (x^(s q) (a x^r + b)^q)`, which is kept rather than dropped:
it is `-1` for `x < 0` in `Sqrt[x^3 B]` and a phase off the real line. `W`'s `B^q`
cancels against the back-substituted antiderivative, so the answer is `base^q` times
a rational function of `x^(1/N)`:
`Integrate[1/Sqrt[x^(5/2) + x^3], x] = -4 (1 + Sqrt[x]) x/Sqrt[x^(5/2) + x^3]`.
The generalised recogniser (`integrate_chebychev_general_try`) runs in a second
cascade slot after DerivativeDivides. DerivativeDivides closes some of these shapes
in the integrand's own radical (`Sqrt[x + Sqrt[x]]`), and the first slot, which still
runs ahead of it, keeps the strict recogniser. `Method -> "ChebychevAlgebraic"` and
``Integrate`ChebychevAlgebraic`` use the generalised form directly.

**DSolve`AutonomousReduction.** A stage-2 quadrature with a `y`-denominator radical is
guarded off the Integrate cascade, as one that may spin. The guarded branch now also
tries the Chebyshev stage, which is a structural match plus one rational quadrature
and so cannot spin, with a differentiate-back check, the way it already tried the
elliptic-trig recogniser. 2.1.2-1168 (`y^2 y''' == y'^3`) now returns a closed
first integral instead of `Inactive[Integrate]`, and so does 2.1.2-267.

**Solve (radicals).** The resultant chain eliminated each generator `u_i` from the
main polynomial only. A later side equation can carry an earlier generator: in
`Sqrt[2 x^(5/2) + 4 x^3]`, `x^(1/2) -> u_0` comes first, which leaves
`u_1^2 - 2 u_0^5 - 4 x^3`. Eliminating `u_1` then re-introduced `u_0`, and the
internal `$radu0$` placeholder leaked into the `Root[]` answers.
`u_i` is now eliminated from the side equations still to come as well:
`Solve[Sqrt[2 x^(5/2) + 4 x^3] == x + x^(3/2), x]` gives `{{x -> 0}, {x -> 1/3}}`.

### The random seed stack survives a timeout (v0.6662)

`bronstein_stress` failed intermittently on a loaded machine: one seed's whole
batch went missing (`OK=2, CRASH=18`), a different seed each run, never
reproducible in isolation. The crash report was a `SIGABRT` in `free` under
`random_pop_seed`, called from PossibleZeroQ's Schwartz-Zippel sampler.

`random_pop_seed` cleared the live GMP random state and rebuilt it with
`gmp_randinit_set`. That allocation is a TimeConstrained safe point, so a
timeout landing there jumped out with the state cleared and half rebuilt, and
the saved slot not yet released; the next clear freed the same buffers twice.
The pop now moves the saved state into place by struct copy and only then frees
the displaced one: it never allocates, and a free is never a safe point. The
stack depth is also registered as a TimeConstrained unwind counter, so a
timeout between a push and its pop no longer leaves it one deeper for the rest
of the session (after four, pushes stopped saving and the sampler perturbed the
user's random stream).

A loop of 3000 `TimeConstrained[PossibleZeroQ[...], 10^-4 k]` calls aborted in
3 of 6 runs before the fix and in none after. `random_tests` checks the
invariant directly: with a counting GMP allocator installed, the pop makes no
allocation, and a push/pop pair leaves `RandomInteger` after `SeedRandom`
unchanged.
