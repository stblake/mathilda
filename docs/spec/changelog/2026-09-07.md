## Simplify hang fix (Factor/GCD `pseudo_rem`) + `TimeConstraint` option

`Simplify[(x+Sqrt[u]) u^(-1/2)]` hung. The heuristic search actually finished
instantly (`best = 1 + x/Sqrt[u]`); the hang was downstream, in Simplify's
radical-fraction polish calling `Factor`, which spun forever inside the
multivariate GCD's `pseudo_rem` — an **unguarded `while (true)`**
(`src/poly/poly.c:1479`) that never terminates when `Factor` treats the
algebraically-dependent generators `Sqrt[u]` and `u` as independent (the
pseudo-remainder degree in the main variable never drops). This was latent for
*every* `Factor`/`PolynomialGCD` caller, not just Simplify.

- **Root-cause fix — `pseudo_rem` degree-monotonicity guard** (`src/poly/poly.c`).
  A valid pseudo-division step strictly decreases the degree of `R` in the main
  variable; track `prev_degR` and `break` if it fails to. The guard is inert for
  every well-formed input and trips only on the degenerate radical-generator
  case, handing the non-reduced `R` back to the already-budgeted outer GCD loop
  (`iter_count > 50`). `Factor[1 + x/Sqrt[u]]` now returns instead of hanging.
- **Narrowed Simplify polish gate** (`src/simp/simp_builtins.c`,
  `has_compound_radicand`). The radical-fraction polish only calls `Factor` when
  a radical has a *compound* base it could expose (e.g. `Sqrt[6+x^2]`); bare-symbol
  radicals like `Sqrt[u]` are skipped. The intended
  `Simplify[(Sqrt[6] Sqrt[6+x^2])/(6x+x^3)] → Sqrt[6]/(x Sqrt[6+x^2])` case is
  preserved.
- **New `TimeConstraint` option on `Simplify`** (default `Infinity`). A
  synchronous, **per-sub-expression** wall-clock budget in seconds: when a
  sub-expression's heuristic search exceeds it, the best-so-far form is returned
  (not `$Aborted`). It is checked between search steps in `simp_search`
  (`src/simp/simp_search.c`) against a local deadline armed from a
  dynamically-scoped budget (`simp_set_time_budget`/`simp_current_time_budget`,
  save/restored in `builtin_simplify` — re-entrancy-safe), using a new monotonic
  clock helper `simp_mono_seconds` (`src/simp/simp_util.c`, POSIX-guarded). It
  bails through the normal return path, so it **never leaks** — unlike the async
  `TimeConstrained` mechanism, which it deliberately avoids. It does not
  interrupt a single long-running kernel call (that class is what the `pseudo_rem`
  guard handles). Accepts `t`, `Infinity`, or `{tLoc, ...}` (uses `tLoc`).
  Registered as a default option (visible in `Options[Simplify]`).

Tests: `tests/test_simplify_hang.c` (ctest-registered) — a 24-input

per-case alarm, plus exact-output and `TimeConstraint` option checks. `make

## DSolve M17 — 2nd-order-linear special-function wave (`DSolve`SpecialFunctionForm`)

Two verified increments on the largest §2.1.2 corpus bucket (2nd-order linear),
both emitting heads that numericize (`Hypergeometric2F1`, `BesselJ/Y/I/K`,
`AiryAi/Bi`) so both the in-method numeric self-verify **and** the corpus's numeric
back-substitution are genuine — the 0-FAIL corpus invariant is preserved. All in
`src/calculus/dsolve_specialform.c`; no new method file or cascade edit.

- **Affine + local-exponent reduction to Gauss ₂F₁.** Any rational-coefficient
  hypergeometric-class equation with exactly two finite regular singular points
  `{x1, x2}` (the poles of `P`, `Q`; a squarefree `PolynomialLCM` of degree 2) is
  mapped affinely `x = x1 + h s` onto the canonical interval `x(1-x)`, then the
  local exponents are pulled out by an **F-homotopy** `Y = s^r0 (1-s)^r1 F` (the
  indicial roots at `s=0,1`) so the reduced `F`-equation is canonical Gauss and
  solves as `Hypergeometric2F1`. This reaches **Gegenbauer, Jacobi, and associated
  Legendre at symbolic (non-integer) degree/order** — exactly the cases Kovacic
  declines (no Liouvillian solution) — as verifiable 2F1 closed forms. Gated by a
  numeric self-verify (`hgc_num_ok`) that samples inside the mapped interval, the
  sole guard against a mis-mapped 2F1 (whose residual `zero_test` cannot disprove).
  The canonical Gauss row was factored into `specialform_gauss_basis` and reused.
- **Ordinary vs associated Legendre.** The Legendre recognizer now emits `LegendreP`
  only for the ordinary case (`mu == 0`, which numericizes); the associated case
  (`mu != 0`) declines to the affine/F-homotopy row, since a 3-argument
  `LegendreP[nu, mu, x]` does not numericize for symbolic `nu, mu` (its residual
  verify and the corpus check both fail).
- **Liouville normal-form pre-pass.** An equation carrying a `y'` term is also
  tried through its normal form `z'' = r z` (`y = z Exp[-Int P/2]`, when the
  integral is elementary) against the y'-free Airy/Bessel recognisers (factored into
  `specialform_reduced_basis`); a match multiplies the recovered basis by the
  recovery factor. Gated by `sf_num_ok`.
- **Robustness.** Both the mapped coefficients and the indicial-limit extraction use
  `Cancel[Together[.]]` rather than `Simplify` (the rational-in-`s` reduction actually
  needed; `Simplify` blows up trying to canonicalise the radical-parametric constants).
  Four decline-fast gates keep the recognizer from hanging on equations it cannot close
  (all fall through to the cascade / series fallback): (1) the indicial `FactorList`/
  `Solve` quadratic is skipped above 80 leaves (a many-parameter equation gives radical
  `a+b`, `ab` that `Solve` grinds on); (2) the affine row runs only when the two regular
  singular points are RATIONAL (radical RSPs — roots of an irreducible quadratic leading
  coefficient — are not closed here and make every downstream symbolic step slow);
  (3) the normal-form pre-pass is skipped when the potential `-r` exceeds 50 leaves; and
  (4) the pre-pass runs at top level only (`g_dsolve_depth <= 1`) — a recursive caller
  such as `OperatorFactor` re-solving an order-(n-1) quotient could otherwise compose the
  `mu = Exp[-Int P/2]` recovery factor into an infinite rewrite (`$IterationLimit`).

## DSolve M18 — 2nd-order reducible-μ integrating factor (`DSolve`ReducibleIntegratingFactor`)

New method for NONLINEAR second-order ODEs `y'' == Φ(x, y, y')` that admit an
**integrating factor** μ of a restricted two-variable form (Cheb-Terrab & Roche,
*Integrating Factors for Second-order ODEs*, J. Symb. Comput. 27 (1999) 501–519;
Maple's `_reducible, _mu_*` classes). `src/calculus/dsolve_ifactor.c`.

A function μ(x,y,y') is an integrating factor when `μ (y'' − Φ)` is a total
x-derivative `dR/dx` of a first integral `R(x,y,y')`; from the paper's (2.8)–(2.10)
`μ = R_{y'}`, `R = ∫μ dy' + G(x,y)`, with `G` fixed by `R_x + y'R_y + Φ R_{y'} = 0`.
`R(x,y,y') == C[1]` is then a **first-order ODE**, solved by recursing into the
scalar cascade (the second constant comes from that solve). Two verification gates
mean a wrong μ can only ever produce a clean decline, never a wrong answer: (1) the
symbolic first-integral test `A(R) ≡ R_x + y'R_y + Φ R_{y'} == 0` (the paper's
exactness condition (2.3)) rejects a wrong μ *before any solve*; (2) a numeric
back-substitution of the final explicit branch into the original residual rejects a
bad inversion.

**Stage 1 landed — μ(x,y) (Section 2.1).** Detects that Φ is a degree-≤2 polynomial
in `y'` (`y'' = a y'² + b y' + c`, 2.13), reads `a,b,c`, and branches on `2a_x − b_y`:
Case A (≠0) gives a closed-form μ (2.17) under the existence conditions (2.16); Case
B (=0) gives `μ = ν(x)·e^{−∫a dy}` where ν solves the one linear 2nd-order ODE the
algorithm needs (2.20), solved through the cascade. Solves e.g.
`y y' + y'' == 1` and `y'' − y y' == 6` (→ Airy), the arbitrary-parameter family
`y'' == a(1 + 2 y y')`, and the transcendental-coefficient Case-B family
`−(y'²/y²) + y''/y + 2 Coth[2x] y'/y == 2` (→ Log/ArcTanh form).

**Symbolic-parameter verification.** The numeric back-substitution gate now
instantiates the residual's free *parameters* (a, b, k, …) at generic reals — not
just `C[1],C[2],x` — so a correct solution of a symbolic-parameter ODE (the common
corpus form) numericizes instead of sampling to a symbolic, non-finite residual and
being wrongly rejected (the M16 lesson). Argument-position symbols only; function
heads (Cos, AiryAi, …) are never instantiated.

**Measured (§2.1.2 corpus, the 80 reducible-μ UNEVAL targets): +7 new PASS**
(2.1.2-184, 207, 693, 906, 1013, 1014, 1094), **0 FAIL** — the remaining targets need
Stages 2/3 (μ(x,y'), μ(y,y')) or carry arbitrary functions / non-closing reduced
first integrals.

**Robustness.** Mirrors the M12 lie2 kit: 6 s wall-clock deadline, `TimeConstrained`
on every sub-Solve/Integrate/DSolve, a per-top-level decline memo, node budgets, and
an undefined-function gate. A **linearity gate** declines linear ODEs (not the
method's domain, and it terminates the Case-B ν-ODE recursion so the linear
specialists own it). Cascade slot: 2nd-order-nonlinear tail, immediately before
`SecondOrderSymmetry` — the algebraic μ-search is cheaper than lie2's polynomial
ansatz and reaches ODEs with no point symmetry (paper §3).

Stage 2 (`_mu_x_y1`, Lemma 3 for 𝓕 + Lemma 2 for μ̃) was implemented and verified this
session for Cases A/C/D — it correctly finds valid integrating factors (Kamke 226 →
μ=y'; Kamke 136 → (y'−1)/h(y'); Kamke 66 → (y'+b)/(a(1+y'²)^{3/2}), all with `A(R)=0`
holding) — but **yields 0 new corpus solves**, because the reduced first integrals
`R==C[1]` are NON-ELEMENTARY first-order ODEs (`y'=√(x²y²+2C)`, `y'=Tan[C+Log[x−y]]`)
that neither our cascade nor — verified directly — Maple/Mathematica close in elementary
explicit form (those CAS return them implicitly). So it was reverted; Stage 2 is
**blocked on** an implicit/non-elementary first-order solver (or a policy decision to
emit the reduced first integral as an implicit answer). Stage 3 (`_mu_y_y1`, the `y↔x`
swap) depends on Stage 2. Exact equations transcribed in `DSOLVE_PLAN.md` M18.
`_mu_y2`/`_mu_poly_yn` (3rd-order integrating factors) are future.

Tests: `tests/test_dsolve.c` (`t_m18_*` — Case A/B, auto-dispatch, linearity-gate
decline, the Coth regression), the forward-generator stress suite
`tests/test_dsolve_m18_stress.c` (Case-A `y''+k y y'==c` and Case-B
`y y''−y'²+h(x)y²==0` grids, back-substitution verified), and the §2.1.2 corpus

## DSolve M19 — confluent Whittaker / ₁F₁ recogniser + §2.1.2 re-baseline

**Re-baseline first.** `DSolve_test_status/reports/2.1.2.*` was stale (pre-M17/M18); a
full re-run puts the honest post-M17/M18 baseline at **424/1000 scalar (42.4%), 0 FAIL**
(the 396→424 jump is M17 + M18, previously unmeasured together). M19 then takes it to
**427/1000 (+3: 2.1.2-102, -568, -611), 0 FAIL, 0 regressions**; ctest gate 612→576.

The confluent twin of M17's affine→Gauss row: a 2nd-order linear ODE whose Liouville
normal form `z'' = r z` has a **single finite regular singular point** `x0` (a double
pole of `r`) and a **rank-1 irregular point at infinity** (`r → b2 ≠ 0`) is Whittaker's
equation. Writing `r`'s coefficient as `Qc = b2 + b1/(x−x0) + b0/(x−x0)²` and matching
`W'' + (−1/4 + κ/z + (1/4−μ²)/z²)W == 0` under `z = c(x−x0)` gives
`c = 2√(−b2)`, `μ = √(1/4 − b0)`, `κ = b1/c`, and the two independent solutions are
emitted as the **verifiable** confluent-hypergeometric form
`Exp[−z/2] z^(1/2±μ) Hypergeometric1F1[1/2±μ−κ, 1±2μ, z]` (which numericizes and
auto-rewrites to `HypergeometricPFQ`, so the residual back-substitutes — the inert
`WhittakerM/W` heads are never emitted). New `specialform_whittaker_basis()` in
`src/calculus/dsolve_specialform.c`; no new method file, no cascade edit.

- **Detection** isolates the single finite double pole by the squarefree-part trick
  (`den / gcd(den, den')` of degree 1), so the two-finite-pole Gauss case (M17) and the
  pole-free Airy/polynomial cases decline here; `g = Cancel[Together[Qc (x−x0)²]]` must
  be a degree-2 polynomial with a nonzero leading coefficient (`b2 ≠ 0`).
- **Gate:** declines when `2μ` is a numeric integer (the two ₁F₁ partners are then
  dependent, or a lower parameter `1∓2μ` is a non-positive integer / singular ₁F₁) —
  a correct fall-through to the Frobenius log-second-solution; symbolic `μ` is kept.
- **`base` self-verifies** against the reduced equation `w'' + Qc w == 0` (numeric,
  parameters instantiated) before returning, so a mis-read pole / parameter can never
  ship — 0-FAIL by construction.
- **Scope: the y'-free (`P == 0`) surface only.** The recogniser runs where the equation
  is already `y'' + Q y == 0` (Q a rational with the required single-double-pole / rank-1-
  at-∞ shape). It is deliberately NOT run in the Liouville normal-form pre-pass (`P ≠ 0`):
  there the recovery factor `Exp[−∫P/2]` shares the finite-pole base `(x − x0)` with the
  Whittaker `z^(1/2±μ)` factors, so the composed candidate stacks two symbolic-radical
  powers of the same base, and verifying / differentiating that (in `dsolve_run`, or in
  a multi-parameter `HypergeometricPFQ` numeric evaluation) can drive the evaluator into
  `$IterationLimit` and starve the Frobenius fallback that otherwise solves those as a
  series — a **regression** measured on ≈5 corpus cases (94/470/472/806/811). Running
  Whittaker only on `P == 0` (no recovery factor, no stacking) keeps the invariant of **0
  regressions**.
- **Solves** the y'-free confluent §2.1.2 cases as closed-form ₁F₁ — e.g. 2.1.2-102
  (`x²y'' + (cx²+bx+a)y == 0`), -568, and the Whittaker/Coulomb normal forms — previously
  reaching only the Frobenius series fallback. **0 FAIL, 0 regressions.**

*Future work (documented, not shipped):* the much larger `P ≠ 0` confluent family
(2.1.2-97/-101/-104 and kin, ~13 corpus cases) — the pre-pass Whittaker with the recovery
factor — needs an evaluator-robustness fix for the same-base symbolic-radical-exponent
verify (`zero_test` / `HypergeometricPFQ` numeric `$IterationLimit`) before it can ship
without the regressions above.

+ the forward-generator stress suite `tests/test_dsolve_m19_stress.c` (P==0 Whittaker

## DSolve M20 — first-order symmetry gap, Stage 1 (`DSolve`PolynomialShiftSubstitution`)

First wave on the §2.1.2 `1st_with_symmetry` bucket (65 total, 38 unsolved) — **427→432
scalar (+6), 0 FAIL, 0 real regressions**. New method `dsolve_polyshift.c`: the
x-dependent-shift generalisation of `FirstOrderSubstitution`.
For `y' = R(x) + g(x) (φ(x) + c y)^p` with `p` a non-integer rational, `φ` polynomial in
`x`, `c` constant and `R = −φ'/c`, the substitution `u = φ(x) + c y` reduces the ODE to
the separable `u' = c g(x) u^p`, whose first integral `u^(1−p)/(1−p) − Integrate[c g, x]
== C[1]` is returned **implicitly** (branch-safe — the radical's sign is never committed;
verified by the implicit-function rule `y' = −G_x/G_y`).

- These are Maple's `[F(x),G(x)]`-symmetry cases (invariant `u`). The heuristic Lie method
  `abaco2_similar` targets the same class but its `Q = ω_y/ω_yy`, `T = Q_x/Q_y` construction
  differentiates the radical `ω`, blows past the node budget, and ABORTs; the deterministic
  substitution sidesteps the symmetry machinery.
- **Cascade slot:** after `Separable`, before the heavier `Linearizable`/`Exact`/`Lagrange`
  searches — those otherwise spin on the parameter-laden radical before the late implicit
  slot is reached. Detection needs a fractional-power-of-(linear-in-y) atom the standard
  methods never produce, so early placement is safe and steals nothing (`y' = a y + b√y`
  has an additive `a y` → the reduced form is not the pure `k(x) u^p` → declines).
- **Simplify-free by design:** the reduced form is built by plain evaluation, not
  `Simplify` — `Simplify[(x + Sqrt[u]) u^(-1/2)]` loops (radical rationalisation), a shape
  the `nth_algebraic` branches of a Lagrange equation (`y = 2 x y' + y'^2` →
  `y' = −x ± Sqrt[x^2 + y]`) hit; the evaluator's same-base-power / additive cancellation
