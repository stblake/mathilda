# Changelog: week of 2026-08-03 (Mon) – 2026-08-09 (Sun)

Feature additions and fixes recorded during this week.

## Added: `Order` — canonical structural comparison (2026-08-03)

`Order[e1, e2]` gives `1` if `e1` is before `e2` in canonical order, `-1` if
after, and `0` if identical — the direct user-facing surface of the same
`expr_compare` comparator that `Sort`, `SortBy`, `OrderedQ`, and every other
sorting routine already share.

```mathematica
In[1]:= {Order[a, a], Order[a, b], Order[b, a]}
Out[1]= {0, 1, -1}

In[2]:= {Order[6, Pi], Order[6, N[Pi]]}
Out[2]= {1, -1}

In[3]:= Order @@@ Tuples[{0, 1, 2}, 2]
Out[3]= {0, 1, 1, -1, 0, 1, -1, -1, 0}
```

`Order` compares **structurally**, not by numerical value: `Order[6, Pi]` is `1`
(the Integer sorts before the symbol `Pi`), while `Order[6, N[Pi]]` is `-1` (two
numeric atoms, by value). The implementation is a single `expr_compare` call with
the sign inverted (`expr_compare` returns negative when `e1` sorts first, `Order`
returns `+1`); attribute `Protected`.

**Compilable and auto-compiled.** Inside `Compile[]` every argument is a machine
number, so `Order[a, b]` lowers to `Sign[b - a]` — reusing the existing `SUB` and
`SIGN` opcodes, no new bytecode — and returns the Integer `{1, 0, -1}`. Because
the result type is declared `CT_INT` (like `Sign`), `Head[...]` is `Integer`,
matching the interpreter (result-HEAD parity), and `Table`/`Plot`/`NIntegrate`
auto-compile bodies that mention it for free. Complex/array arguments decline and
fall back to the interpreter.
