## Definite `Integrate`: whole-line hyperbolic residue family extended to higher-order poles ; v0.293

**Outcome: Phase 3a of the stress-test campaign — `Cos[a x]/Cosh[b x]^2` and the whole
class `(trig)/Cosh[b x]^n` now close instantly, correct-by-construction.**
- `Integrate[Cos[a x]/Cosh[b x]^2, {x,-Inf,Inf}, Assumptions -> Element[a,Reals] && b>0]`
  → `Pi a Csch[Pi a/(2 b)]/b^2` (0.03 s, was a ~55 s decline).
- The same path closes `Cos[a x]/Cosh[b x]^3` → `Pi (a^2+b^2) Sech[Pi a/(2b)]/(2 b^3)`,
  `Cosh[b x]^4` → `Pi a (a^2+4 b^2) Csch[Pi a/(2b)]/(6 b^4)`, and the `Sin`/`Sinh`
  numerators (as a correct Csc-sum), for any integer `n >= 2`.

### What changed (`src/calculus/integrate_residue.c`, `residue_family_hyperbolic_strip`)

The periodic-strip (rectangle) family closed `N(x)/Cosh[b x]` on `(-Inf,Inf)` by the
quasi-period fold `Cosh[b(x + i Pi/b)] = -Cosh[b x]` and a hard-coded `Sec` closed form
per exponential term.  It matched only a **bare** `Sech[b x]` factor, so `Sech[b x]^2`
(head `Power`) fell through and `Cos[a x]/Cosh[b x]^2` ground the full Newton-Leibniz
antiderivative search for ~55 s before declining.  Two changes, both
correct-by-construction (the integrand has no elementary antiderivative; NO NIntegrate):
- **Matcher** (`match_cosh_power_factor`): accept `Sech[beta x]^n` and `1/Cosh[beta x]^n`
  for any integer `n >= 1` (argument still exactly `beta*x`, `beta` free of `x`), carrying
  the order `n`; the convergence gate widens from `|Re alpha| < Re beta` to
  `|Re alpha| < n Re beta` (`Cosh^n ~ e^(n beta|x|)/2^n` at infinity).
- **Closed form** (`hyperbolic_strip_term`, new): for each exponential term `C E^(alpha x)`
  with `n >= 2`, emit the Gamma-reflection value of the Mellin-Barnes integral
  (equivalently the order-`n` residue of the quasi-period fold),
  `2^(n-1)/(beta (n-1)!) · R(w) · Prod(w)` with `w = alpha/(2 beta)`:
  `R = Pi/Cos[Pi w]`, `Prod = Prod_{j=0}^{m-1}((j+1/2)^2 - w^2)` for odd `n = 2m+1`;
  `R = Pi w/Sin[Pi w]`, `Prod = Prod_{j=1}^{m-1}(j^2 - w^2)` for even `n = 2m`.
  This collapses to the existing `(Pi/beta) Sec[alpha Pi/(2 beta)]` at `n=1` (kept on its
  own untouched path, so every existing `Cosh/Cosh`, `Exp/Cosh`, `Sinh/Cosh` output is
  byte-for-byte unchanged).  The family's own `ComplexExpand`+`Simplify` tail then
  reduces the elementary, even-in-`alpha` form to `Sech`/`Csch · polynomial`.

Verified: new self-certifying cases in `tests/test_integrate_residue.c`
(`test_hyperbolic_strip`) pin `Cosh^2`/`Cosh^3` exactly and `Cosh^4`/`Sin·Sinh/Cosh^2`
numerically against the series value; all definite-integration suites green; `check-c99`
and `check-messages` clean.

## Definite `Integrate`: special-function integral-representation recognizers + Euler→Beta·2F1 ; v0.292

**Outcome: Phase 2 of the half-line/transform stress-test campaign — five previously
unevaluated integrals now close, as general classes (not one-offs):**
- `Integrate[E^(-c x) BesselJ[0, a x], {x,0,Inf}, Assumptions -> c>0]` → `1/Sqrt[a^2+c^2]`
  (Laplace-Bessel, general `nu`).
- `Integrate[E^(-a Cosh[x]) Cosh[n x], {x,0,Inf}, Assumptions -> a>0]` → `BesselK[n, a]`.
- `Integrate[E^(-a x - b/x)/Sqrt[x], {x,0,Inf}, Assumptions -> a>0 && b>0]`
  → `Sqrt[Pi/a] E^(-2 Sqrt[a b])` (the `nu=1/2` case of the general
  `2 (B/A)^(nu/2) BesselK[nu, 2 Sqrt[A B]]`, elementary via `K_{1/2}`).
- `Integrate[Cos[x^3/3 + a x], {x,0,Inf}, Assumptions -> Element[a,Reals]]` → `Pi AiryAi[a]`
  (the Airy integral; general `Cos[p x^3 + q x]`).
- `Integrate[x^(a-1)(1-x)^(b-1)/(x+c)^(a+b), {x,0,1}, Assumptions -> a>0 && b>0 && c>0]`
  → `Beta[a,b] (1+1/c)^(-a) c^(-(a+b))` (Euler integral → `Beta · 2F1`).

### Integral-representation recognizer (new `src/calculus/integrate_intrep.c`)

A half-line integrand that IS a classical integral representation of a special
function has no elementary antiderivative — so Newton-Leibniz, the Mellin/residue
families and Ramanujan all decline — yet the closed form is immediate once the shape
is matched and its convergence gate is proved from Assumptions.  Correct-by-construction
(the representation is an identity on its domain); NO NIntegrate.  Four families, each a
structural match + `Refine`/`Simplify`-proved gate:
- **Laplace-Bessel** `E^(-p x) BesselJ[nu, q x]` → `(Sqrt[q^2+p^2]-p)^nu/(q^nu Sqrt[q^2+p^2])`,
  gated `p>0` (and `q>0` for `nu != 0`; `nu=0` needs only `p>0`).
- **Bessel-K (cosh)** `E^(-A Cosh[x]) Cosh[n x]` → `BesselK[n, A]`, gated `A>0`.
- **Bessel-K (exp)** `x^(nu-1) E^(-A x - B/x)` → `2 (B/A)^(nu/2) BesselK[nu, 2 Sqrt[A B]]`,
  gated `A>0, B>0`.  A half-integer `nu` lands the elementary form: the close is
  `TrigToExp[Simplify[...]]` as the LAST step (no trailing Simplify — Simplify's
  complexity metric would re-fold `e^(-z)` back into `Cosh-Sinh`).
- **Airy** `Cos[p x^3 + q x]` → `Pi (3p)^(-1/3) AiryAi[q (3p)^(-1/3)]`, gated `p>0`, `q` real.

Wired into the half-line cascade after Ramanujan, before FTC; `Method ->
"IntegralRepresentation"` and `Integrate`IntegralRepresentation[f, {x,0,Infinity}]`.

### Euler finite-interval → Beta·2F1 (`integrate_euler_2f1_try`, `integrate_beta.c`)

`Integrate[x^(a-1)(1-x)^(b-1)(alpha+beta x)^e, {x,0,1}]
= alpha^e Beta[a,b] Hypergeometric2F1[-e, a, a+b, -beta/alpha]` — the Euler integral
representation of `2F1`, generalizing the pure-Beta reduction by ONE extra linear
factor.  The degenerate `2F1` auto-reduces (`2F1[a+b,a,a+b,z] = (1-z)^(-a)`), so #18
lands on an algebraic·Beta form.  Gated `Re a>0, Re b>0` (convergence) and `alpha>0 &&
alpha+beta>0` (base positive on `[0,1]`, which also keeps the `2F1` argument off the
branch cut) — proved with **`Refine`** (a new `prove_ref`), since `Simplify` leaves an
implication like `c>0 => c+1>0` as the unproved `c > -1`.  Runs under the `Beta`
mechanism, after `integrate_beta_try`.  (This also closes `Integrate[1/(1+x),{x,0,1},
Method->"Beta"] = Log[2]` — the `a=b=1` Euler case — so the stale beta-suite
negative-control for that input was updated.)

## Definite `Integrate`: confidence-first cascade reorder + rational-Mellin strip + sound residue cleanup ; v0.291

**Outcome: a reliability-and-speed pass over definite integration (Phase 1 of the
half-line/transform stress-test campaign). Three changes, all correct-by-construction,
no new math:**
- **Speed (reorder).** `Integrate[x^(s-1)/(1+x^2)^m, {x,0,Inf}, …]` now closes in
  **0.007 s (was 54 s)**, `Integrate[Sin[x]^a Cos[x]^b, {x,0,Pi/2}, …]` in
  **0.0015 s (was 19.5 s)**, `Integrate[Exp[-x] x^(s-1) Log[x]^2, {x,0,Inf}, s>0]`
  in **0.005 s (was 54 s)** — and the spurious `Integrate::nonelem` these used to
  print is gone.
- **Coverage.** `Integrate[x^a/(x^2+2b x+c), {x,0,Inf}, Assumptions -> -1<a<1 &&
  c>b^2 && b>0]` now **closes** (0.42 s; was a 10 s decline) via the keyhole Mellin
  residue sum.
- **Output quality.** `Integrate[Log[x]/(x^2-a^2), {x,0,Inf}, PrincipalValue -> True,
  Assumptions -> a>0]` now returns the clean **`Pi^2/(4a)`** instead of a ~200-node
  `Arg`/`Abs`/`(a^4)^(1/4)` expression; the two-pole-pair, square-root and
  hyperbolic-strip residue outputs are likewise tidied where the assumptions permit.

### (a) Confidence-first reorder of the definite cascade (`src/calculus/integrate.c`)

The deterministic, correct-by-construction transform reductions — `integrate_beta_try`
(`[0,1]` Euler Beta), `integrate_trigpower_try` (`Sin^m Cos^n` over a canonical trig
interval) and `integrate_ramanujan_try` (half-line Mellin / RMT) — now run **before**
`integrate_newton_leibniz_try_pv` instead of after it. Each is gated by a cheap
structural interval/shape test and owns exactly its family, so for a symbolic-exponent
integrand it yields the closed form at once; previously FTC ran first and ground a
doomed elementary-antiderivative search (Risch / ParallelMixed*) for tens of seconds
before the owning stage was ever reached. This is the same confidence-first rule the
Weierstrass and Symmetry placements already follow. Order after residue/symmetry is
unchanged, so residue's pinned outputs are preserved; FTC still owns the integer-power
and genuinely-elementary cases the transform stages decline on.

### (b) Rational half-line Mellin accepts the true convergence strip (`integrate_residue.c`)

`mellin_core` already implements the general keyhole residue sum
`-Pi Sum_k z_k^(s-1) Res(R,z_k) e^(-i Pi s)/Sin(Pi s)` with conjugate-pair and
higher-order-pole support, but declined `x^a/(x^2+2b x+c)` for two reasons, both fixed:
- **Coupled bounds were discarded.** `c > b^2` leaves `c` unbounded, forcing the
  `FindInstance` branch of `build_instantiation`, which cleared *all* per-parameter
  bounds (`g_nbounds = 0`) — so the convergence gate could not verify `0 < 1+a < 2`
  for the directly-bounded exponent `a`. The sound bounds `absorb_fact` found (a
  bare-symbol-vs-numeric relation like `-1<a<1`) are now recorded even in the coupled
  path; a new `g_coupled` flag (distinct from `g_nbounds`) carries the mode for the
  trig family's degenerate-point retry, which is unchanged.
- **The integer-`s` guard fired on the representative point.** With the exponent
  symbolic (`s = 1+a`), the coupled instantiation `a -> 0` makes `s = 1` (integer),
  and the "reject integer `s`" guard (the keyhole degenerates at `Sin[Pi s] = 0`)
  wrongly rejected it. The guard now reads the *literal* `s` (`res_reim_direct`, no
  instantiation), so a symbolic exponent survives — the generic `Csc[Pi s]` closed
  form is the correct generic-parameter answer.

### (c) Sound assumption-aware cleanup of residue output (`integrate_residue.c`, `refine.c`)

Residue families are correct by construction but several return a form laden with
`Arg`/`Abs`/`Sqrt[a^2]`/`(a^4)^(1/4)` that the per-family close (plain `Simplify`, or a
close gated on all-parameters-positive) does not discharge. A new `res_refine_final`
runs once at the top of `integrate_residue_try`, decoupled from `g_all_pos`:
`Refine[·, assumptions]` (SOUND — it collapses `Sqrt[a^2]->a`, `Abs[a]->a`,
`Arg[pos]->0`, `Arg[neg]->Pi` only when it can PROVE the sign, never the unsound
in-file `PowerExpand`), then a plain `Simplify`, then — only on a small, **radical-
and trig-free** elementary rational-log form carrying a cancelling imaginary unit — a
bounded `FullSimplify` finisher. The candidate replaces the original only when strictly
smaller by node count, so a legitimately-messy result (`Arg[I a]` that `Refine` cannot
reduce; a mixed-sign radical the assumptions do not pin, e.g. the `-1<a<1` quartic #11;
the already-clean `Sec` hyperbolic form #17) is never enlarged or corrupted.
Deliberately **no `ComplexExpand`**: on a compact nested-radical conjugate-pair form it
explodes into a giant tree that then hangs `Simplify`, while buying the collapsible
families nothing. The enabling `refine.c` addition: `deep_positivity_walk` now collapses
`Arg[p] -> Pi` for a provably-negative real compound `p` (the fast
`simp_assume_rewrite` path already did `Arg[positive] -> 0` but left `Arg[-a]`
standing), which is exactly what lands #13 on `Pi^2/(4a)`.

### Still open (next phases)

Unbroken but still unevaluated (future phases): the Laplace/Bessel-K/Airy

## Series/Limit: ArcTanh/ArcCoth branch-point expansion for a non-linear inner ; v0.290

**Outcome: `Series[ArcTanh[Sqrt[1 - a^2]], {a, 0, 1}]` now expands to
`Log[2] - Log[a] + O[a]^2` (it was returned unevaluated), so the limits that rely
on it decide instead of returning `Infinity`:
`Limit[Log[a] + ArcTanh[Sqrt[1 - a^2]], a -> 0] = Log[2]`.**

### Root cause (`src/calculus/series.c`)

ArcTanh/ArcCoth have a logarithmic branch point at an argument of ±1. The existing
branch-point handler (`so_apply_arctanh_branch_point`) only fires when the inner
series is `±1 + q*w` (a LINEAR leading correction, `branch_check_linear_inner`).
`Sqrt[1 - a^2] = 1 - a^2/2 - ...` approaches 1 QUADRATICALLY, so the handler
declined and `series_expand` returned unevaluated — and `Limit`/Gruntz then saw two
individually divergent `±Log[a]` terms and reported `Infinity`.

### Fix

When the ArcTanh/ArcCoth inner is at a ±1 branch point but the linear handler
declines, rewrite at the Expr level `ArcTanh[arg] = (Log[1 + arg] - Log[1 - arg])/2`
and recurse through `series_expand`, whose Log-of-a-vanishing-series handling
(`Log[c (x-x0)^r (1+u)] = r Log[x-x0] + Log[c] + Log[1+u]`) extracts the
`Log[x-x0]` singularity for whichever of `1 ± arg` vanishes — for a leading
correction of ANY order. The recursion terminates (the rewrite is Log-only, no
ArcTanh). Purely additive: the linear branch-point and at-zero / at-infinity paths
are unchanged, so the series/limit/gruntz suites are green.

### Tests

`tests/test_limit.c::test_arctanh_branch_point` pins the two canceling limits and
that the underlying `Series` no longer returns unevaluated.

## DiffUnderInt `Integrate`: reverse recognition (Gamma') + repeated differentiation + output-quality finalize ; v0.288

**Outcome: three more `Method -> "DiffUnderInt"` targets close.
(1) `Integrate[Exp[-x] x^(a-1) Log[x], {x,0,Inf}, Assumptions -> a>0]` ->
`Gamma[a] PolyGamma[0,a]`.
(2) `Integrate[Sin[a x]^3/x^3, {x,0,Inf}, Assumptions -> a>0]` -> `3 Pi a^2/8`.
(3) `Integrate[Log[1 + a^2 x^2]/(1 + b^2 x^2), {x,0,Inf}, Assumptions -> a>0 && b>0]`
now returns the contracted `(Pi(Log[a+b]-Log[b]))/b` instead of the split
`(Pi(-2Log[b]+Log[a b+b^2]))/b`.**

### Reverse recognition (`stage_reverse_feynman`, `src/calculus/integrate_diffunderint.c`)

When the integrand is itself a parameter-derivative of a known integral --
`f = Log[x]^k h` with `d/da h = Log[x] h` -- the value is `d^k/da^k Integrate[h]`.
`strip_log_x_power` peels the `Log[x]^k` factor; `find_log_derivative_param`
verifies `d/da h == Log[x] h`; `known_integral_closed_form` recovers `F(a) =
Integrate[h, {x,a,b}]` from the families or, for a decaying Laplace/Gamma shape
`C Exp[alpha x] x^(s-1)` (gated by `is_gamma_shape` so it cannot hang), from the
engine; the result is `d^k/da^k F`.  Runs last, outside the `np>0` guard (the Log
weight supplies the parameter).  Closes the Gamma'-derivative integral.

### Repeated differentiation / power reduction (`stage_repeated_quadrature`)

A single differentiation of `trig^n/x^m` leaves a `1/x^{m-1}` the families still
cannot close; `stage_repeated_quadrature` differentiates `k` times (bounded by the
Together-denominator degree `max_inv_x_power`, capped at 4) until the inner integral
closes, then back-integrates `k` times, pinning the `k` lower derivatives at an exact
base (`multi_base`).  Closes `Sin[a x]^3/x^3` (`k = 2`: `I''(a) = 3 Pi/4`, `I(0) =
I'(0) = 0`), which neither the Automatic cascade nor single-differentiation closes.

### Output-quality finalize (`diui_finalize`)

Extended beyond 1-arg PowerExpand with an assumption-aware `FullSimplify`
candidate, taken only when strictly simpler (smaller `LeafCount`) and gated to a
small result so it stays bounded; each candidate is kept only when provably equal
to the verified answer.  Contracts the split Log the per-family Simplify leaves
standing.

### Deferred: finite-period log-trig

`Integrate[Log[a^2 - 2a Cos[x] + 1], {x,0,Pi}]` and `Integrate[Log[1 - a^2 Sin[x]^2],
{x,0,Pi/2}]` remain unevaluated.  The differentiated inner integral (rational in
Sin/Cos over a period) is reachable via the residue unit-circle engine, but the
Feynman back-integration yields a complex-branch antiderivative singular at the
natural base (`∝ 1/a` or `1/√(1-a^2)`) and `Limit` cannot resolve the canceling
log-singularity there -- a branch-correct back-integration is the prerequisite.

### Tests & docs

`tests/test_integrate_diffunderint.c`: `test_reverse_feynman`,
`test_repeated_quadrature`, `test_finalize_quality` (the last also asserts the
uncontracted `Log[a b + b^2]` does not survive).  Docs updated in
`docs/spec/builtins/calculus.md`.  valgrind clean on the new paths.

## `Resolve` / `Reduce` over the Reals: rational-denominator clearing (unblocks limit ε–δ proofs) ; v0.289

**Outcome: the quantified real statements behind whole families of calculus
limits now decide instead of declining — every example in `RESOLVE_IMPROVEMENTS.md`
§2 and the three §1 gap rows close:**
- `Resolve[ForAll[m, m>0, Exists[del, del>0, ForAll[x, 0<x<del, m x < 1]]], Reals]` → `True`
- `Resolve[ForAll[eps, eps>0, Exists[n, n>0, ForAll[x, x>n, eps x > 1]]], Reals]` → `True`
- `lim_{x→∞} 1/x = 0` and `lim_{x→0} 1/x² = ∞` (literal ε/M–δ/N transcriptions) → `True`
- wrong limits (`lim_{x→∞} 1/x = 5`) still correctly return `False`.

The base engine also decides multivariate rational atoms it used to decline:
`Reduce[del>0 && m <= 1/del, {m, del}, Reals]`, `Reduce[x/y <= 0, {x, y}, Reals]`, etc.

**Root cause (the `RESOLVE_IMPROVEMENTS.md` hypothesis was wrong).** The CAD
handles the parameter×variable PRODUCT fine. The real gap: chained quantifier
elimination emits a **rational atom** at an intermediate level — the inner `∀x` of
the product case eliminates correctly to `del>0 && m <= 1/del` — and every
multivariate real engine (`reduce_cad.c`, `reduce_fm.c`, `reduce_sys.c`,
`reduce_zerodim.c`) **declines any atom with a non-constant denominator**
(`nonconst_denom`). The Reals preprocessing rationalized radicals and split
selectors but had no pass to clear rational denominators.

### Denominator clearing (`reduce_piecewise_preprocess`, `src/solve/reduce_realfn.c`)

New "Preprocessing 6": each relational leaf `p/q REL 0` with `q` a non-constant
polynomial in the reduce variables is rewritten to its sign-exact
denominator-free equivalent over the Reals (q² > 0 off the pole set):
`p/q < 0 ⟺ p q < 0`; `p/q <= 0 ⟺ p q <= 0 && q != 0`; `p/q == 0 ⟺ p == 0 && q != 0`
(`> / >=` by operand swap; `q != 0` guards drop the excluded poles, matching
Reduce's domain semantics). Walked in NNF so a negated leaf clears with its
De-Morgan relation. New gate `reduce_stmt_has_fraction` triggers the pass at both
multivariate Reals call sites (`reduce.c`, `reduce_qe.c`). The pass joins the
existing selector/radical fixpoint, ordered selector → fraction → radical (a
fraction that exposes a radical, `del <= 1/Sqrt[M]`, is rationalized the same
iteration).

### Abs-of-fraction pole fix (`split_abs_denominators`)

`eliminate_abs` case-splits the whole formula on the sign of the Abs argument; for
`Abs[1/x]` the branch guards clear to `x>0`/`x<0`, which **miss the pole x=0** and
collapse the surrounding formula to `False` there — unsound inside a `ForAll`. The
sound identity `Abs[p/q] = Abs[p]/Abs[q]` (run before the split) moves the
denominator out of the Abs so its argument is pole-free and the sign guards
(`x>=0`/`x<0`) cover the pole. A conservative guard disables fraction clearing when
a non-Abs selector (Min/Max/Piecewise/…) carries a fractional argument, so those
exotic shapes decline soundly rather than risk the same pole collapse.

**Soundness.** Every change strictly expands what is proved; no decline became a
wrong verdict (an atom the pass cannot clear still hits the engines'
`nonconst_denom` backstop and declines). The univariate path
(`reduce_realfn_preprocess` + the pole-aware sign diagram) is untouched, so
`Reduce[1/x < 1, x, Reals]` etc. are unchanged.

`tests/test_reduce.c` gains multivariate rational-atom and ε–δ product-limit pins;

## DiffUnderInt `Integrate`: self-similar Gaussian recognizer (Glasser substitution) ; v0.287

**Outcome:
`Integrate[Exp[-a^2 x^2 - b^2/x^2], {x, 0, Infinity}, Assumptions -> a > 0 &&
b > 0, Method -> "DiffUnderInt"]` now closes to `(Sqrt[Pi]/(2a)) Exp[-2 a b]`.**

### `detect_selfsimilar_ode` (`src/calculus/integrate_diffunderint.c`)

The Stage B IBP ansatz cannot reach a Laurent-Gaussian integrand (no polynomial
`U` in `x` reproduces the `1/x^2` term — verified: the `x^{-2}` coefficient cannot
be cancelled by an x-free `lambda`), so Stage B now falls back to a dedicated
self-similar recognizer. For `f = Exp[c0 + c2 x^2 + cm2/x^2]` with `c2, cm2 < 0`,
the reciprocal substitution `x -> k/x`, `k = Sqrt[cm2/c2]`, leaves the exponent
invariant, so `Integrate[g, {x,0,Inf}] = Integrate[g(k/x) (k/x^2), {x,0,Inf}] =
lambda I` with `lambda = g(k/x)(k/x^2)/f` read off directly (x-free when it fires),
`M = 0`. Differentiating `Exp[-a^2 x^2 - b^2/x^2]` in `b` gives `lambda = -2a`, and
the integrating factor closes `I = I(0) Exp[-2 a b]` with base `I(0) = Sqrt[Pi]/(2a)`.

Supporting: `has_inv_x_power` gates Stage B's IBP ansatz off any Laurent integrand
(the polynomial `CoefficientList` match has no negative degrees), leaving it for

The method's header advertised a first-order-ODE framing `I'(p) = lambda(p) I +

## Residue `Integrate`: multi-frequency Fourier (cosine difference) + honest arctan decline ; v0.284

### Multi-frequency Fourier family (`src/calculus/integrate_residue.c`)

New `residue_family_fourier_sum` (with helper `fsum_term`), wired into the
whole-line dispatch right after the single-kernel Fourier family.  It recognises

degree-drop ≥ 1.  The sum lifts to `Σ_i C_i e^{i ω_i x}` and the half-plane

only when `Limit[f, x → z₀]` of the **original** integrand is finite — the summed
numerator has reduced the pole order — and then contributes the indented
half-residue (weight 1) alongside the full enclosed residues (weight 2).  The
single `Cos[a x]/x²` (no cancellation, limit infinite) correctly declines as
divergent rather than fabricating a value.  Whole-line `π(b − a)`; the even
half-line add-on gives `π(b − a)/2`.

`∫₀^∞ ArcTan[a x]/(x (1 + b² x²)) dx = (π/2) Log[1 + a/b]` is pinned as a
deliberate decline.  The integrand carries a branch cut (`ArcTan`), not isolated
poles; the closed form comes from parametric differentiation (Feynman:

is outside the residue theorem.  No Feynman engine is on the residue path, so the
method returns the integral unevaluated — consistent with the Case-17/21
decline policy (a negative control, not a silent wrong answer).

## Residue `Integrate`: Fourier axis-pole correctness + a `FactorTerms` zero bug ; v0.277

**Outcome: fixes a silent WRONG ANSWER.
`Integrate[Sin[a x]/(x (x^2+b^2)), {x, -Infinity, Infinity}, Assumptions -> a>0 && b>0,
Method -> "Residue"]` returned `0`; the correct value is `(Pi/b^2)(1 - e^(-a b))`.
Two independent bugs combined to produce it, one of them in a core polynomial
routine that was silently poisoning `Simplify` far beyond residues.**

### The Fourier conjugation (`src/calculus/integrate_residue.c`)

The Jordan/Fourier family already classified the removable real-axis pole at
`x=0` correctly (a weight-1 half-residue) alongside the enclosed pole at `I b`.
But in symbolic-parameter mode the `Cos`/`Sin` extraction conjugated the contour
value by `ReplaceAll[J, I -> -I]`, which rewrites only the interned `+I` symbol
and leaves a stored `-I` (`Complex[0,-1]`) atom untouched.  With a mixed-sign
residue sum (axis half-residue `+I/b^2` plus enclosed `-I e^(-a b)/b^2`) the
`e^(-a b)` term cancelled against itself and the result collapsed.  The closing
now takes `ComplexExpand[Re[J]]` (Cos) and `ComplexExpand[Im[J]]` (Sin):
`ComplexExpand` treats every free parameter as real — which they are here — so it
conjugates both `+I` and `-I` atoms correctly and returns a clean closed form.
The brittle `res_conjugate` helper is removed.

### `FactorTerms` never fabricates a `0` content (`src/poly/facpoly_factorterms.inc`)

The deeper half: the family forms `J = Simplify[Together[Pi I S]]`, and
`Simplify`'s search ran `FactorTerms` as a candidate transform.  When an upstream
`Together` fails to clear a symbolic denominator it can leave a Laurent term
(`b^-1`) inside the numerator; the nonnegative-degree coefficient extraction in
`ft_content_wrt_set` then finds no monomials and returned a **content of `0`**,
which multiplied the whole factor list down to a spurious `0`.  `Simplify` trusts
a transform's literal `0` and early-exits — so `Simplify[(I - I Exp[-a b])/b^2]`
wrongly returned `0` (any `I` coefficient + ≥2 distinct function-head variables +
a symbolic denominator triggered it).  The content of a nonzero expression is a
unit, never `0`: `ft_content_wrt_set` now returns `1` when it extracts no
monomial structure from a nonzero input.  This is reachable only on the

## Residue `Integrate`: Gaussian / shifted-rectangle family (Case 15) ; v0.276

**Outcome: `Method -> "Residue"` now closes an entire `E^(quadratic)` integrand

### `residue_family_gaussian` (`src/calculus/integrate_residue.c`)

A new whole-line family for the pole-free *shifted-rectangle* contour: `e^(A z²)`
(`Re A < 0`) is entire, so the integration line shifts freely.  `TrigToExp` +
`Expand` turn any `Cos`/`Sin`/`Cosh`/`Sinh` kernel into a sum of `E^(linear)`, so
the integrand becomes `Σ_i C_i E^(A x² + B_i x + D_i)`; each Gaussian closes by
completing the square,

```
∫_{-∞}^{∞} e^(A x² + B x + D) dx = Sqrt[-Pi/A] e^(D - B²/(4 A)),   Re A < 0.
```

The leading coefficient's sign is verified over the whole assumption-guaranteed

divergent integral) declines rather than returning a wrong finite value; a kernel
leaving any non-exponential `x`-dependence also declines.  It is gated on an
actual exponential of the integration variable (`contains_exp_of_var`) and runs
**first** on the whole-line branch, short-circuiting the non-elementary
antiderivative search that otherwise spins — so it is the fix for the hang as
well as the miss.  Verified: `Exp[-x²] Cos[2x] = √π/e`, `Exp[-x²+3x] = √π e^(9/4)`,
`Exp[-x²+I x] = √π e^(-1/4)`, `Exp[-2x²] Cos[x] = √(π/2) e^(-1/8)`,
`Exp[-x²] Sin[2x] = 0`; `Exp[x²]` declines.  Not a residue computation (no poles),
but the standard contour route for the family.  Entirely additive: the rational,
Fourier, and rectangular whole-line families are unchanged (26 integrate/series
suites green).

## Residue `Integrate`: principal-value keyhole-log + hyperbolic rectangular reduction ; v0.275

**Outcome: `Method -> "Residue"` now handles a simple pole of the rational
factor sitting on the keyhole-log branch cut `(0, ∞)` as a Cauchy principal
value, and reduces `x^k/Sinh x`-type whole-line integrals to that same
keyhole-log core.  Two probe-set declines close:**
- `Integrate[Log[x]/(x^3 - 1), {x, 0, Infinity}] = 4π²/27` (Case 18) — the pole
  at `x = 1` is removable (`Log 1 = 0`), so no option is needed.
- `Integrate[x/Sinh[x], {x, -Infinity, Infinity}] = π²/2` (Case 7) — via
  `w = Exp[x]`.

### `PrincipalValue` threaded into the residue method (`integrate.c`, `integrate_residue.{c,h}`)

`Integrate`'s already-parsed `PrincipalValue -> True` option was passed only to
Newton–Leibniz.  It is now threaded into `integrate_residue_try` (a new seventh
parameter, carried through a file-scope `g_pv` that is saved/restored per frame
so a nested call cannot leak it) and consulted by the keyhole-log family.

### Principal-value axis pole in the keyhole-log family (`a0_keyhole_log`)

A simple pole `z₀` of `R` on the positive real axis — previously an automatic
decline — is admitted when the caller asked for `PrincipalValue -> True`, **or**
when it is *removable*: a simple pole at `z₀ = 1` under a `Log` factor, whose
zero (`Log 1 = 0`) cancels the pole so the ordinary integral equals its
principal value.  The contour indents around the pole above and below the cut,
so its contribution to the residue sum `S_k` is the average of the two
keyhole-branch residues, `½ Res(R, z₀)[(Log z₀)^k + (Log z₀ + 2πi)^k]`.  A
higher-order axis pole (whose principal value diverges) still declines.  Derived
and cross-checked: `∫₀^∞ Log[x]/(x²−4) dx = π²/8` with `PrincipalValue -> True`,

### Hyperbolic reduction in the rectangular family (`residue_family_rectangular`)

The `w = Exp[x]` substitution that reduces `Exp[c x] R(Exp[x])` to the Mellin
integrand now also closes `x^k/Sinh x` and its relatives: a `Sinh`/`Cosh`/`Tanh`/
`Csch`/`Sech`/`Coth` of `Log w` rationalises under `TrigToExp` + `Together`

keyhole-log family, whose removable `w = 1` (`x = 0`) pole is exactly the
principal-value case above.  The pure-`Exp` strip path is unchanged (no
hyperbolic head → no `TrigToExp`), so the existing rectangular family is
unaffected.

**Outcome: `Method -> "Residue"` now evaluates the log-keyhole with a

### `Arg` of root-of-unity-like constants (`src/complex.c`)

`Arg[(-1)^(1/6)]` and friends were left **unevaluated**: the generic `a + b I`

such a constant, so any residue sum over those poles produced an `Arg`-salad no
simplifier could collapse.

real-rational powers and the imaginary unit — `(-1)^(1/6) → Pi/6`,
`-(-1)^(5/6) → -Pi/6`, `(-8)^(1/3) → Pi/3`, `I (-1)^(1/4) → 3 Pi/4` — by adding
arguments mod `2 Pi` across the factors (`arg = ([c<0] + Σ eᵢ[bᵢ<0]) Pi`) and
reducing into `(-Pi, Pi]`.  Purely structural and provably correct: a free
symbol, an inexact real, or a non-root-of-unity Gaussian (`Sqrt[3] + I`) declines
and falls through to the existing `ArcTan`/unevaluated path untouched.

### Non-integer-power keyhole-with-log (`src/calculus/integrate_residue.c`)

For `p ∉ ℤ` the branch factor `z^p` jumps across the cut, so `1 − e^{2πi p} ≠ 0`
and the keyhole of `z^p (Log z)^m R(z)` gives the lower-triangular system

```
(1 − e^{2πi p}) I_k = 2πi T_k + e^{2πi p} Σ_{j<k} C(k,j) (2πi)^{k−j} I_j,
T_k = Σ_l Res[z^p (Log z)^k R, z_l]   (keyhole branch arg ∈ [0,2π)),
```

solved upward from `I_0` (the `k=0` row is the plain keyhole/Mellin value).  New

order-≥2 shifted form, carrying both `(1+w/z)^p` and the shifted log);
`residue_family_mellin_log` dispatches integer `p ≥ 0` to the existing `a=0`
`(Log z)^{k+1}` contour and non-integer `p` to the new system.

## Residue `Integrate`: parametrized-contour family + essential-singularity residues ; v0.271

**Outcome: `Method -> "Residue"` now evaluates a parametrized contour integral
over a full period, `Integrate[g(c Exp[I t]) (I c Exp[I t]), {t, 0, 2 Pi}]`,
including integrands with an essential singularity.** Examples now solved:

### `residue_family_contour_param` + `res_ess0` (`src/calculus/integrate_residue.c`)

The substitution `t -> -I Log[u]` (so `Exp[I t] -> u`, `Exp[-I t] -> 1/u`) turns
the whole `t`-integral into the contour integral of `G(u) = integrand/(I u)`
around `|u| = 1`, hence `2 Pi i Sum_{|u_k|<1} Res[G, u_k]` -- the same transform
`residue_family_trig` uses, but for a transcendental `G` (an essential
singularity, or an Exp/trig-of-(1/u) kernel) that is not rational in `u`, which
the trig family declines on.  Wired after `residue_family_trig` in the
full-period branch, gated on the integrand carrying `Exp` (stored `Power[E,.]`)
so the common rational-trig path is untouched.

`res_ess0` computes the residue at an essential singularity at `0` as the `w^1`
coefficient of `Series[G /. u -> 1/w, {w, 0, 1}]` (the Laurent `u^{-1}`
coefficient); for an ordinary pole at `0` of an entire-in-`u` integrand
(`Exp[2u]/u^4`) the ordinary `residue_compute` runs first (the `1/w` substitution
would turn `Exp[2u]` into the essential `Exp[2/w]`).  `u = 0` is always a
candidate pole (the `1/u` kernels put a singularity there that is not a
polynomial-denominator root); a denominator root equal to `0` is de-duplicated
against it (it was otherwise double-counted -- caught as `16 E - 256/3` instead
of `16 E - 128/3`).  The contour value is genuinely complex, so the finite-scalar
gate applies, not the real gate.

Case 9's literal `z \[Element] Circle[...]` contour spelling remains out of
scope (no named-character / region-iterator parsing); its mathematics is

## Residue `Integrate`: unit-circle trig with symbolic parameters (Case 16) ; v0.272

**Outcome: `Method -> "Residue"` now evaluates `Integrate[R(Cos x, Sin x), {x,0,2π},
Assumptions -> ...]` with symbolic parameters, including a higher-order pole and a
coupled assumption.** `Integrate[1/(a+b Cos[x])^3, …, a>b>0] =
π(2a²+b²)/(a²−b²)^(5/2)` (Case 16); `1/(a+b Cos[x]) → 2π/√(a²−b²)`.

### Coupled-assumption instantiation (`build_instantiation`, `src/calculus/integrate_residue.c`)

The symbolic-parameter mode reads pole signs at a representative point of the
assumption region.  `absorb_fact` reduces only INDEPENDENT numeric bounds, so a
coupled constraint like `a > b > 0` (where `a` is bounded by `b`, not a number)
left `a` "unconstrained" and declined.  When that happens, `build_instantiation`
now falls back to `FindInstance[assumptions, {params}]` for one consistent point
(e.g. `{a->1, b->1/2}`); the per-parameter intervals are then unknown, so the
mellin/sector families (which gate on them) still decline, while the unit-circle
family — which only classifies poles at the point — proceeds.  This alone fixes
the order-1 symbolic case.

### Analytic-part residue for a parametric higher-order pole (`residue_family_trig`)

`solve_roots` de-duplicates a multiple root to one representative, and the
generic residue engine's Laurent series is pathologically slow for a symbolic
RADICAL pole — `Residue` of the order-3 pole at `(-a+√(a²-b²))/b` is >30s and its
cost explodes with the radical's surface form (`√(4a²-4b²)` ~30× slower than
`√(a²-b²)` for the same value).  The symbolic branch instead:
- recovers each pole's order with `pole_order` (counting the leading vanishing
  derivatives of the denominator at the instantiated root);
- takes the residue by the analytic-part derivative
  `Res = (1/(m-1)!) d^{m-1}/dz^{m-1}[ N / (lead ∏_{r≠z₀}(z-r)^{m_r}) ]|_{z₀}`,
  building the pole-free denominator from the distinct roots and their orders
  (~0.1s, no Series);
- simplifies each residue, sums, and closes with `Simplify[2πi S]` (real under
  the assumptions).

The numeric trig family is unchanged (its `solve_roots`/`residue_compute` path
is already correct and cheap), and a `1/(2+Cos[x])^2 = 4π/(3√3)` regression pins it.
