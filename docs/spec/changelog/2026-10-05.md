# Changelog: week of 2026-10-05 (Mon) – 2026-10-11 (Sun)

## `Simplify` — Sqrt-local trig radicand preparation ; v0.335

Fourth step of the assumed-trig campaign. A `Sqrt[R]` whose radicand `R` is not
yet a perfect square is now rewritten toward one with the unconditional
double-angle / half-angle / reciprocal-Pythagorean identities, then the
v0.332–v0.333 extraction runs. 39/50 → **43/50**.

- New `sqrt_prepare_radicand` (`src/simp/simp_logexp_abs.c`): a memoized
  `ReplaceAll` of `1±Cos[2u] -> 2{Cos,Sin}[u]²`, `(1±Cos u)/2 -> {Cos,Sin}[u/2]²`,
  `Sec[u]²-1 -> Tan[u]²`, `Csc[u]²-1 -> Cot[u]²`, `1-{Cos,Sin}[u]² -> {Sin,Cos}[u]²`
  and the hyperbolic analogues. Called from `try_simp_sqrt_of_square` only when the
  plain/Times gates miss; the prepared node is committed **only if it actually
  became a perfect-square shape**, so a non-square radicand is never disturbed.
  `is_sqrt_node`, the walker gate, and `contains_sqrt_of_square` were widened to
  reach any `Sqrt`.
- This deliberately bypasses the round-loop complexity scorer, where
  `1+Cos[2x] -> 2Cos[x]²` is a *tie* (the `-` in `1-Cos[2x]` inflates its score, so
  only the minus form collapsed before): the collapse is done locally inside the
  Sqrt, where it enables the downstream Abs resolution, without altering the global
  canonical form of a bare `1+Cos[2x]`.
- **Soundness**: all preparation identities are unconditional (complex-valid); the
  subsequent `Abs` resolution is gated by the v0.332 sign oracle. A 2-element `Plus`
  pattern never matches a longer sum (`Sqrt[1+Cos[2x]+y]` unchanged), and a radicand
  whose base is not provably real is left intact (`Sqrt[1+Cos[2x]]` with no
  assumption unchanged); `Sqrt[(1-Cos x)/2] -> Sin[x/2]` verified against `N[]`.
- Regression + soundness tests: `tests/test_logexp_simplify.c`
  (`test_sqrt_double_angle_*`, `test_sqrt_half_angle_*`, `*_declines`).

## `Simplify` — symbolic-integer Pi periodicity ; v0.334

Third step of the assumed-trig campaign. `Sin[t + k Pi] -> (-1)^k Sin[t]` (and
`Cos`/`Sec`/`Csc` likewise; `Tan`/`Cot` with period `Pi`, no sign) now fire when
`k` is a provable integer-linear combination of integer-assumed symbols — the
`2n`, `2n+1`, `4n`, `2n-1`, … cases the existing coefficient-1 string rules
(`Times[n, Pi]` only) could not reach. 35/50 → **39/50**.

- New `trig_pi_shift_symbolic` + `pi_integer_coeff` + `pi_parity`
  (`src/simp/simp_assume_rewrite.c`), dispatched from `assume_structural_rewrite`
  for the six forward trig heads. The argument is split into its integer-`Pi`
  part `K·Pi` and the rest `t`; the sign is the parity of `K`.
- `pi_integer_coeff` is robust to nesting/ordering: it forms `k = term/Pi`
  (evaluated) and accepts iff the quotient is **Pi-free** and a provable integer
  — necessary because `2 n Pi` canonicalizes to the nested `Times[2, Times[Pi, n]]`,
  which a top-level factor scan would miss. `pi_parity` is even/odd/undetermined
  (sum ⇒ XOR of term parities), declining when the parity is not fixed.
- **Soundness**: `Sin[t + k Pi] = (-1)^k Sin[t]` is exact for integer `k` (entire
  function). Declines without an integer assumption (`Sin[x + 2 n Pi]` unchanged)
  and for non-integer multiples (`Sin[x + n Pi/2]` unchanged). The generic
  coefficient-1 `(-1)^n` string rule is untouched (parity-unknown ⇒ this helper
  declines).
- Regression + soundness tests: `tests/test_logexp_simplify.c` (`test_pi_period_*`).

## `Simplify` — generalized Sqrt perfect-square extraction ; v0.333

Second step of the assumed-trig campaign (see v0.332). `Sqrt[c · f₁² · f₂² · …]`
now extracts each **real** squared factor as `Abs[fᵢ]` (resolved to `±fᵢ` by the
v0.332 sign oracle), leaving the rest under the root →
`Sqrt[c · f²] = Sqrt[c] · Abs[f]`. 33/50 → **35/50**.

- Previously `is_sqrt_of_square` (`src/simp/simp_logexp_abs.c`) required the *entire*
  radicand to be a bare `Power[_, 2]`, so `Sqrt[2 Sin[x]²]` was left intact; the
  per-symbol string rule in `apply_assumption_rules` handled only a bare symbol base.
- New `is_sqrt_of_times_with_square` structural detector + a `Times`-radicand branch in
  `try_simp_sqrt_of_square` (factored through `resolve_sqrt_square_base`): partition the
  radicand into real squared factors `{fᵢ}` and a residual `T`, emit
  `(∏ resolve(fᵢ)) · Sqrt[T]`. The walker gate (`sqrt_of_square_walk`) and
  `contains_sqrt_of_square` were widened to admit the Times shape.
- **Soundness**: for real `f`, `f² ≥ 0`, so the principal-root split
  `Sqrt[f² · T] = Abs[f] · Sqrt[T]` holds for **any** sign of `T` (verified: `Sqrt[-2 x²]`
  with `x ∈ Reals → I Sqrt[2] Abs[x]`, matching `N[]` at `x = 3`). A factor whose base is
  not provably real stays under the root (`Sqrt[2 Sin[x]²]` with no assumption is unchanged).
- Regression + soundness tests: `tests/test_logexp_simplify.c` (`test_sqrt_coeff_square_*`,
  `test_sqrt_product_of_squares`, `test_sqrt_negative_coeff_square`,
  `test_sqrt_coeff_square_no_assumption_declines`).

## `Simplify` — deep sign oracle for Abs/Sqrt under interval assumptions ; v0.332

First step of a 50-case *assumed-trig* `Simplify` campaign (differences that reduce to
`0` only under quadrant/`Integers`/`Reals` assumptions); baseline **22/50**. This commit
wires a general **sign oracle** into the `Abs`/`Sqrt[_^2]` resolution path → **33/50**,
with no regressions.

- **Deep sign oracle** (`src/simp/simp_assume.c`: new `assume_sign_nonneg_deep` /
  `assume_sign_nonpos_deep`, declared in `src/simp/simp_internal.h`). Decides the sign of an
  *arbitrary* expression `g` under the assumptions in three strata: (1) the cheap `prov_*`
  provers; (2) a **structural decomposition of the pole-bearing trig family** —
  `sign(Sec)=sign(Cos)`, `sign(Csc)=sign(Sin)`, `sign(Tan)=sign(Cot)=sign(Sin)·sign(Cos)` —
  because the Reduce region oracle declines Tan/Cot/Sec/Csc and a `Sin/Cos` ratio just
  re-canonicalizes back to `Tan`; (3) a Reduce/CAD base case that proves `g ≥ 0` by showing
  `A ∧ g < 0` is **unsatisfiable** (the *direct* strict inequality — the trig-region oracle
  only recognizes a bare `Sin[x] < 0` atom, and the negated `Not[g ≥ 0]` form hits a general
  path that returns a spurious `False` on a half-bounded/sign-changing region, i.e. a wrong
  answer). Depth-guarded; gated to variables that appear in an inequality fact.
- **Call sites** (`src/simp/simp_logexp_abs.c`): `try_simp_abs` resolves `Abs[g] -> ±g`, and
  `try_simp_sqrt_of_square` resolves `Sqrt[g^2] -> ±g` in place. So e.g.
  `Simplify[Abs[Sin[x]] - Sin[x], 0 < x < Pi/2] -> 0`, `Simplify[Abs[Tan[x]] + Tan[x],
  Pi/2 < x < Pi] -> 0`, `Simplify[Abs[Sin[x]+Cos[x]] - (Sin[x]+Cos[x]), 0 < x < Pi/2] -> 0`,
  and the bound-shifting `Simplify[Abs[x-2], 0 < x < 1] -> 2 - x`.
- **Soundness controls**: `Abs` needs only nonneg *or* nonpos (never strict); an undecided
  sub-query declines (over-restricting is safe); no `PossibleZeroQ` — every `0` comes from a
  Reduce `False` (a proof) or an exact prover. Verified to DECLINE where the sign is not
  fixed: `Abs[Cos[x]]` on `0 < x < Pi` (flips at `Pi/2`), `Abs[Sin[x]]` on `x > 0`
  (unbounded), and with no assumptions.
- Regression + soundness tests: `tests/test_logexp_simplify.c`
  (`test_abs_*`, `test_sqrt_cos_squared_quadrant3`, three `*_declines` guards).

## `Simplify` — assumption-gated log/exp/trig identities ; v0.331

A 50-case log/exp `Simplify` stress corpus, every item of which should reduce to
`0` **only under its stated assumptions** (positivity, reality, integrality, or a
principal-value range), scored 40/50 at v0.330. Eight general, sound mechanisms
close the tractable gaps → **48/50**. Each is an exact rewrite — unconditional
where the identity is principal-value general, assumption-gated where
branch-correctness requires it — and every gated rule has a paired soundness
control (does nothing without its assumption, and refuses to fire in the wrong
region). No `PossibleZeroQ`; all `0`s come from exact transforms.

- **ArcCos logarithmic form** (`src/simp/trigsimp.c`: `exp_to_trig_rules`) — adds
  the reverse rule `Log[x + I Sqrt[1-x^2]] :> I ArcCos[x]`, the missing sibling of
  the existing ArcSin entry. Unconditional and sound (the identity is
  principal-value general, verified numerically at `x = ±2, ±0.5`), so
  `ArcCos[x] + I Log[x + I Sqrt[1-x^2]] -> 0` and `Log[x + I Sqrt[1-x^2]] - I
  ArcCos[x] -> 0` with or without assumptions. The forward `TrigToExp[ArcCos]`
  form (pinned by a regression test) is untouched.
- **Range-gated inverse-of-direct trig collapse** (`src/simp/simp_assume_rewrite.c`:
  `assume_structural_rewrite`, with a new `sr_proves_sle` non-strict bound helper) —
  `ArcSin[Sin[x]] -> x` on `-Pi/2 <= x <= Pi/2`, `ArcCos[Cos[x]] -> x` on
  `0 <= x <= Pi`, `ArcCot[Cot[x]] -> x` on `0 < x < Pi`, mirroring the existing
  `ArcTan[Tan[x]]` rule (each inverse is a bijection from exactly that strip).
  Soundness checked: off-range (`Pi <= x <= 2Pi`) and assumption-free inputs are
  left unchanged.
- **ArcCosh logarithmic form, gated `x >= 1`** (same file) — `ArcCosh[u] ->
  Log[u + Sqrt[u^2-1]]` when `u >= 1` is provable. Essential gate: the combined
  radical `Sqrt[u^2-1]` is branch-correct only on `[1, inf)` (residual `2.63` at
  `u = -2`), unlike the factored `Sqrt[u-1] Sqrt[u+1]` the forward table uses.
  Closes `ArcCosh[x] - Log[x + Sqrt[x^2-1]] -> 0` for `x >= 1`; leaves it for
  `x <= -1` and with no assumption.
- **Exp additive periodicity, gated `n` integer** (same file, integer bucket) —
  `E^(2 I Pi n + rest) :> E^rest` and the odd-multiple `E^(I Pi n + rest) :>
  (-1)^n E^rest`, so `E^(x + 2 I Pi n) - E^x -> 0`. The evaluator keeps `Exp[sum]`
  fused and does not know `n` is integer, so the peel must be assumption-gated.
- **Integer-exponent root-of-unity split** (same file) —
  `(-1)^(k + n) :> (-1)^k (-1)^n` for integer `n`, any `k`, so
  `(-1)^n + (-1)^(n+1) -> 0` and hence `Cos[n Pi] - E^(I n Pi) -> 0`.
- **Branch-gated `Sqrt[E^w] -> E^(w/2)`** (same file) — more generally
  `Power[E^w, r] -> E^(r w)` when `Im[w]` is provably in `(-Pi, Pi]` (the strip on
  which the principal `Log` recovers `w`, so the identity holds for *any* `r`).
  The `Im`-strip gate is decided by the `Reduce`/CAD entailment oracle. Closes
  `Sqrt[E^(2 I x)] - E^(I x) -> 0` under `-Pi/2 < x < Pi/2`; the sound
  counterpart of `PowerExpand`'s unconditional (strip-ignoring) collapse, so it
  stays unreduced off the strip.

Known gaps (documented, not shipped — each needs a search-ordering change or a
pattern-specific trusted rewrite that would carry regression risk disproportionate
to one corpus case): the compound complex half-angle `Log[1 + E^(I x)] =
I x/2 + Log[2 Cos[x/2]]` (`-Pi < x < Pi`), and `Log[(1+I x)/(1-I x)] = 2 I
ArcTan[x]` (`x` real) — for the latter, `TrigReduce` already produces the split
`Log[1+I x] - Log[1-I x]` but the search does not adopt the higher-complexity
split to let the ArcTan rule fold it.

Regression + soundness tests: `tests/test_logexp_simplify.c` (17 new cases,
`test_arcsin_sin_*`, `test_arccos_*`, `test_arccosh_log_*`, `test_exp_periodicity_*`,
`test_neg_one_power_split`, `test_cos_minus_exp_integer`, `test_sqrt_exp_*`,
including the no-assumption / wrong-region controls). No new user-facing messages;
no numeric/packed surface.

## `Simplify` — log/exp identities: log-power symmetry + constant complex powers ; v0.330

A 25-case log/exp `Simplify` stress corpus left two genuine, *general* gaps
(the rest already reduced, and the cases that correctly do **not** reduce bare —
e.g. `(E^x)^y - E^(x y)`, or `Log[x+Sqrt[x^2-1]] - ArcCosh[x]` for `x<-1` — stay
unreduced, as a sound simplifier must). Both are closed with general, sound
transforms; no one-off hacks, and every new rewrite is positivity/constant-gated
so it can never emit a false zero.

- **Power→exp normalization under positivity** (`src/simp/simp_power.c`:
  `transform_powbase_to_exp_assuming`) — rewrites `base^exp -> Exp[exp Log[base]]`
  and re-evaluates, exposing the log-power symmetry so it cancels:
  `x^Log[y] - y^Log[x] -> 0` and `a^Log[b] - b^Log[a] -> 0` under `x,y>0`.
  Two-sided gate (`prov_pos` on the base **and** every single-arg `Log` argument
  in the exponent): `base^exp = Exp[exp Log base]` needs only `base>0`, but the
  `E^(c Log a) -> a^c` reversion turns a `Log` argument back into a base, so a
  one-sided `y>0` assumption would assert the identity where it fails (`x=0`,
  `x<0`). Wired as a strict-`<` score-gated seed in `simp_pipeline_logexp` and
  `simp_search` (never the force-take `LogExpRules` path), so a non-cancelling
  standalone power (`x^Log[x]`) is left unchanged. Inert without positivity facts.
- **Constant complex-power fold** (`src/simp/simp_builtins.c`:
  `simp_const_cpow_fold`, in the polish tail after the qqbar fold) — a
  variable-free `Power[c1, c2]` with a non-positive-real base folds to its
  principal value `Exp[c2 Log[c1]]`, reusing the existing `Log[I] -> I Pi/2`,
  `Log[-1] -> I Pi` and `Exp[I q Pi]` closed forms: `I^I - E^(-Pi/2) -> 0`,
  `(-1)^I Exp[Pi] -> 1`, `I^(2 I) Exp[Pi] -> 1`. Scored at the **whole-expression**
  level (mandatory: `SimplifyCount[I^I]=7 < SimplifyCount[E^(-Pi/2)]=8`, so the
  collapse only pays off via the enclosing `Plus/Times`), so standalone `I^I`
  and surds like `(-1)^(1/3)` (idempotent under the fold) are preserved, and
  `2^I` (positive-real base) is skipped outright.

Regression + soundness tests: `tests/test_logexp_simplify.c`
(`test_logpow_symmetry_*`, including the one-sided-assumption and
standalone-idempotency guards) and `tests/test_power_corpus.c`
(`test_const_cpow_fold`). No new user-facing messages; no numeric/packed surface.

## `PossibleZeroQ` — two-symbol coupling inequalities under `Assumptions` ; v0.325

Fixes an unsound `False` in the assumption-aware zero recogniser
(`src/zero_test.c`): `PossibleZeroQ[Max[x, y] - x, Assumptions -> x > y]`
returned `False`, though `Max[x, y] - x` is identically `0` on `{x > y}`. The
`x >= y` variant failed the same way; found via a 20-case `Assumptions` stress
suite (the other 19 already passed).

- **Cause.** The Schwartz–Zippel sampler draws each free symbol independently
  from a per-symbol `SampleSpec`, which cannot encode a fact that **couples two
  symbols** (`x > y`). `fact_keeps_false_sound` treated *every* inequality as
  FALSE-preserving on the rationale that an inequality carves a full-measure
  region — but that is wrong for a **piecewise** head: `Max[x, y]` is a
  *different function* off the region, so sampling the whole space hits `x < y`
  points where `Max[x, y] - x = y - x ≠ 0`, and the sampler reported a
  non-identity.
- **Fix — region-conforming rejection sampling.** A coupling dense relation
  (`>`, `>=`, `<`, `<=`, `Inequality`, `Unequal`) that references ≥ 2 of the
  expression's free symbols and is groundable by the draw is collected into a
  `conform_facts` list; `sz_trial` then **re-draws** any assignment that lands
  outside the feasible region (`assignment_conforms` substitutes the draw and
  checks each relation numerically — no `Simplify`, no evaluator re-entry) up to
  `ZT_CONFORM_MAX_TRIES` (128). The tested points therefore lie strictly inside
  the assumed region, so `Max[x, y] - x` collapses to `x` (→ `True`) while a
  genuine non-zero there (`x - y`, `Max[x, y] - y`) still rejects (→ `False`).
  If the region is unhittable the point is skipped, and an all-skip screen
  returns an honest `Unknown`.
- **Soundness preserved.** A coupling *equality* (`a == b`) pins a measure-zero
  variety that rejection sampling cannot hit, so it keeps the existing
  `False → Unknown` downgrade (returns `True`); `Refine[x == y, x > y]` stays
  `False`. The new path engages **only** when a ≥ 2-symbol coupling inequality
  is present, so the draw stream — and every verdict — for all other inputs is
  byte-for-byte unchanged.
- **Tests.** New `test_pzq_coupling_relations` group in
  `tests/test_possiblezeroq_assumptions.c`; the full 20-case suite now scores
  20/20. `zero_test_tests`, `possiblezeroq_stress_tests`, `comparisons_tests`,
  `refine_tests`, `reduce_tests`, `fullsimplify_tests`, `simplify_hang_tests`
  all pass unchanged.

## `PossibleZeroQ` — huge-scale deep-cancellation false-negative ; v0.324

Fixes a silent wrong answer in the hybrid zero recogniser (`src/zero_test.c`,
`POSSIBLE_ZEROQ_IMPROVEMENTS.md` #5): an identically-zero expression whose two
terms are astronomically large — e.g.
`PossibleZeroQ[Cosh[14]^30 - (1 - Tanh[14]^2)^(-15)]`, where the terms are equal
because `1 - Tanh^2 = Sech^2 = 1/Cosh^2` — returned `False`.

- **Cause.** At a huge operand scale, a `(1 - near-1)` subtraction inside
  `Tanh`/`Cosh`/… loses far more than the 52-bit machine mantissa, so the
  machine-precision residual of a genuine cancellation **zero** is a large
  fraction of the operand scale — above the `ZT_OBVIOUS_NONZERO_BITS` (2^-12)
  gate. Both `decide_numeric` (symbol-free inputs) and `screen_point` (the
  Stage-3 Schwartz–Zippel sampler) **trusted that machine `FALSE` directly,
  without climbing the precision ladder** — a wrong answer. Empirically a
  cancellation zero and a genuine small non-zero (`… + 1`) leave *bit-identical*
  residuals through 500 bits; they diverge only at the 1000-bit rung, so machine
  precision cannot adjudicate this at all.
- **Fix.** A new scale gate `ZT_HUGE_SCALE_BITS` (2^40): at or above it, a
  residual that trips the obvious gate is sent to `decide_numeric_huge_scale`
  instead of being fast-rejected. That helper climbs the full MPFR ladder
  (200 → 500 → 1000 bits) and trusts the residual's **trend** — a first *plateau*
  (`m >= prev/2`) means the genuine value has resolved at that rung (so a huge
  non-zero with no cancellation rejects after a single extra evaluation); a
  residual that keeps *shrinking* to the top rung trusts that rung's floor, which
  (~`scale·2^-(1000-30)`) is finally tight enough to tell a true small value from
  zero. `screen_point` returns `UNKNOWN` at huge scale so `sz_trial` escalates
  the point to that ladder rather than settling a spurious whole-test `False`.
  Below 2^40 the machine fast path is byte-for-byte unchanged.
- **Verified.** The reproducers (`Cosh[27/2]^20-(1-Tanh[27/2]^2)^-10`, and the
  k15/k20/k10 variants) flip `False → True`; the genuine controls stay `False`
  — `… + 1` (resolves at the top rung) and the huge `… + …` SUM (plateaus at
  rung 1); the flagship Weierstrass round-trip
  `D[∫ Cosh[x] Cosh[2x] dx] - Cosh[x] Cosh[2x]` stays `True` (now robustly, not
  by draw-order luck); moderate-scale hyperbolic identities, all Group 1–19
  cases, and the `make check-messages` gate are unchanged. The huge-scale climb
  is cheap (huge *values*, small *trees*): 24 distinct huge-scale decisions and
  the §2.2.5 `y''+x y'+y==0` solve are each sub-10 ms. Tests:
  `tests/test_zero_test.c` Group 20.

## `PossibleZeroQ` — numeric-function magnitude-decline re-draw ; v0.323

Fixes a silent wrong answer in the hybrid zero recogniser (`src/zero_test.c`,
`POSSIBLE_ZEROQ_IMPROVEMENTS.md` #4): `PossibleZeroQ[PolyLog[2, x^2] + 1]`
returned `True` for a function that is nowhere zero.

- **Cause.** A numeric special function can *decline* past its numeric window and
  hand back its own unevaluated head on numeric arguments — `N[PolyLog[2, z]]` for
  `|z| >~ 300` returns `PolyLog[2.0, z]`. In the Stage-3 Schwartz–Zippel sampler
  that surfaced as a non-pure-numeric residue, which the sampler treated as
  genuinely undecidable and used to **abort the whole test to `UNKNOWN → True`** on
  the first such point — a wrong, draw-order-dependent verdict.
- **Fix.** A declined residue is a numeric coordinate the evaluator *can* compute
  at a smaller argument, so it is now re-drawable exactly like an IEEE overflow. A
  new predicate `residue_is_numeric_decline` recognises a residue built only from
  `ATTR_NUMERICFUNCTION` heads on numeric arguments; `evaluate_rung` flags it and
  `sz_trial_shelled`'s magnitude-shell ladder shrinks the sample to a resolvable
  point, which then decides `FALSE`. An *undefined* head carries no
  `ATTR_NUMERICFUNCTION`, so it stays a genuine residue and the `UNKNOWN → True`
  trip-wire is preserved. The fix is generic over numeric heads (`PolyLog`,
  `PolyLog[3, …]`, …); `Gamma`, the backlog's original example, no longer declines
  (it returns a finite extended-range value already handled by the v0.208
  IEEE-overflow re-draw).
- **Verified.** A/B against a pre-change binary: `PolyLog[2, x^2]+1`,
  `PolyLog[2, x^2]+5`, `PolyLog[3, x^4]+1` flip `True → False` (correct); the
  identity `PolyLog[2, x^2] - PolyLog[2, x^2]` stays `True`; `Gamma[x^2]+1`,
  `E^(-10 t)+E^(-100 t)`, `Sin[x]^2+Cos[x]^2-1`, and the `UndefinedZQHead`
  trip-wire are unchanged. Tests: `tests/test_zero_test.c` Group 19. No regression
  across the zero-test, `possiblezeroq_*`, `trigexp_zero`, `comparisons`,
  `simplify`, `solve`, `limit`, `refine`, and `interp` suites.
- Backlog #5 (deep-cancellation screen `FALSE`) was re-investigated in the same
  pass and found non-reproducing on `HEAD`; a prototype guard changed no verdict
  and was not shipped. (Subsequently **RESOLVED in v0.324** once a deterministic
  reproducer was constructed — see the v0.324 entry above.)

## `Reduce` / CAD / QE — deficiency campaign ; v0.319–

Driven by `tasks/reduce_deficiencies.md` (six REPL-verified weaknesses D1–D6
surfaced by the `Minimize` campaign II). Every change is fully general and
preserves the sound-or-decline invariant (a wrong formula is never emitted; an
out-of-reach input stays unevaluated). The `Minimize` constrained-QE scaffold
(v0.318) routes into these paths, so each gain is picked up with no change to
`Minimize` itself.

- **v0.319 — `Reduce[expr]` and `Reduce[expr, dom]` now behave as in Mathematica
  (closes D1+D2).** The 1-arg form and the 2-arg domain form were silently
  broken: the 2-arg form treated a domain symbol (`Reals`/`Complexes`/`Integers`/
  `Rationals`) in the second slot as the *sole variable*, so it returned
  unevaluated or a half-processed wrong form (`Reduce[x^2<1, Reals]` → unevaluated
  instead of `-1<x<1`; `Reduce[x^2==1, Complexes]` → `-1+x^2==0` instead of
  `x==-1||x==1`), and the 1-arg form bailed outright. Both now **infer the free
  variables of `expr`** (all free symbols, excluding named constants like `Pi`,
  domain symbols, and reserved literals; sorted alphabetically to match the
  explicit var-list form) and recognise a domain symbol in the last positional
  slot, dispatching to the already-correct 3-arg engine. This subsumes the D2
  "emptiness" deficiency outright — `Reduce[x+y+z==1 && x>=0 && y>=0 && z>=0 &&
  x^2+y^2+z^2>4, Reals]` now decides `False` directly, matching
  `Resolve[Exists[…]]`. A constant statement still short-circuits to True/False;
  the explicit `Reduce[expr, x]` / `Reduce[expr, {x,y}]` variable forms and the
  `Reduce::ivar` diagnostic are unchanged. `src/solve/reduce.c`
  (`reduce_is_domain_symbol`, `reduce_infer_var_list`, arg-bind rewrite);
  leak-verified (no new blocks over the fixed-init baseline).

- **v0.320 — CAD is preemptible by `TimeConstrained` (closes D6).** The CAD C
  loops never polled the abort flag, so a single hard `Reduce[…, Reals]` probe
  overran its `TimeConstrained` budget (the inner projection / lifting / cell
  loops only yielded at sub-`evaluate()` boundaries, and a signal/jump there would
  unwind through — and leak — the CAD's PolySets / regions / root arrays). Added a
  **non-jumping** `tc_deadline_passed()` (core.c) that a throttled `CAD_POLL()`
  (one monotonic-clock read per 64 iterations, only inside a `TimeConstrained`
  scope) checks at every CAD loop head in `reduce_cad.c`; on an expired deadline
  the loop **clean-returns NULL through the engine's existing decline path**,
  freeing every local — so `Reduce` yields promptly with **no new leak** on that
  path, instead of being unwound mid-frame. The normal, unconstrained path is
  byte-identical (the poll short-circuits to false with no clock read). Verified:
  the degree-6 three-variable certificate that used to grind now returns under a
  2 s budget. Also fixed a latent correctness bug this surfaced — a timeout
  `siglongjmp` out of `builtin_reduce` skipped its `mth_msg_ifun_suppress_pop`,
  silencing `Solve::ifun` session-wide; the ifun depth is now saved/restored
  across the unwind by `tc_run_guarded` (core.c/message.c), mirroring the existing
  `Quiet`/Block guards. Residual (pre-existing, unchanged): a deadline elapsing
  *inside* one large nested `evaluate()` (e.g. a single giant `Resultant`) still
  unwinds via the eval-loop jump and abandons that frame — a bounded, rare
  abort-only leak inherent to `siglongjmp`, which the new loop-head polls strictly
  reduce rather than add to.

- **v0.322 — SOS / Positivstellensatz emptiness certificate (closes D5).** A new
  `src/solve/reduce_sos.c` stage proves a real region EMPTY (→ `False`) when the
  CAD hits its algebraic-degree wall, via an exact rational sum-of-squares
  certificate. For a region `{g_i >= 0, h_j == 0, q < 0}` it certifies `q >= 0`
  on `{g_i >= 0, h_j == 0}` by a Putinar representation
  `q = σ₀ + Σ σ_i g_i` (mod the equality ideal) with each σ an SOS. The Gram
  matrices are found NUMERICALLY (an SDP by alternating projection onto the PSD
  cone — eigenvalue-floor clamp for a strictly-interior point — and the
  coefficient-matching affine subspace, via LAPACK), then **rounded to rationals
  and the whole identity + PSD-ness re-verified in EXACT `mpq` arithmetic**
  (rational LDL^T). The pathological **interior-zero** case (the certificate sits
  on the PSD boundary, unroundable) is handled by **facial reduction**: the zero
  `x*` is found by numeric minimisation, verified rational+exact, and every basis
  monomial is shifted by its value at `x*` so the reduced SDP is strictly
  feasible. Only a fully-verified certificate returns `False`; every other outcome
  declines (NULL) — it is **sound by construction** (the final check is exact) and
  never emits a solution set. Runs BEFORE the CAD (it fast-declines any shape
  without a strict polynomial inequality, and the cases it targets are exactly the
  ones the CAD grinds on). Needs LAPACK; degrades to a clean decline without it.

  baseline); soundness confirmed on a sweep of non-empty regions (never `False`).

- **v0.321 — quantifier elimination gets the Phase-6e well-orientedness retry

  augmentation, so any positive-dimensional McCallum fibre *nullification* was an
  instant decline — while the plain-`Reduce` driver `reduce_cad_nvar` has long
  wrapped `cad_build` in an augment-and-retry loop (add the offending factor's
  coefficients to the level below, re-derive the lower projection stack, retry;
  bounded to a few rounds). QE was therefore *strictly more fragile* than plain

## `Minimize` / `Maximize` — campaign II (21-40 stress suite) ; v0.313–v0.318

A second 20-problem stress suite (examples 21–40) drove this pass. Baseline
(v0.312): 4 solved, 4 timeouts, 12 declines, **zero wrong answers**. Every phase
below preserves the soundness invariant (adds an exact-oracle-checked proof path
or declines — never guesses) and is independently version-bumped.

- **v0.313 — separable / additive decomposition (unconstrained).** An
  unconstrained objective that splits into variable-disjoint blocks
  `f = Σ gᵢ(blockᵢ)` is minimised block-by-block and summed: the infimum of a sum
  over disjoint variable sets is the sum of the infima. This sidesteps the
  multivariate lower-bound certificate (the CAD's algebraic-coefficient wall) for
  a separable objective — each block is solved by the already-sound univariate /
  critical-point engine. `Minimize[(x⁴-16x²+5x)+(y⁴-16y²+5y), {x,y}]` (separable
  Styblinski-Tang) went from a **>60 s timeout to ~16 ms** (a `Root` value, both
  blocks at the same minimiser). `mz_separable_min` + the `mz_unconstrained_min`
  dispatcher; a union-find over the additive terms' variable supports partitions
  the blocks, an unbounded block propagates `-Infinity`/`natt`.

- **v0.314 — general compact-region extreme-value shortcut.** The v0.306
  single-equality shortcut is generalised to ANY compact (bounded + closed)
  feasible region: on a compact region a continuous `f` attains its minimum, and
  by Fritz–John every extremum is a REGULAR KKT point (already enumerated) or a
  SINGULAR point of some active set (its constraints satisfied with a
  rank-deficient Jacobian — all `nact×nact` minors vanish, enumerated by
  `mz_add_singular_candidates`). Those together COMPLETE the candidate set, so the
  least feasible candidate is the global minimum and the Reduce lower-bound
  certificate is skipped — dodging the algebraic-coefficient / degree wall. New:
  `Minimize[{x+y+z, x²+y²+z²==4 && (x-1)²+y²==1}, {x,y,z}]` (Viviani curve, two
  equalities) -> an exact `Root` value in ~45 ms (was a 1.8 s decline);
  `Minimize[{x⁶+y⁶+z⁶-xyz, x+y+z==1, x≥0,y≥0,z≥0}, {x,y,z}]` -> `-8/243` in ~0.4 s
  (was a >60 s timeout). The shortcut is tried BEFORE the certificate (which does
  not fail fast on a high-degree region), fires only when the closure is provably
  bounded (a single large-radius `Resolve[Exists[region && Σx²>2²⁰], Reals]`
  probe — existential QE decides where plain `Reduce` leaves a 3+-variable
  equality region unevaluated) and every regular + singular solve is clean.

- **v0.315 — equality-constraint variable elimination.** When an equality pins a
  bare variable to an expression free of it (`v == h`, `h` free of `v`), `v` is
  substituted out of the objective and remaining constraints, dropping the
  dimension, and the reduced problem is solved (the reported point reconstructs
  `v = h`). `Minimize[{(x-1)²+(y-2)²+(z-3)², x==t && y==t² && z==t³}, {x,y,z,t}]`
  (point-to-twisted-cubic distance) collapses to a univariate problem in `t` and
  solves in ~2 ms (was a >60 s timeout). `mz_eliminate_solve`.

- **v0.316 — rational-function objectives.** A rational objective `f = p/q` is
  reformulated as the polynomial problem `Minimize[w, cons && p - w*q == 0 &&
  q(>|<)0]` over `{vars, w}`, reusing `mz_exact_poly` whole, then stripping `w`.
  The equivalence `p/q == w ⟺ p - w*q == 0` holds wherever `q != 0`; proving `q`'s
  strict definite sign on the closure selects that branch and excludes the `q==0`
  locus. `Minimize[{x²y²/(x²+y²+1), x²+y²>=1}, {x,y}]` -> `{0, {x->0, y->-1}}`;
  `Minimize[x²/(x²+1), x]` -> `{0, {x->0}}`. A denominator of indefinite sign on
  the closure (boundary poles, e.g. `1/x+1/y+1/z` on the open simplex) is a sound
  decline. `mz_rational_solve`.

- **v0.317 — Integers: parametric Diophantine + coercive minimisation, and the
  `Element` spelling.** `Element[{vars}, Integers]` in the CONSTRAINT list is now
  read as a domain declaration when it covers every variable (a PARTIAL
  membership is mixed integer/continuous and stays a decline, never silently
  all-integer). An infinite parametric family from `Solve[cons, vars, Integers]`
  is handled by substituting it into the objective to get a polynomial `Q` over
  the free parameters `C[k]`; a coercive `Q` has its integer minimum found by
  bounding the ellipsoid `{Q <= B}` (`B` = `Q` at the rounded continuous
  minimiser) and enumerating it. `Minimize[{x²+y²+z², 5x+7y+11z==13,
  Element[{x,y,z},Integers]}, {x,y,z}]` -> `{3, {x->-1, y->1, z->1}}`.
  `mz_integer_parametric`, `mz_strip_domain_element`.

- **v0.318 — constrained positive-dimensional / general unboundedness via QE.**
  `mz_qe_infimum` is generalised from unconstrained to constrained: the infimum
  is read off `Reduce[ForAll[{vars}, Implies[cons, f>=b]], {b}, Reals]`, a witness
  is realised by `FindInstance[cons && f==b*, vars, Reals]` and verified to BOTH
  attain `b*` and satisfy the constraints (the inf-vs-min attainment gate — no
  witness ⇒ decline, never report an un-attained infimum). It fires only after
  the KKT engine declines and a non-polynomial objective declines at the QE gate
  (so no cost there). This settles the cases the CAD can decide — e.g.
  `Minimize[{x+y, x<=y²}, {x,y}]` is now `-Infinity` (unbounded below over the
  region) rather than a decline. Constrained positive-dimensional minima whose
  `Reduce[ForAll[…]]` the engine cannot yet eliminate (e.g. `xw-yz` on the
  4-ball) remain sound declines until the CAD/QE engine strengthens.

Deferred (sound declines, out of exact-algebraic scope): mixed integer/continuous
programming, transcendental objectives/constraints, unconstrained sums of
multivariate radicals.

  an exact answer in ~3 s instead of declining. The shortcut fires only when both
  the regular and singular solves are clean and the region is provably bounded
  (resting on the `solvenlsys` "complete-or-decline" contract); any gap falls
  through to the certificate, and a positive-dimensional minimizer set (e.g.
  `x^2+y^2==1`, where the whole circle is optimal) still declines. All coefficients
  in the shortcut's probes are rational, so it never meets the CAD's
  algebraic-coefficient wall.

- **v0.307 — radical-cleared lower-bound certificate.** The general fallback for
  irrational-algebraic optima that the compact shortcut does not cover
  (inequality-constrained, multi-equality, non-compact-but-attained). When the
  candidate optimum `bestv` carries radicals, the certificate `cons => f >= bestv`
  is proved by replacing each radical `Power[c, p/q]` (`c` a positive constant)
  with a fresh variable pinned by `u^q == c && u >= 0` and reducing the resulting
  **rational-coefficient** system over the enlarged variable set — logically
  identical to the original, but decidable where the CAD declined on the
  algebraic coefficient. Repeated radicals are deduplicated (a second CAD variable
  blows the certificate up), the direct certificate is skipped entirely when
  radicals are present (it would waste the budget), and a `Root[]`-valued optimum
  that cannot be cleared falls through to the direct certificate (sound: an
  unprovable bound declines). New: `Minimize[{x^2+y^2, (x-2)^2+(y-3)^2 <= 1}, {x,y}]`
  -> `14 - 2 Sqrt[13]` (was unevaluated). The rational-optimum path and the working
  `-Sqrt[2]` disk-LP case are unchanged.

- **v0.308 — radical / fractional-power objectives and constraints.** A new
  objective- and constraint-side radical pass polynomializes the problem before
  dispatch: each `Power[g, p/q]` (q >= 2) is rewritten as `u^p` with fresh real
  constraints `u^q == g && u >= 0`; since `u >= 0 && u^q == g` forces `g >= 0`,
  this restricts to exactly where the real principal branch is defined (Mathilda's
  `Power[g, p/q]` is complex for `g < 0`), preserving both value and domain.
  Nested radicals are cleared inside-out and identical radicals are deduplicated;
  the fresh variables are appended to the variable list and stripped from the
  reported point. New (well-formed syntax `Minimize[{f, cons}, vars]`):
  `Minimize[{Sqrt[x+Sqrt[x]]+Sqrt[x-Sqrt[x]], x>=1}, x]` -> `{Sqrt[2], {x->1}}`;
  `Minimize[{Sqrt[x]+Sqrt[y], x+y==2}, {x,y}]` -> `{Sqrt[2], {x->0, y->2}}`;
  `Minimize[Sqrt[x^2+1], x]` -> `{1, {x->0}}`.
  Limitation: a fractional power whose substitution raises the constraint degree
  beyond the CAD's reach still declines — e.g. `x^(2/3)` with `x^4+y^4<=1`
  substitutes to degree 12 (`a^12+b^12`), which the real CAD cannot settle, so
  `Minimize[{x^(2/3)+y^(2/3), x^4+y^4<=1}, {x,y}]` is left unevaluated (sound
  decline, not a wrong answer).

- **v0.309 — univariate `Abs` / piecewise-polynomial objectives.** A univariate
  objective that is piecewise-polynomial through `Abs[g]` terms (`g` polynomial)
  is smooth on each sign cell of the `g`'s, so its global minimum is attained at a
  breakpoint (a real root of some `Abs` argument) or at a stationary point of a
  piece. The engine evaluates the original objective at `{breakpoints} ∪ {real
  roots of each piece's derivative}` and takes the exact least — sound because
  every candidate is a genuine real point and the true minimiser is always in the
  set; it avoids the O(2^terms) blow-up the active-set LP/epigraph reformulation
  would hit (one `Abs` term = two inequalities, past `MZ_MAX_INEQ` almost at
  once). Unboundedness is read off the two end pieces' leading terms. New:
  `Minimize[Sum[Abs[x-i^2], {i,1,10}], x]` -> `{275, {x->25}}`;
  `Minimize[x^2+Abs[x-2], x]` -> `{7/4, {x->1/2}}`;
  `Minimize[Abs[x]-x, x]` -> `{0, {x->0}}`; `Minimize[2x+Abs[x], x]` -> unbounded.
  Pieces are evaluated after sign resolution so an identically-zero cell
  (`-x+x`) collapses to the constant 0 and is handled, not mistaken for a
  degenerate polynomial.

- **v0.310 — exact `Integers`-domain optimization over a bounded region.**
  `Minimize[{f, cons}, vars, Integers]` (and `Maximize`) now solves integer
  programs over a finite feasible set, by two routes: (1) the Diophantine
  enumeration `Solve[cons, vars, Integers]` for equality regions, and (2) a box
  enumeration for inequality regions, where each variable's range is bounded by
  the continuous relaxation (`Ceiling`/`Floor` of the Reals min/max) and the box
  is then enumerated exactly with a per-point feasibility test. New:
  `Minimize[{x+y, x^2+y^2==25}, {x,y}, Integers]` -> `{-7, {x->-4, y->-3}}`;
  `Minimize[{x^2+y^2, x+y>=3 && 0<=x<=5 && 0<=y<=5}, {x,y}, Integers]` ->
  `{5, {x->2, y->1}}`; `Maximize[{x y, x^2+y^2==25}, {x,y}, Integers]` ->
  `{12, ...}`. Both routes are sound (exact enumeration, exact comparison).
  **Honest scope / declines:** an unconstrained integer objective (no bound), a
  region the continuous relaxation cannot bound, a parametric/infinite integer
  family, or a box past the size cap all **decline** rather than guess — so the
  research-frontier Diophantine stress cases stay unevaluated (e.g.
  `x^3+y^3+z^3==33`, whose smallest solution has ~16-digit components, declines
  within the time budget; the Mordell `Abs[x^3-y^2]` over `x>10 && y>10` declines
  because the region is unbounded). Mixed integer/continuous problems (only some
  variables integer) are out of scope: all variables are taken integer.

- **v0.311 — per-call time budget (not just per-probe).** The v0.305 budget
  bounded each internal `Solve`/`Reduce` probe, but a problem with many probes
  (active-set enumeration, the radical/fractional-power polynomialization's extra
  equalities, the integer box's `2n` continuous bounds) could still cost
  `TimeConstraint × probes`. Each multi-probe path (`mz_exact_poly`,
  `mz_univar_piecewise`, `mz_integer_box`/`mz_integer_opt`) now anchors a
  `clock()` deadline and hands each probe only the *remaining* budget, declining
  once it is spent — so the whole call is bounded by `TimeConstraint`. This fixes
  a responsiveness regression the v0.308 radical path introduced:
  `Minimize[{x^(2/3)+y^(2/3), x^4+y^4<=1}, {x,y}]` (which polynomializes to a
  degree-12 CAD) now declines within the budget instead of running for minutes.
  An incomplete enumeration on a spent deadline declines (never reports a
  partial-candidate minimum), preserving soundness.

- **v0.312 — positive-dimensional (flat-valley) unconstrained minima via real
  QE.** `Minimize[(x y - 3)^2 + 1, {x, y}]` returned *unevaluated*: its
  minimizer set is the whole hyperbola `x y == 3`, so the gradient system
  `∇f == 0` has infinitely many real solutions and `Solve` declines with
  `Solve::nsdim` — leaving the isolated-critical-point method (`mz_exact_poly`)
  with zero candidates, which for an *unconstrained* problem fell through to a
  silent `NULL`. New fallback `mz_qe_infimum` (`src/calculus/minimize.c`): when
  the critical-point method finds no isolated candidate, read the global infimum
  directly off real quantifier elimination,
  `Reduce[ForAll[{vars}, f >= b], {b}, Reals]` — a single bound `b <= v` pins the
  infimum `v` (possibly an algebraic `Root`). A minimiser is realised by one of
  two verified strategies: **(a)** `FindInstance[f == v, {vars}, Reals]` (fast
  when `v` is rational / a simple surd), else **(b)** pin every variable but one
  to a trial constant and recursively minimise the *univariate* polynomial
  slice — the univariate optimiser returns a clean single-`Root` minimiser,
  whereas `Solve[f_slice == v]` would hand back a *nested* `Root` the engine
  cannot zero-test. Either way the point is verified to attain `v` exactly
  (`rru_sign_compare(f(pt), v) == 0`).
  `Minimize[(x y - 3)^2 + 1, {x, y}]` -> `{1, {x -> -1, y -> -3}}` (strategy a);
  `Minimize[(x y - 3)^4 - x y + 1, {x, y}]` -> `{Root[256 #^3 + 1536 #^2 + 3072 #
  + 2075 &, 1], {x -> Root[4 #^3 - 36 #^2 + 108 # - 109 &, 1], y -> 1}}` (an
  algebraic infimum, strategy b);
  `Minimize[(x^2 - 2 y)^2 - x^2 + 2 y - 1, {x, y}]` -> `{-5/4, {x -> 0, y ->
  -1/4}}`; `Minimize[(x + y - 2)^2, {x, y}]` -> `{0, {x -> 0, y -> 2}}`. An
  objective unbounded below (QE returns `False`, e.g. the saddle `x^2 - y^2`)
  now reports `{-Infinity, {x -> Indeterminate, ...}}` with `Minimize::natt`
  instead of declining; `Maximize` reaches this on `-f`, so a flat-valley
  maximum unbounded above gives `{Infinity, ...}`. Soundness is unchanged: `v`
  comes from the same `Reduce`/CAD oracle the lower-bound certificate trusts, the
  witness is verified, and any "don't know" (`Reduce` unevaluated, no real
  witness, a 3-variable query past the CAD) declines. Scoped to the
  **unconstrained** case; constrained and non-attained positive-dimensional
  minima remain deferred.

## `Minimize` / `Maximize` — exact (symbolic) global optimization ; v0.304

**Outcome: two new builtins. `Minimize[f, x]`, `Minimize[f, {x, y, ...}]`,
`Minimize[{f, cons}, vars]` and `Minimize[..., dom]` (and the `Maximize` pair)
find an EXACT global optimum, returning `{f_opt, {x -> x_opt, ...}}` with exact
Integer / Rational / radical / `Root[]` values. Examples now evaluated:
`Minimize[2x^2-3x+5, x]` -> `{31/8, {x -> 3/4}}`;
`Minimize[Expand[(x-1)(x-2)(x-4)(x-7)(x-9)(x-10)], x]` -> `{-35721/64, {x -> 11/2}}`;
`Minimize[x^2+y^2, {x,y}]` -> `{0, {x->0, y->0}}`;
`Minimize[{x+y, x^2+y^2<=1}, {x,y}]` -> `{-Sqrt[2], {x->-1/Sqrt[2], y->-1/Sqrt[2]}}`;
`Minimize[{2x+3y-z, 1<=x+y+z<=2 && 1<=x-y+z<=2 && x-y-z==3}, {x,y,z}]` -> `{3, ...}`;
`Maximize[-x^2, x]` -> `{0, {x->0}}`. Previously every such input returned
unevaluated.**

- New translation unit `src/calculus/minimize.c` (`builtin_minimize` /
  `builtin_maximize`) — it is a **symbolic calculus** module, not a numerical
  one — registered by `minimize_init()` (called from `core_init` beside
  `deriv`/`series`/`limit`) as `Protected` — **not `HoldAll`**, matching
  Mathematica's `Attributes[Minimize]`: the variables are unbound
  symbols that evaluate to themselves, so the objective and constraints arrive
  in symbolic form and the engine proceeds by value-preserving substitution.
  Symbols `SYM_Minimize` / `SYM_Maximize` interned in `src/sym_names.{h,c}`;
  docstrings in `src/info.c`; option tables (`Method`, `WorkingPrecision`) in
  `src/options_builtin.c`.
- **Built on existing sound engines**, with the repository's "decline rather
  than guess" discipline: the candidate set comes from `Solve[..., Reals]` /
  the zero-dimensional engine, exact ordering of candidate values from the
  FLINT qqbar sign oracle (`rru_sign_compare`), and the global lower-bound
  certificate + region-emptiness test from `Reduce[..., Reals]`. Any oracle
  "don't know" (`rru_sign == -2`, an unclean/parametric `Solve`, an undecided
  `Reduce`) abandons the path; the expression is left unevaluated, never
  guessed. Internal `Solve`/`Reduce`/substitution probes run under
  `mth_msg_suppress_push/pop`, so e.g. `Solve::nsdim` from a parametric
  active-set subproblem never leaks to the user.
- **Scope.** (a) univariate polynomial objectives — derivative solved for its
  real stationary points, objective compared exactly, with the degree-parity +
  leading-coefficient-sign tail theorem deciding boundedness/attainment (odd
  degree or even-degree-negative-leading ⇒ `{-Infinity, ...}` + `Minimize::natt`);
  (b) multivariate polynomial objectives with isolated critical points (gradient
  system + a Reduce lower-bound certificate `f >= f_opt`); (c) polynomial
  objectives under polynomial constraints over the Reals — equalities,
  inequalities, chained `a<=g<=b` (expanded from `Inequality[...]`), and their
  `&&` combinations — via KKT/active-set enumeration on the region closure,
  confirmed by the Reduce certificate and an attainment check against the
  original strict region. Small **linear programs** fall out as the degenerate
  case. Infeasible regions return `{Infinity, {x->Indeterminate, ...}}` +
  `Minimize::infeas`.
- **`Maximize`** reuses the entire engine by minimizing `-f` and negating the
  reported value (so `-(-Infinity)` ⇒ `Infinity`, and infeasible/unbounded map
  correctly).
- **Inexact input** (any machine/MPFR real in `f` or `cons`) is delegated to
  `NMinimize`/`NMaximize` and returned verbatim — numeric by construction,
  mirroring Mathematica's approximate-input fallback. Exact input that the
  symbolic engine cannot settle (transcendental objectives, positive-dimensional
  minimizer sets, unbounded-via-QE, exact `Integers`) is left unevaluated.
- All diagnostics route through `fm_warn("Minimize"/"Maximize", tag, ...)` ->
  `mth_message` (tags `natt`, `infeas`), so `Quiet[]` / `Check[]` work. As a
  symbolic/structural head returning rule-lists (like `Solve`, `Reduce`,
  `NMinimize`), `Minimize`/`Maximize` carry no packed/NDArray/`Compile[]`
  surface — a deliberate, documented exemption.

Tests: `tests/test_minimize.c` (26 tests: shape, univariate incl. the degree-6
showcase and unbounded cases, `Maximize` duality, multivariate bowls, the
positive-dimensional decline, constrained disk/equality+inequality/LP,
infeasible, inexact fallback, transcendental/unbounded/arity declines, memory
smoke). Docs: `docs/spec/builtins/calculus.md` (new `Minimize / Maximize`
section).

## `Simplify` of a function-radical with an algebraic-constant coefficient ; v0.302

**Outcome: `Simplify[D[Integrate[(x^2+1)/(x^3 Sqrt[2x^4-2x^2+1]), x], x] -
integrand]` now returns `0` almost instantly. It previously did not terminate.**

- The decision procedure for this class already existed — `simp_radical_rational`
  (`src/simp/radrat.c`) reduces a rational function of `x` and several radicals in

  for a transcendental generator, combining with a *plain* (non-algebraic)
  `Together`, and reducing the numerator modulo the generator relations. But it only
  collected radical bases that **contained a free symbol**, so the algebraic
  *constant* `Sqrt[2]` was dropped; that left a single `x`-dependent generator, the
  `n >= 2` gate declined, and the input fell into the algebraic-field `Together` over
  `Q(x)[R]/(R^2-q)`, which blows up (multivariate GCD + ideal `divrem` with the
  relation parametric in `x`) on even a 344-leaf input.
- `radrat` now collects **constant radical bases as generators too** (building the
  relation `s^q - c`, e.g. `s^2 - 2`), and engages whenever there are `n >= 2`

  radical identity (`Sqrt[8] - 2 Sqrt[2]`) is still left to the `RootReduce`/qqbar

- Sound (the reduction uses only true relations, so a non-identity never collapses:

## Mellin transform (`Method -> "Mellin"`): seven new closures + an ArcTan[a/x] sign fix ; v0.300

**Outcome: a third Mellin-transform stress set `∫₀^∞ x^{s-1} f(a x) dx` (the
2026-10 set) — five forms already closed, seven more now close through general,
algorithmic extensions (no per-example patches), and a latent sign bug in the
reciprocal-argument path is fixed. All closed forms are proven identities,
numerically cross-checked against `NIntegrate` / the known constant during
development and pinned in `tests/test_integrate_ramanujan.c`
(`test_mellin_stress_set`). Everything lives in
`src/calculus/integrate_ramanujan.c`.**

- **Sign fix — `ArcTan[a/x]` (and every reciprocal-argument kernel).** The
  monomial substitution `g(x^k)` applied the Jacobian `1/k`, but the correct
  factor is `1/|k|`: for `k<0` the substitution `y=x^k` reverses the `(0,∞)`
  limits, contributing the sign that keeps the factor positive. `ArcTan[a/x]`
  (`k=-1`) was returning the **negated** `-(π/2s)Sec(πs/2)a^s`, though the
  integrand is strictly positive; it now gives the correct `+(π/2s)Sec(πs/2)a^s`.
- **`ExpIntegralE[n, a x]` for symbolic `n` (new `rec_expintegrale`).**
  `a^{-s}Γ(s)/(s+n-1)`, strip `Re s>0 ∧ Re(s+n)>1`. The operational-calculus
  `E_n'=−E_{n-1}` chain (which closed `n=1`) cannot bottom out for symbolic `n`.
  The second strip condition binds for small `n` and is *not* implied by
  `{Re s>0, Re(s−n)<0}`, so under those assumptions the honest result is a
  `ConditionalExpression` carrying `Re(s+n)>1` (matching Mathematica's decline).
- **Trig powers `Sin[a x]^k`, `Cos[a x]^k` (new `rec_trigpow`).** `TrigReduce`
  linearizes into harmonics closed by the `Sin/Cos` base rows at symbolic `s`;
  the scaleless mean is dropped (its transform is `0` on the `Re s<0` half). The
  strip is read off the whole function's asymptotics (left edge `−k` for `Sin^k`,
  `0` for `Cos^k`; right edge `0`/`1` by whether a mean survives), not the
  per-harmonic strips (which intersect to empty). `Cos^{even}` correctly declines.
- **`Exp[-a x] {Sin,Cos}[b x]` (new `conv_exp_trig`).** Via the complex frequency
  `c=a−ib`, `Γ(s)(a²+b²)^{-s/2}{Sin,Cos}(s·ArcTan(b/a))` — a generalization of the
  bare `Exp` (`b→0`) and `Sin/Cos` (`a→0`) rows; added to the convolution engine.
- **`ArcTan[a x]^2` (new `rec_arctan_sq`).** The self-convolution's Barnes residue
  sum closes to `(π a^{-s}/(2s)) Csc(πs/2)(ψ((1−s)/2)−ψ(1/2))` on `−2<Re s<0`
  (`s=-1` gives `π Log 2`). Mathematica returns this unevaluated.
- **`Coth[a x] − 1` (reduce rule).** Rewritten (before Expand) to the Bose kernel
  `2/(e^{2a x}−1)` and closed by the exponential-geometric recognizer as
  `2^{1-s}a^{-s}Γ(s)ζ(s)` (`Re s>1`). Fires only with the explicit `−1`; bare
  `Coth[a x]` (divergent) stays unreduced and declines.
- **Regressions pinned:** `Sin[a x^2]`, `Cos[a x^2]`, `ArcCot[a x]`,
  `Log[1+a^2 x^2]` (already closing) plus the corrected `ArcTan[a/x]`. The stale
  `test_declines_cleanly` negative control (`Exp[-x] Cos[x]`, which now closes)
  was replaced by a three-kernel product (still out of scope). Symbolic-only
  method: no NDArray/packed/`Compile[]` surface applies. Valgrind-clean on the new
  recognizer paths (identical leak profile to the pre-existing Mellin baseline).

## UpValues review follow-ups: Flat-head leftover matching + fixes ; v0.299

**Outcome: the post-merge review of the UpValues PR (#87) is addressed. The
headline item — rewrite rules on `Plus`/`Times` only firing at *exact* arity — is
fixed, so Mathilda now matches Wolfram on the main UpValue use case, plus three

### Flat-head rules fire on longer operand sequences

A rewrite rule whose LHS head is **Flat** (`Plus`, `Times`, `Dot`, `**`, `And`,
`Or`, …) now matches a **subset** of a longer operand sequence, rewriting the
matched part and keeping the rest — the way Wolfram does. This covers UpValues,
DownValues, and `Replace`/`ReplaceAll`.

```mathematica
mod /: mod[a_, p_] + mod[b_, p_] := mod[Mod[a + b, p], p];
mod[1,5] + mod[2,5] + mod[3,5]      (* mod[1,5]  -- was: unevaluated *)
mod[1,5] + mod[2,5] + x             (* mod[3,5] + x *)
d /: d[a_] + d[b_] := d[a + b];  d[1]+d[2]+d[3]   (* d[6] *)
1 + x + y /. x + y -> z             (* 1 + z *)
```

- **Mechanism.** Implemented at the rule-application layer (`match_rule_flataware`
  in `src/match.c`), **not** in the generic matcher, so `MatchQ` stays a
  whole-expression test (`MatchQ[mod[1,5]+mod[2,5]+x, mod[a_,p_]+mod[b_,p_]]` is
  still `False`, as in Wolfram). The strategy is *normal match first, augment on
  failure*: the ordinary match is tried unchanged (preserving Flat
  group-absorption — `pp + a_` on `pp+x+y` still binds `a_ = x+y`), and only on
  failure is the pattern retried as `head[p…, $FlatRest$___]` with the surplus
  spliced back into the head. The dispatch arity/first-arg pre-filters in
  `apply_down_values_def` / `apply_up_values_for_def` relax for Flat heads.
- **Limitation.** For a non-`Orderless` Flat head (`Dot`, `**`) the matched
  operands must form a **prefix** run; interior matches do not fire. `Plus`/`Times`
  are `Orderless`, so all positions are reachable.
- **Performance.** The common (non-Flat) matcher path is unchanged: the Flat
  machinery is gated behind cheap pointer-only structural checks that bail before
  any attribute lookup, so a non-Flat head pays nothing. `bench_match` (all ops
  linear, ratio < 3.3) and `bench_eval` (no workload > 2.5× baseline) pass, and an
  A/B against the pre-change binary shows no matcher regression.

## NonCommutativeMultiply (`**`) ; v0.298

**Outcome: Mathematica's associative-but-non-commutative multiplication
`NonCommutativeMultiply`, with surface operator `**`, is now available for
representing composition in non-commutative algebras (differential operators,
operator matrices, quaternions, …).**

- **Parser.** `a ** b ** c` lexes `**` as a new infix operator (precedence

  5900 sits in the empty gap between `Dot` (5300) and `Power` (6500), giving
  the exact Mathematica ordering `Plus < Times < Dot < NonCommutativeMultiply

  stays unevaluated (unlike `Times[a] → a`), and `Expand` / `Simplify` /
  `FullSimplify` are no-ops on NCM expressions. Registered in the static
  attribute table (`src/attr.c`) with a docstring (`src/info.c`).
- **Printing.** Infix round-trip `a ** b ** c` with precedence-aware
  parenthesisation (`(a + b) ** c`, `a ** b + c`); the one-argument form prints

  (`src/sym_names.{c,h}`, `src/print.c`).
- **Tests.** `tests/test_noncommutativemultiply.c` (parse/flatten, associativity,

## Mellin transform (`Method -> "Mellin"`): single-function + hyperbolic recognizers and the convolution engine ; v0.297

**Outcome: a second Mellin-transform stress set `∫₀^∞ x^{s-1} f(a x) dx` gains
eleven more closures through three general, algorithmic extensions (no
per-example patches). The headline is the **Mellin-convolution engine** — the
module's long-standing "product of two transcendental kernels → NULL" boundary
is removed for the Bessel-product and exp/Gaussian × Bessel families. All
closed forms are proven identities, numerically cross-checked against
`NIntegrate` during development and pinned in
`tests/test_integrate_ramanujan.c` (`test_mellin_single_extensions`,
`test_mellin_convolution`). Everything lives in
`src/calculus/integrate_ramanujan.c`.**

- **Single functions → a recognized kernel (`reduce_to_hypergeometric` + one
  dedicated recognizer).** `EllipticK[z] → (π/2)₂F₁(½,½;1;z)` and
  `EllipticE[z] → (π/2)₂F₁(-½,½;1;z)` (closed by `rec_pfq`); the Weber function
  `BesselY[ν,z] → (cos(νπ)J_ν − J_{-ν})/sin(νπ)` (each half closed by the
  `BesselJ` base transform, strips intersecting to `|Re ν|<Re s<3/2`); and a new
  `rec_gamma_upper` for the **upper incomplete gamma** `Γ[ν, a x] → a^{-s}Γ(s+ν)/s`
  (the operational-calculus identity `Γ'(ν,x)=−x^{ν-1}e^{-x}`, which the generic
  IBP fallback could not close because it does not re-absorb the `x^{ν-1}`
  monomial). Closes `EllipticK`, `BesselY`, `Gamma[ν,·]`.
- **Hyperbolic Dirichlet recognizer (`rec_hypergeom_dirichlet`).** The
  two-exponential sibling of the Bose/Fermi kernel:
  `Csch[a x] → 2 a^{-s}Γ(s)(1-2^{-s})ζ(s)` (`Re s>1`) and
  `Sech[a x] → 2^{1-s} a^{-s}Γ(s)·LerchPhi(-1,s,½)` (`= 2a^{-s}Γ(s)β(s)`,
  `Re s>0`), each from the odd-argument Dirichlet series of `e^{-a x}`.
- **Mellin-convolution engine (`rec_convolution`, new `dispatch_term` branch).**
  A product of two kernels is the Barnes integral `(1/2πi)∫M[K₁](z)M[K₂](s-z)dz`
  of Gamma ratios, closed in two regimes: **equal internal scale →** a pure Gamma
  ratio — `J_μ(ax)J_ν(ax)` (Weber–Schafheitlin, via the `J_μJ_ν → ₂F₃` identity
  fed back through `rec_pfq` + the `x²` monomial wrapper), `K_μ(ax)K_ν(ax)`
  (Barnes' first lemma), `J_ν(ax)K_ν(ax)` equal order (Kummer's theorem);
  **distinct scales →** a hypergeometric in the scale ratio —
  `e^{-ax}J_ν(bx) → ₂F₁(…;-b²/a²)` and the Gaussian Weber integral
  `e^{-a²x²}J_ν(bx) → ₁F₁(…;-b²/(4a²))`. Closes `J·J`, `K·K`, `J·K`, `exp·J`,
  `Gaussian·J`.
- **Out of scope (documented):** `AiryAi[x]²` — a genuine Meijer-G with 1/3-step
  Gamma coefficients that does not reduce to a simple `pFq`/Gamma ratio — and the
  three functions that do not yet exist as builtins (`WhittakerW`, `WhittakerM`,
  `ParabolicCylinderD`), deferred to separate campaigns.

## Mellin transform (`Method -> "Mellin"`): assumptions fix + general extensions ; v0.296

**Outcome: all twenty of a Mellin-transform stress set `∫₀^∞ x^{s-1} f(a x) dx`
now close, up from ten. The gains are a dispatcher/assumptions correctness fix
and three general, algorithmic extensions — no per-example patches.**

- **Assumptions — dispatcher gate (`def_has_undefined_function`, `src/calculus/integrate.c`).**
  The guard that skips the improper/parametric definite methods for an arbitrary
  forcing function is now **x-aware**: an undefined head disqualifies the
  integrand only when that subexpression *contains the integration variable*.
  An x-free parameter `List` (every `HypergeometricPFQ[{…},{…},z]`) no longer
  blocks the engine. This unblocks the three hypergeometric cases
  (`Hypergeometric2F1`/`1F1`/`HypergeometricPFQ`), whose exact Gamma-ratio
  transforms the Ramanujan-Master-Theorem recognizer already computed, and
  repairs the previously-red `1F1`/`2F1` assertions in
  `tests/test_integrate_ramanujan.c`.
- **Assumptions — strip discharge (Refine-augmented).** The convergence strip is
  now discharged with `Refine` as well as `Simplify`, per conjunct against each
  assumption atom, so a user assumption on `Re[...]` or a sign (`a>0`) collapses
  the `ConditionalExpression` to the bare value (`Re[s]>0 && Re[a]>0` now gives
  `½ a^{-s/2} Γ(s/2)` directly). Collapse is all-or-nothing: a partly-proven
  strip is carried **whole**, so the reported convergence region stays complete
  and sound.
- **Route A — hypergeometric reductions.** `reduce_to_hypergeometric` gained the
  entire-`pFq` identities for `SinIntegral` (`Si(z)=z·₁F₂(½;3/2,3/2;−z²/4)`) and

  uniformly by `rec_pfq` + the monomial wrapper.
- **Route C — dedicated recognizers.** `rec_besselk` (`∫x^{s-1}K_ν(ax)=2^{s-2}a^{-s}
  Γ((s+ν)/2)Γ((s−ν)/2)`, `Re s>|Re ν|`) and `rec_airy` (`∫x^{s-1}Ai(ax)=
  a^{-s}Γ(s)/(3^{(s+2)/3}Γ((s+2)/3))`, `Re s>0`) — the modified-Bessel and Airy
  transforms that are cancelling combinations of divergent series and so have no
  single-`pFq` form.
- **Route B — Mellin operational calculus.** A new integration-by-parts fallback
  `rec_ibp`: for a kernel whose derivative is a single recognized kernel,
  `M_f(s) = −(1/s) M_{f'}(s+1)`, with the lower boundary `Re s>0` added soundly
  (the differentiated kernel's strip misses the integration constant) and the
  upper boundary taken from the kernel strip. Closes `Erfc` (`f'`=Gaussian),
  `CosIntegral` (`f'`=cos/x) and `ExpIntegralE` (`f'`=−exp/x, via the
  `E_n→E_{n−1}` chain).
- **New special functions.** `ExpIntegralE[n,z]` (generalized exponential
  integral `E_n`; machine numeric by the continued-fraction/series split, with
  `E_0=e^{−z}/z`, `E_n(0)=1/(n−1)`, and `D[E_n,z]=−E_{n−1}`) and `StruveH[nu,z]`
  (Struve `H_ν`, numeric via its `₁F₂` representation). Both `Listable`,
  `NumericFunction`, `Protected`.



## UpValues subsystem (trial, `UP_VALUES`) ; v0.295

**Outcome: Mathilda gains UpValues and the five assignment/inspection heads that
drive them — `UpSet` (`^=`), `UpSetDelayed` (`^:=`), `TagSet`/`TagSetDelayed`
(`f /: lhs = / := rhs`), `TagUnset` (`f /: lhs =.`), the `UpValues[]` reader, and
`Definition[]`. Every change is gated behind the `UP_VALUES` build flag (on by
default; `make UP_VALUES=0` restores the exact pre-UpValues behaviour).**

An UpValue associated with a symbol `s` fires when `s` appears at level one of an
enclosing call — `s` as a direct argument, or the head of one — and is tried
**before** the enclosing head's DownValues/builtin, so the idiomatic
"associate the rule with the operand, not the operator" pattern now works:

```mathematica
mod /: mod[a_, p_] + mod[b_, p_] := mod[Mod[a + b, p], p];
mod /: i_Integer mod[a_, p_] := mod[Mod[i a, p], p];
mod[2, 5] + 3 mod[3, 5] - mod[1, 5]        (* -> mod[0, 5] *)

area[square] ^= s^2;  UpValues[square]     (* -> {HoldPattern[area[square]] :> s^2} *)
```

### Storage & evaluation
- New `Rule* up_values` on `SymbolDef` (gated), freed everywhere own/down are
  (`reset_node_payload`, `symtab_clear_symbol`, `symtab_remove_symbol`, and
  `Block`'s save/restore). A global `symtab_up_value_count` makes the per-call
  evaluator hook a single load+branch when no up-values exist anywhere.
- `apply_up_values` runs in `evaluate_step` just before `apply_down_values_def`,
  collecting the distinct level-one candidate symbols of the call (including the
  head of a `Blank` — `a_mod` keys on `mod`) and reusing the matcher's
  arity/first-arg-head dispatch pre-filter. `HoldAllComplete` suppresses up-values;
  `HoldAll` does not (so `Hold[g[x]]` still fires an all-heads upvalue while
  `HoldComplete[g[x]]` does not). The assignment primitives are skipped so an
  all-heads upvalue cannot hijack a held assignment LHS.

### Assignment heads & attributes
- `UpSet` (`HoldFirst`), `UpSetDelayed`/`TagSet`/`TagSetDelayed`/`TagUnset`
  (`HoldAll`), all `Protected | SequenceHold`. `UpSet`/`UpSetDelayed` install on
  **every** distinct level-one symbol of the LHS; `TagSet`/`TagSetDelayed` install
  on the single tag as an own-/down-/up-value as appropriate (SubValues declined
  with a message; a tag absent from the LHS issues `tagnf`).
- Parser: `^=`, `^:=` at Set's tier (500); `/:` as a dedicated ternary led branch;
  printer round-trips all five (`get_expr_prec`, `print_standard`).

### Inspection
- `UpValues[s]` (symbol or string) returns `{HoldPattern[lhs] :> rhs, …}`, `{}`
  when none, `UpValues::sym` for a string naming no symbol.
- `UpValues[s] = list`, and now also `DownValues[s] = list` / `OwnValues[s] = list`,
  replace the whole rule list.
- `Definition[s]` is an inert object that displays the own/down/up values;
  `?s` / `Information[s]` append them after the usage message. (Immediate vs
  delayed is not tracked, so down/up values display delayed, as `DownValues[]`
  already reads back.)

### Stress-test hardening
An adversarial stress pass (behavioural corpus + an independent diff bug-hunt +
valgrind churn) found and fixed four correctness issues before release:
- **Guarded delayed RHS.** `g /: f[g[x_]] := body /; test` (and the `^:=` form) now
  lift the `Condition` onto the LHS pattern, exactly as `SetDelayed` does — the
  guard was previously stored in the replacement and never filtered (`move_rhs_condition`).
- **Protected list setters.** `DownValues[s]=…` / `OwnValues[s]=…` / `UpValues[s]=…`
  now honour `Protected` (e.g. `DownValues[Sin]={…}` is refused with
  `Set::wrsym`); the intercept previously sat before the Protected guard.
- **No pattern-head pollution.** An UpSet whose operand is a bare blank or a
  pattern wrapper (`x_`, `x_?test`, `x_ /; c`) no longer installs a spurious
  upvalue on `Blank`/`PatternTest`/…; `element_dispatch_head` returns the wrapped
  pattern's head or nothing, a top-level `Condition` LHS is unwrapped, and an

- **`Unset` no longer corrupts a non-matching guarded rule (pre-existing core bug).**
  `pattern_alpha_normalize` rewrote pattern variables in place through a
  refcount-aliased copy, so a non-matching `=.` against a guarded rule

  RHS kept the old names — a later call then returned `rhs[x]` with `x` unbound.

  `Unset`/`TagUnset` on DownValues, OwnValues and UpValues.

## Definite `Integrate`: Lerch/Hurwitz-zeta integral-representation recognizer ; v0.294

**Outcome: Phase 3b of the stress-test campaign — the shifted Bose/Fermi Mellin
integral now closes as the Lerch transcendent / Hurwitz zeta.**
- `Integrate[E^(-a x) x^(s-1)/(1 - E^(-x)), {x,0,Inf}, Assumptions -> s>1 && a>0]`
  → `Gamma[s] HurwitzZeta[s, a]` (0.003 s, was a ~1.5 s decline).
- The whole class: `x^(s-1) E^(-a x)/(1 - z E^(-c x))` →
  `c^(-s) Gamma[s] LerchPhi[z, s, a/c]` for any fugacity `z <= 1` and rate `c>0`
  (e.g. `/(1-E^(-2x))` → `2^(-s) Gamma[s] HurwitzZeta[s, a/2]`, `/(1-(1/2)E^(-x))`
  → `Gamma[s] LerchPhi[1/2, s, a]`, `/(1+E^(-x))` → `Gamma[s] LerchPhi[-1, s, a]`).

### `rec_lerch_hurwitz` (new, `src/calculus/integrate_intrep.c`)

`1/(1 - z E^(-c x)) = Sum_{k>=0} z^k E^(-k c x)` termwise gives
`Integrate[x^(s-1) E^(-a x)/(1 - z E^(-c x)), {x,0,Inf}] = Sum_k z^k Gamma(s)/(a/c + k)^s / c^s
= c^(-s) Gamma(s) LerchPhi[z, s, a/c]` — a classical integral representation, so it
has no elementary antiderivative and the Mellin/Ramanujan families decline the
`e^(-a x)`-shifted form (`Integrate`Ramanujan`'s `rec_expgeom` owns only the
unshifted `a=1` case → `Gamma(s) Zeta(s)`).  The recognizer matches
`x^(rho) * E^(-A x) * (d0 + d1 E^(-c x))^(-1)` structurally (`s = rho+1`,
`z = -d1/d0`), proves the convergence gate from Assumptions, and emits
`HurwitzZeta` when `z == 1` else `LerchPhi`.  Gates, all correct-by-construction
(no NIntegrate): `A>0` and `c>0` proved *separately* (Simplify will not discharge a
scaled `a/c>0` from `a>0`, but proves each factor, and `A,c>0 => A/c>0` soundly);
denominator pole-free on `(0,Inf)` for real `z <= 1`; and `Re s>1` when `z==1` (the
`x=0` pole) else `Re s>0`.  Divergent shapes decline: no decay factor (`a=0`, so
`HurwitzZeta[s,0]` would be a pole) and `s=1` (the zeta pole) both stay unevaluated.

Verified: new `test_lerch_hurwitz` in `tests/test_integrate_intrep.c` (numeric
oracle across z=1/scaled-c/fugacity, plus the two divergence declines); all
definite suites green; `check-c99` and `check-messages` clean.

**Outcome: Phase 3a of the stress-test campaign — `Cos[a x]/Cosh[b x]^2` and the whole
class `(trig)/Cosh[b x]^n` now close instantly, correct-by-construction.**
- `Integrate[Cos[a x]/Cosh[b x]^2, {x,-Inf,Inf}, Assumptions -> Element[a,Reals] && b>0]`

### What changed (`src/calculus/integrate_residue.c`, `residue_family_hyperbolic_strip`)

The periodic-strip (rectangle) family closed `N(x)/Cosh[b x]` on `(-Inf,Inf)` by the
quasi-period fold `Cosh[b(x + i Pi/b)] = -Cosh[b x]` and a hard-coded `Sec` closed form
per exponential term.  It matched only a **bare** `Sech[b x]` factor, so `Sech[b x]^2`
(head `Power`) fell through and `Cos[a x]/Cosh[b x]^2` ground the full Newton-Leibniz
antiderivative search for ~55 s before declining.  Two changes, both
correct-by-construction (the integrand has no elementary antiderivative; NO NIntegrate):
- **Matcher** (`match_cosh_power_factor`): accept `Sech[beta x]^n` and `1/Cosh[beta x]^n`
  for any integer `n >= 1` (argument still exactly `beta*x`, `beta` free of `x`), carrying
  the order `n`; the convergence gate widens from `|Re alpha| < Re beta` to
  `|Re alpha| < n Re beta` (`Cosh^n ~ e^(n beta|x|)/2^n` at infinity).
- **Closed form** (`hyperbolic_strip_term`, new): for each exponential term `C E^(alpha x)`
  with `n >= 2`, emit the Gamma-reflection value of the Mellin-Barnes integral
  (equivalently the order-`n` residue of the quasi-period fold),
  `2^(n-1)/(beta (n-1)!) · R(w) · Prod(w)` with `w = alpha/(2 beta)`:

  `R = Pi w/Sin[Pi w]`, `Prod = Prod_{j=1}^{m-1}(j^2 - w^2)` for even `n = 2m`.

  byte-for-byte unchanged).  The family's own `ComplexExpand`+`Simplify` tail then
  reduces the elementary, even-in-`alpha` form to `Sech`/`Csch · polynomial`.

A half-line integrand that IS a classical integral representation of a special
function has no elementary antiderivative — so Newton-Leibniz, the Mellin/residue
families and Ramanujan all decline — yet the closed form is immediate once the shape
is matched and its convergence gate is proved from Assumptions.  Correct-by-construction

- **Laplace-Bessel** `E^(-p x) BesselJ[nu, q x]` → `(Sqrt[q^2+p^2]-p)^nu/(q^nu Sqrt[q^2+p^2])`,

Wired into the half-line cascade after Ramanujan, before FTC; `Method ->

## Series/Limit: ArcTanh/ArcCoth branch-point expansion for a non-linear inner ; v0.290

**Outcome: `Series[ArcTanh[Sqrt[1 - a^2]], {a, 0, 1}]` now expands to
`Log[2] - Log[a] + O[a]^2` (it was returned unevaluated), so the limits that rely
on it decide instead of returning `Infinity`:
`Limit[Log[a] + ArcTanh[Sqrt[1 - a^2]], a -> 0] = Log[2]`.**

### Root cause (`src/calculus/series.c`)

ArcTanh/ArcCoth have a logarithmic branch point at an argument of ±1. The existing
branch-point handler (`so_apply_arctanh_branch_point`) only fires when the inner
series is `±1 + q*w` (a LINEAR leading correction, `branch_check_linear_inner`).
`Sqrt[1 - a^2] = 1 - a^2/2 - ...` approaches 1 QUADRATICALLY, so the handler
declined and `series_expand` returned unevaluated — and `Limit`/Gruntz then saw two
individually divergent `±Log[a]` terms and reported `Infinity`.

### Fix

When the ArcTanh/ArcCoth inner is at a ±1 branch point but the linear handler
declines, rewrite at the Expr level `ArcTanh[arg] = (Log[1 + arg] - Log[1 - arg])/2`
and recurse through `series_expand`, whose Log-of-a-vanishing-series handling
(`Log[c (x-x0)^r (1+u)] = r Log[x-x0] + Log[c] + Log[1+u]`) extracts the
`Log[x-x0]` singularity for whichever of `1 ± arg` vanishes — for a leading
correction of ANY order. The recursion terminates (the rewrite is Log-only, no
ArcTanh). Purely additive: the linear branch-point and at-zero / at-infinity paths
are unchanged, so the series/limit/gruntz suites are green.

`tests/test_limit.c::test_arctanh_branch_point` pins the two canceling limits and

and cross-checked: `∫₀^∞ Log[x]/(x²−4) dx = π²/8` with `PrincipalValue -> True`,
matching a symmetric-exclusion Cauchy numeric.

### Hyperbolic reduction in the rectangular family (`residue_family_rectangular`)

The `w = Exp[x]` substitution that reduces `Exp[c x] R(Exp[x])` to the Mellin
integrand now also closes `x^k/Sinh x` and its relatives: a `Sinh`/`Cosh`/`Tanh`/
`Csch`/`Sech`/`Coth` of `Log w` rationalises under `TrigToExp` + `Together`
(`Sinh[Log w] = (w − 1/w)/2`), while a polynomial `x^k` factor becomes
`(Log w)^k`.  The resulting `(Log w)^k R(w)` integrand is handed to the
keyhole-log family, whose removable `w = 1` (`x = 0`) pole is exactly the
principal-value case above.  The pure-`Exp` strip path is unchanged (no
hyperbolic head → no `TrigToExp`), so the existing rectangular family is
unaffected.

## Residue `Integrate`: non-integer-power keyhole-with-log + exact `Arg` on roots of unity ; v0.270

**Outcome: `Method -> "Residue"` now evaluates the log-keyhole with a
NON-integer branch power (`∫₀^∞ x^p (Log x)^m R(x) dx`, `p ∉ ℤ`), e.g.
`Integrate[Sqrt[x] Log[x]/(x^2+1)^2, …] = π(π−4)/(8√2)`.  The integer-power
log-keyhole (Cases 4/4b from the probe set) now returns the clean closed form
instead of silently declining: `Integrate[Log[x]/(1+x^6), …] = −√3 π²/18`,
`Integrate[Log[x]/(1+x^4), …] = −√2 π²/16`.** The enabling fix is a general
`Arg` improvement that lands far beyond the residue method.

### `Arg` of root-of-unity-like constants (`src/complex.c`)

`Arg[(-1)^(1/6)]` and friends were left **unevaluated**: the generic `a + b I`
re/im split has no `(-1)^r` to decompose, so it fell through to a symbolic
`Arg[(-1)^(1/6)]`.  Every pole of `1 + x^n` off the Gaussian lattice is exactly
such a constant, so any residue sum over those poles produced an `Arg`-salad no
simplifier could collapse.

`Arg[z]` now recovers the exact rational multiple of `Pi` for a product of
real-rational powers and the imaginary unit — `(-1)^(1/6) → Pi/6`,
`-(-1)^(5/6) → -Pi/6`, `(-8)^(1/3) → Pi/3`, `I (-1)^(1/4) → 3 Pi/4` — by adding
arguments mod `2 Pi` across the factors (`arg = ([c<0] + Σ eᵢ[bᵢ<0]) Pi`) and
reducing into `(-Pi, Pi]`.  Purely structural and provably correct: a free
symbol, an inexact real, or a non-root-of-unity Gaussian (`Sqrt[3] + I`) declines
and falls through to the existing `ArcTan`/unevaluated path untouched.

### Non-integer-power keyhole-with-log (`src/calculus/integrate_residue.c`)

For `p ∉ ℤ` the branch factor `z^p` jumps across the cut, so `1 − e^{2πi p} ≠ 0`
and the keyhole of `z^p (Log z)^m R(z)` gives the lower-triangular system

```
(1 − e^{2πi p}) I_k = 2πi T_k + e^{2πi p} Σ_{j<k} C(k,j) (2πi)^{k−j} I_j,
T_k = Σ_l Res[z^p (Log z)^k R, z_l]   (keyhole branch arg ∈ [0,2π)),
```

solved upward from `I_0` (the `k=0` row is the plain keyhole/Mellin value).  New
helpers `keyhole_log_general_a` and `klog_branch_pole_contribution` (the
order-≥2 shifted form, carrying both `(1+w/z)^p` and the shifted log);
`residue_family_mellin_log` dispatches integer `p ≥ 0` to the existing `a=0`
`(Log z)^{k+1}` contour and non-integer `p` to the new system.

### Keyhole-log closing (`a0_keyhole_log`)

The integer-power family computed the right value but closed with
`Simplify[RootReduce[Re[…]]]`, which turned the nice `(-1)^(1/6)` poles into
`Root[…]` objects whose `Arg` never simplified — leaving an unresolved
`Re[Root…]` that failed the real-scalar gate, so Cases 4/4b **declined** (and
their tests passed only vacuously through the `N[]` → `NIntegrate` fallback).
The triangular solve now keeps each `I_k` as its exact complex form and closes
once with `Simplify[ComplexExpand[…]]`; with `Arg` reducing on the roots of
unity the poles live at, the result collapses to the clean algebraic multiple of
`π^{m+1}`.

## Residue `Integrate`: parametrized-contour family + essential-singularity residues ; v0.271

**Outcome: `Method -> "Residue"` now evaluates a parametrized contour integral
over a full period, `Integrate[g(c Exp[I t]) (I c Exp[I t]), {t, 0, 2 Pi}]`,
including integrands with an essential singularity.** Examples now solved:
`Integrate[Exp[Exp[-I t]] Sin[Exp[-I t]] I Exp[I t], {t,0,2Pi}] = 2 Pi I`
(Case 9/19, essential singularity at 0);
`Integrate[(Exp[2Exp[I t]]/(Exp[4 I t](Exp[I t]-1/2))) I Exp[I t], …]
= 2 Pi I (16 E - 128/3)` (Case 20, order-4 + simple pole);
`Integrate[(2Exp[I t])^5 Cos[1/(2Exp[I t])^2] 2 I Exp[I t], …] = 0` (Case 22).

### `residue_family_contour_param` + `res_ess0` (`src/calculus/integrate_residue.c`)

The substitution `t -> -I Log[u]` (so `Exp[I t] -> u`, `Exp[-I t] -> 1/u`) turns
the whole `t`-integral into the contour integral of `G(u) = integrand/(I u)`
around `|u| = 1`, hence `2 Pi i Sum_{|u_k|<1} Res[G, u_k]` -- the same transform
`residue_family_trig` uses, but for a transcendental `G` (an essential
singularity, or an Exp/trig-of-(1/u) kernel) that is not rational in `u`, which
the trig family declines on.  Wired after `residue_family_trig` in the
full-period branch, gated on the integrand carrying `Exp` (stored `Power[E,.]`)
so the common rational-trig path is untouched.

`res_ess0` computes the residue at an essential singularity at `0` as the `w^1`
coefficient of `Series[G /. u -> 1/w, {w, 0, 1}]` (the Laurent `u^{-1}`
coefficient); for an ordinary pole at `0` of an entire-in-`u` integrand
(`Exp[2u]/u^4`) the ordinary `residue_compute` runs first (the `1/w` substitution
would turn `Exp[2u]` into the essential `Exp[2/w]`).  `u = 0` is always a
candidate pole (the `1/u` kernels put a singularity there that is not a
polynomial-denominator root); a denominator root equal to `0` is de-duplicated
against it (it was otherwise double-counted -- caught as `16 E - 256/3` instead
of `16 E - 128/3`).  The contour value is genuinely complex, so the finite-scalar
gate applies, not the real gate.

Case 9's literal `z \[Element] Circle[...]` contour spelling remains out of
scope (no named-character / region-iterator parsing); its mathematics is
delivered through the parametrized spelling (Case 19), which is identical.

## Residue `Integrate`: unit-circle trig with symbolic parameters (Case 16) ; v0.272

**Outcome: `Method -> "Residue"` now evaluates `Integrate[R(Cos x, Sin x), {x,0,2π},
Assumptions -> ...]` with symbolic parameters, including a higher-order pole and a
coupled assumption.** `Integrate[1/(a+b Cos[x])^3, …, a>b>0] =
π(2a²+b²)/(a²−b²)^(5/2)` (Case 16); `1/(a+b Cos[x]) → 2π/√(a²−b²)`.

### Coupled-assumption instantiation (`build_instantiation`, `src/calculus/integrate_residue.c`)

The symbolic-parameter mode reads pole signs at a representative point of the
assumption region.  `absorb_fact` reduces only INDEPENDENT numeric bounds, so a
coupled constraint like `a > b > 0` (where `a` is bounded by `b`, not a number)
left `a` "unconstrained" and declined.  When that happens, `build_instantiation`
now falls back to `FindInstance[assumptions, {params}]` for one consistent point
(e.g. `{a->1, b->1/2}`); the per-parameter intervals are then unknown, so the
mellin/sector families (which gate on them) still decline, while the unit-circle
family — which only classifies poles at the point — proceeds.  This alone fixes
the order-1 symbolic case.

### Analytic-part residue for a parametric higher-order pole (`residue_family_trig`)

`solve_roots` de-duplicates a multiple root to one representative, and the
generic residue engine's Laurent series is pathologically slow for a symbolic
RADICAL pole — `Residue` of the order-3 pole at `(-a+√(a²-b²))/b` is >30s and its
cost explodes with the radical's surface form (`√(4a²-4b²)` ~30× slower than
`√(a²-b²)` for the same value).  The symbolic branch instead:
- recovers each pole's order with `pole_order` (counting the leading vanishing
  derivatives of the denominator at the instantiated root);
- takes the residue by the analytic-part derivative
  `Res = (1/(m-1)!) d^{m-1}/dz^{m-1}[ N / (lead ∏_{r≠z₀}(z-r)^{m_r}) ]|_{z₀}`,
  building the pole-free denominator from the distinct roots and their orders
  (~0.1s, no Series);
- simplifies each residue, sums, and closes with `Simplify[2πi S]` (real under
  the assumptions).

The numeric trig family is unchanged (its `solve_roots`/`residue_compute` path
is already correct and cheap), and a `1/(2+Cos[x])^2 = 4π/(3√3)` regression pins it.

`tests/test_integrate_residue.c::test_trig_symbolic` pins the order-1 and order-3

## Residue `Integrate`: Mellin–Barnes vertical line + directed-infinity Plus fix (Case 11) ; v0.273

**Outcome: `Integrate[Gamma[s] x^(-s), {s, 1/2 - I Infinity, 1/2 + I Infinity}]`
now returns `2 Pi I e^(-x)` — it was a silent WRONG `0`.** This is the inverse
Mellin transform / Bromwich integral, the last of the probe set's two wrong
answers.

### Directed infinity survives `Plus` (`src/plus.c`)

`1/2 - I Infinity` evaluated to a real `Infinity`: `classify_plus_term` treated
`Times[Complex[0,-1], Infinity]` as a real `+Infinity` (reading
`expr_numeric_sign` of the complex coefficient), so `Plus[1/2, that]` collapsed
to `Infinity` and both vertical-line endpoints became `Infinity` before
`Integrate` (not HoldAll) ever saw them.  A `Times[c, Infinity]` with a NON-REAL
coefficient is now classified as an ordinary term, so `1/2 ± I Infinity` stays
`Plus[1/2, Times[Complex[0,∓1], Infinity]]` — the imaginary direction is
preserved.  Real `±Infinity` arithmetic and the `Infinity + (-Infinity) ->
Indeterminate` checks are unchanged.

### Mellin–Barnes family (`residue_family_mellin_barnes`, `src/calculus/integrate_residue.c`)

`is_vertical_line` recognises `{s, c-iInf, c+iInf}` (same real offset `c`,
opposite imaginary directions) and its orientation.  For an integrand
`const · Gamma[A + B s] · X^(P + Q s)` with `B` a positive numeric and `c` to the
right of the rightmost pole, the contour closes to the left and the value is
`orient · 2 Pi i · Sum_{k>=0} Res[F, s=-(A+k)/B]`, with
`Res[Gamma[A+Bs]] = (1/B)(-1)^k/k!`; the residue series is handed to `Sum`, which
closes it to the inverse-Mellin closed form (`Gamma[s] x^-s -> 2 Pi i e^-x`,
`Gamma[2s] x^-s -> i Pi e^-Sqrt[x]`).  Wired as the first branch of
`integrate_residue_try`.  Declines (stays unevaluated) when the integrand is not
of this shape or the series does not close.
