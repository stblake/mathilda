# Changelog: week of 2026-10-05 (Mon) – 2026-10-11 (Sun)

## DiffUnderInt `Integrate`: reverse recognition (Gamma') + repeated differentiation + output-quality finalize ; v0.288

**Outcome: three more `Method -> "DiffUnderInt"` targets close.
(1) `Integrate[Exp[-x] x^(a-1) Log[x], {x,0,Inf}, Assumptions -> a>0]` ->
`Gamma[a] PolyGamma[0,a]`.
(2) `Integrate[Sin[a x]^3/x^3, {x,0,Inf}, Assumptions -> a>0]` -> `3 Pi a^2/8`.
(3) `Integrate[Log[1 + a^2 x^2]/(1 + b^2 x^2), {x,0,Inf}, Assumptions -> a>0 && b>0]`
now returns the contracted `(Pi(Log[a+b]-Log[b]))/b` instead of the split
`(Pi(-2Log[b]+Log[a b+b^2]))/b`.**

### Reverse recognition (`stage_reverse_feynman`, `src/calculus/integrate_diffunderint.c`)

When the integrand is itself a parameter-derivative of a known integral --
`f = Log[x]^k h` with `d/da h = Log[x] h` -- the value is `d^k/da^k Integrate[h]`.
`strip_log_x_power` peels the `Log[x]^k` factor; `find_log_derivative_param`
verifies `d/da h == Log[x] h`; `known_integral_closed_form` recovers `F(a) =
Integrate[h, {x,a,b}]` from the families or, for a decaying Laplace/Gamma shape
`C Exp[alpha x] x^(s-1)` (gated by `is_gamma_shape` so it cannot hang), from the
engine; the result is `d^k/da^k F`.  Runs last, outside the `np>0` guard (the Log
weight supplies the parameter).  Closes the Gamma'-derivative integral.

### Repeated differentiation / power reduction (`stage_repeated_quadrature`)

A single differentiation of `trig^n/x^m` leaves a `1/x^{m-1}` the families still
cannot close; `stage_repeated_quadrature` differentiates `k` times (bounded by the
Together-denominator degree `max_inv_x_power`, capped at 4) until the inner integral
closes, then back-integrates `k` times, pinning the `k` lower derivatives at an exact
base (`multi_base`).  Closes `Sin[a x]^3/x^3` (`k = 2`: `I''(a) = 3 Pi/4`, `I(0) =
I'(0) = 0`), which neither the Automatic cascade nor single-differentiation closes.

### Output-quality finalize (`diui_finalize`)

Extended beyond 1-arg PowerExpand with an assumption-aware `FullSimplify`
candidate, taken only when strictly simpler (smaller `LeafCount`) and gated to a
small result so it stays bounded; each candidate is kept only when provably equal
to the verified answer.  Contracts the split Log the per-family Simplify leaves
standing.

### Deferred: finite-period log-trig

`Integrate[Log[a^2 - 2a Cos[x] + 1], {x,0,Pi}]` and `Integrate[Log[1 - a^2 Sin[x]^2],
{x,0,Pi/2}]` remain unevaluated.  The differentiated inner integral (rational in
Sin/Cos over a period) is reachable via the residue unit-circle engine, but the
Feynman back-integration yields a complex-branch antiderivative singular at the
natural base (`∝ 1/a` or `1/√(1-a^2)`) and `Limit` cannot resolve the canceling
log-singularity there -- a branch-correct back-integration is the prerequisite.

### Tests & docs

`tests/test_integrate_diffunderint.c`: `test_reverse_feynman`,
`test_repeated_quadrature`, `test_finalize_quality` (the last also asserts the
uncontracted `Log[a b + b^2]` does not survive).  Docs updated in
`docs/spec/builtins/calculus.md`.  valgrind clean on the new paths.

## DiffUnderInt `Integrate`: self-similar Gaussian recognizer (Glasser substitution) ; v0.287

**Outcome:
`Integrate[Exp[-a^2 x^2 - b^2/x^2], {x, 0, Infinity}, Assumptions -> a > 0 &&
b > 0, Method -> "DiffUnderInt"]` now closes to `(Sqrt[Pi]/(2a)) Exp[-2 a b]`.**

### `detect_selfsimilar_ode` (`src/calculus/integrate_diffunderint.c`)

The Stage B IBP ansatz cannot reach a Laurent-Gaussian integrand (no polynomial
`U` in `x` reproduces the `1/x^2` term — verified: the `x^{-2}` coefficient cannot
be cancelled by an x-free `lambda`), so Stage B now falls back to a dedicated
self-similar recognizer. For `f = Exp[c0 + c2 x^2 + cm2/x^2]` with `c2, cm2 < 0`,
the reciprocal substitution `x -> k/x`, `k = Sqrt[cm2/c2]`, leaves the exponent
invariant, so `Integrate[g, {x,0,Inf}] = Integrate[g(k/x) (k/x^2), {x,0,Inf}] =
lambda I` with `lambda = g(k/x)(k/x^2)/f` read off directly (x-free when it fires),
`M = 0`. Differentiating `Exp[-a^2 x^2 - b^2/x^2]` in `b` gives `lambda = -2a`, and
the integrating factor closes `I = I(0) Exp[-2 a b]` with base `I(0) = Sqrt[Pi]/(2a)`.

Supporting: `has_inv_x_power` gates Stage B's IBP ansatz off any Laurent integrand
(the polynomial `CoefficientList` match has no negative degrees), leaving it for
this recognizer. The `c0` shape check computes `arg - c2 x^2 - cm2/x^2` and
requires it x-free — `Coefficient[arg, x, 0]` cannot be used, as it lumps the
`1/x^2` term into the x^0 bucket. The strict `D[I,p] - (lambda I + M) === 0`
verification is kept.

## DiffUnderInt `Integrate`: Stage B — first-order linear ODE in the parameter (integrating factor) ; v0.286

**Outcome: the classic Feynman Gaussian
`Integrate[Exp[-a^2 x^2] Cos[b x], {x, 0, Infinity}, Assumptions -> a > 0 &&
Element[b, Reals], Method -> "DiffUnderInt"]` now closes to
`(Sqrt[Pi]/(2a)) Exp[-b^2/(4a^2)]` — it was returned unevaluated because the inner
integral `Integrate[D[f,b]]` is a Sin-Gaussian (Dawson/Erfi) the moment family
declines.**

### Stage B solver (`src/calculus/integrate_diffunderint.c`)

The method's header advertised a first-order-ODE framing `I'(p) = lambda(p) I +
M(p)` but only ever implemented `lambda = 0` (Stage A, pure quadrature). Stage B
is now implemented: when `J = Integrate[D[f,p], {x,a,b}]` does not close to an
x-free form, it may equal `lambda(p) I + M(p)`, where `I` is the original integral
and `lambda`, `M` are x-free — exactly when, by integration by parts in `x`,
`D[f,p] - lambda(p) f = D[U,x]` for an x-free `lambda` and a `U` spanned by `f`'s
transcendental atoms. New statics:
- `collect_primitive_atoms` / `collect_term_shapes` / `atom_shape_of_term` —
  gather the maximal transcendental-of-x leaves (`Exp`, `Sin`, `Cos`, …) and the
  atom-product shapes of `f` and `g`.
- `detect_linear_ode` — builds the ansatz `U = Sum c_k B_k` (the `B_k` the
  shapes) with a fresh `lambda`, forms `R = Expand[g - lambda f - D[U,x]]`,
  substitutes the primitive atoms (collected from `R`, so the basis is complete)
  for fresh indeterminates, and matches coefficients via `CoefficientList` +
  `Solve` for `{c_k, lambda}`. The IBP identity `g - lambda f - D[U,x] === 0` is
  then verified literally (the atoms need not be independent), and the boundary
  term `M = [U]_a^b` is evaluated by `boundary_value` (direct substitution or
  `Limit`, declining a non-convergent boundary).
- `solve_linear_ode` — integrating factor `mu = Exp[-Integral lambda dp]`,
  `I = (1/mu)(Integral mu M dp + C)`, with `C` pinned by the base `I(p0)`. Every
  parameter antiderivative routes through the (now bounded) `integrate_over_param`,
  so no unbounded engine call is formed.
- `stage_linear_ode` — driver, tried in `stage_quadrature` only when Stage A's
  inner integral fails to close, and only in the computed-base pass. Keeps the
  strict `D[I,p] - (lambda I + M) === 0` verification.

Deferred: the self-similar `Exp[-a^2 x^2 - b^2/x^2]` (IBP-in-x cannot find it;
needs a substitution recognizer) and the inhomogeneous `M != 0` branch beyond the
gaussian/rational antiderivative table.

`tests/test_integrate_diffunderint.c::test_stage_b_ode` pins the one- and

## DiffUnderInt `Integrate`: bounded back-integration (hang fix) + trig-product / zero-base correctness ; v0.285

**Outcome: two robustness/correctness fixes to `Method -> "DiffUnderInt"`.
(1) `Integrate[Exp[-a x] (Sin[b x]/x)^2, {x,0,Infinity}, Assumptions -> a>0 && b>0]`
no longer HANGS uninterruptibly — it closes to
`b ArcTan[2b/a] − (a/4) Log[1+4b²/a²]`.
(2) `Integrate[Exp[-a x] Sin[b x] Sin[c x]/x, {x,0,Infinity}]` no longer returns a
NON-REAL value (a spurious `−iπ/2`) for `b<c`, nor `Indeterminate` for `b=c`; it
returns the clean, all-signs-real `(1/4) Log[(a²+(b+c)²)/(a²+(b−c)²)]`.**

### Bounded parameter back-integration (`integrate_over_param`, `src/calculus/integrate_diffunderint.c`)

The back-integral `∫ J dp` fell back to the unbounded indefinite engine. For the
squared-sinc, the inner image was `J = (1/2)Log[a] + Log[1/(a²+4b²)^(1/4)]`, and
`Integrate[J, a]` drove the engine into an uninterruptible algebraic/radical grind
on the `Log[1/poly^(1/4)]` spelling (`TimeConstrained` does not bound a nested
evaluate). `integrate_over_param` now `PowerExpand`s `J` (pulling the `Log` out of
the reciprocal radical — the plain-`Log` spelling integrates instantly) and then
**declines** unless the normalized `J` is free of radical/trig/Gaussian *of the
parameter*, mirroring the families-only discipline of `inner_definite`. A branch
slip from `PowerExpand` is caught by the existing `D[I,p]−J===0` verification.

### Trig-product normalization + zero-base-first parameter selection

Two coupled fixes close the `Sin[b x] Sin[c x]` case correctly for all real `b,c`:
- **`has_trig_product_of_x` + `TrigReduce`** — when a term of the differentiated
  integrand carries ≥2 trig-of-x factors (a `Power[trig,k]` counting as one),
  `inner_definite` first rewrites the product as a sum of single trig terms
  (`Sin[b x] Sin[c x] → (Cos[(b−c)x] − Cos[(b+c)x])/2`). The complex-exponential
  path otherwise yields a tangled `Log[b−c]`/`ArcTanh` form that is non-real for
  some real parameter signs. A lone `Sin[a x]^2` is left untouched.
- **zero-base-first pass** (`stage_quadrature` now two passes; `find_base` gains a
  `zero_base_only` flag) — a parameter whose integrand *vanishes* at the base point
  (`I(p₀)=0`, exact and sign-independent) is preferred over one needing a
  sign-sensitive computed base. The `D[I,p]−J` check cannot catch a wrong constant
  base, so when a zero-base parameter exists it must win. For the `Sin·Sin` case
  the `a`-path's computed base `∫ Sin[b x] Sin[c x]/x dx` is valid only for `b>c`,
  while the `b`/`c` paths have the exact base `b=0 → 0`; the `b`-path now wins.

## Residue `Integrate`: multi-frequency Fourier (cosine difference) + honest arctan decline ; v0.284

**Outcome: `Integrate[(Cos[a x] - Cos[b x])/x^2, {x, 0, Infinity}, Assumptions ->
a > 0 && b > 0, Method -> "Residue"]` now returns `π(b − a)/2` (In[13]) — a
difference of two cosines whose individual integrals diverge, previously declined.
`Integrate[ArcTan[a x]/(x (1 + b^2 x^2)), …]` (In[20]) is a documented honest
decline.**

### Multi-frequency Fourier family (`src/calculus/integrate_residue.c`)

New `residue_family_fourier_sum` (with helper `fsum_term`), wired into the
whole-line dispatch right after the single-kernel Fourier family.  It recognises
`R(x) · Σ_i C_i K[ω_i x]` where the `K` are all one kernel type (`Cos` or `Sin`),
the frequencies `ω_i` share one sign, and `R` is rational with denominator
degree-drop ≥ 1.  The sum lifts to `Σ_i C_i e^{i ω_i x}` and the half-plane
contour closes it once; `Re[π i Σ Res]` for `Cos`, `Im` for `Sin`.

The substance is the **axis-pole-by-cancellation** gate: a difference like
`Cos[a x] − Cos[b x]` is `O(x²)` at the origin, so `(Cos[a x] − Cos[b x])/x²` is
*finite* at `x = 0` even though `Cos[a x]/x²` and `Cos[b x]/x²` each have a genuine
double pole there and diverge.  A real-axis pole of `R` is therefore admitted
only when `Limit[f, x → z₀]` of the **original** integrand is finite — the summed
numerator has reduced the pole order — and then contributes the indented
half-residue (weight 1) alongside the full enclosed residues (weight 2).  The
single `Cos[a x]/x²` (no cancellation, limit infinite) correctly declines as
divergent rather than fabricating a value.  Whole-line `π(b − a)`; the even
half-line add-on gives `π(b − a)/2`.

### Honest decline: arctan / branch-cut integrand (In[20])

`∫₀^∞ ArcTan[a x]/(x (1 + b² x²)) dx = (π/2) Log[1 + a/b]` is pinned as a
deliberate decline.  The integrand carries a branch cut (`ArcTan`), not isolated
poles; the closed form comes from parametric differentiation (Feynman:
`∂_a I = ∫₀^∞ dx/((1+a²x²)(1+b²x²)) = π/(2(a+b))`, then integrate in `a`), which
is outside the residue theorem.  No Feynman engine is on the residue path, so the
method returns the integral unevaluated — consistent with the Case-17/21
decline policy (a negative control, not a silent wrong answer).

`tests/test_integrate_residue.c`: In[13] exact pins (half-line `1/2 Pi (-a + b)`,

`a → 2, b → 5`, the single-`Cos[a x]/x²` divergence-decline control, and the

## Residue `Integrate`: unit-circle `b Cos + c Sin`, degenerate-instance retry + no message leak ; v0.283

**Outcome: `Integrate[1/(a + b Cos[θ] + c Sin[θ])^2, {θ, 0, 2π}, Assumptions ->
a > Sqrt[b^2+c^2], Method -> "Residue"]` now returns `2π a/(a^2-b^2-c^2)^(3/2)`
(In[11]) — it had leaked a stream of `Power::infy` / `Infinity::indet` messages to
stderr and then declined.**

### No message leak from the classification probe (`src/calculus/integrate_residue.c`)

`apply_inst` (substitute the representative point into a symbolic pole) now runs
inside `Quiet`: at a degenerate point the substitution can hit `1/0` (the pole
location's denominator vanishes there — e.g. the leading `(b − c I)/2` of the
z-quadratic at `b = c = 0`), whose `Power::infy` / `Infinity::indet` must not leak
from an internal probe (it bypassed `Quiet[]` / `Check[]`).  The `N`-based probes
(`res_reim_direct`, `numeric_double`) are Quieted for the same reason.

### Degenerate-instance retry in the unit-circle family

`FindInstance[a > Sqrt[b^2+c^2]]` picks the degenerate `b = c = 0`, where the
pole quadratic loses degree and no pole can be classified, so the family declined.
`residue_family_trig` now wraps its core: on an *undecidable* classification (and
only in the coupled `FindInstance` mode) it retries at a representative point with
every parameter nonzero.  This is sound for the full-period rational family — its
integral is analytic wherever no pole lies on the unit circle (the core still
flags that via `Integrate::idiv`), so the parameter-analytic residue formula
extends from a nondegenerate point.  The retry is confined to this family, so the
real-axis Fourier family's under-constrained declines (e.g.
`Cos[k x]/(x^2+a^2)` with only `k > 0`) are unchanged.  (`b Cos + c Sin` was always
substituted correctly; the only obstruction was the degenerate instance.)  The
result is correct but not fully reduced (`16π a/(4a^2−4b^2−4c^2)^(3/2)`).

**Outcome: `∫₀^∞ x^(2m)/(1+x^(2n)) = (π/(2n)) Csc[π(2m+1)/(2n)]` (In[19], symbolic
`m`, `n`) and `∫₀^∞ x^a/(x+b)^c = b^(a+1-c) Γ(a+1)Γ(c-a-1)/Γ(c)` (In[16],

### Sector family extended to symbolic exponents (`src/calculus/integrate_residue.c`)

`residue_family_sector` now takes a symbolic numerator exponent (new
`monomial_split_sym` returns the exponent as an expression, not an `int`) and
proves its convergence gates (`c > 0`, `n > 0`, `0 < s < n`, `s = e+1`) over the

A new half-line family for `C x^a (x + b)^(-c)` with a non-integer `c` (a branch
point at `-b` that the rational Mellin engine cannot handle): `x = b t` reduces
it to `C b^(a+1-c) B(a+1, c-a-1) = C b^(a+1-c) Γ(a+1) Γ(c-a-1)/Γ(c)`, gated by

rational/integer-`c` shapes still reach the Mellin engine first.

## Residue `Integrate`: Mellin-after-power-substitution (Gamma / generalized Fresnel) ; v0.281

**Outcome: `∫₀^∞ x^(s-1) e^(-a x²) = (1/2) a^(-s/2) Γ(s/2)` (In[9]) and
`∫₀^∞ x^p Sin[x²] = (1/2) Γ((p+1)/2) Sin[π(p+1)/4]` (In[10]) now close under
`Method -> "Residue"`.**

### `residue_family_mellin_power` (`src/calculus/integrate_residue.c`)

A new half-line family for `C x^(μ-1) G(κ x^ν)` with `G ∈ {Exp, Sin, Cos}` and
`ν` a positive integer.  The substitution `u = x^ν` turns it into
`(C/ν)` times the Mellin transform of `G` at `s = μ/ν`:
`Exp[-c u] → Γ(s) c^(-s)` (Re s > 0), `Sin[k u] → Γ(s) k^(-s) Sin[π s/2]` and
`Cos[k u] → Γ(s) k^(-s) Cos[π s/2]` (0 < Re s < 1, k > 0) — the standard
sector/wedge contour.  Convergence is proved over the assumed region with the
`res_region_*` helpers.  Covers `x^(s-1) e^(-a x²)`, `x^p Sin[x²]`,
`x^p Cos[x²]`, and the plain `Sin[x³] = Γ(4/3)/2`.

Convergence must be stated as `s > 0` / `0 < s < 1` rather than the complex
spelling `Re[s] > 0`: `Refine` cannot combine a `Re[...] > 0` conjunct with a
sibling (e.g. `Refine[-a < 0, Re[s] > 0 && a > 0]` fails to use `a > 0`), so
`x^(s-1) e^(-a x²)` wants `Assumptions -> s > 0 && a > 0`.

## Residue `Integrate`: periodic-strip hyperbolic family + `Arg` under assumptions ; v0.280

**Outcome: `N(x)/Cosh[b x]` integrals over `(-Infinity, Infinity)` with a symbolic
non-integer `b` now close.  `Integrate[Exp[a x]/Cosh[Pi x]] = Sec[a/2]` (In[4]),
`Integrate[Cosh[a x]/Cosh[b x]] = (Pi/b) Sec[Pi a/(2b)]` (In[21]),
`Integrate[Exp[I a x]/Cosh[b x]] = (Pi/b) Sech[Pi a/(2b)]` (In[18]), and
`Integrate[x/Sinh[a x], {x,0,Infinity}] = Pi^2/(4 a^2)` (In[12]).**

### `residue_family_hyperbolic_strip` (`src/calculus/integrate_residue.c`)

A new whole-line family for `N(x)/Cosh[b x]`.  The quasi-period
`Cosh[b(x + i Pi/b)] = -Cosh[b x]` folds the infinite ladder of poles into the
single enclosed pole at `x = i Pi/(2 b)`, giving, per exponential term,
`Integrate[E^(alpha x)/Cosh[b x]] = (Pi/b) Sec[alpha Pi/(2 b)]` for
`|Re alpha| < Re b`.  `TrigToExp` turns a `Cosh`/`Sinh`/`Exp` numerator into such
a sum, so the three In[4]/In[18]/In[21] shapes are all covered; convergence is
proved per term with `Refine`.  This handles the symbolic non-integer `b` that the
`w = Exp[x]` rectangular reduction cannot rationalise (`Cosh[b Log w]` is a
non-integer power of `w`).

### Scale normalisation in `residue_family_rectangular`

A common positive coefficient `c` on `x` in the hyperbolic/exp arguments
(`Sinh[a x]`) is normalised to `1` by substituting `x -> x/c` (Jacobian `1/c`)
before the `w = Exp[x]` reduction, which needs a unit coefficient.  So
`x/Sinh[a x]` reduces to `(1/a^2) u/Sinh[u]` and closes via the existing a=1
keyhole route (In[12]).  The symbolic-`a` closed form carries an unsimplified but
correct keyhole `Arg` surface (same `Simplify` gap as In[17]); the concrete-scale
form `x/Sinh[2 x] = Pi^2/16` is fully reduced.

### `Refine[Arg[...], assumptions]` (`src/simp/simp_assume_rewrite.c`)

`Refine` now reduces `Arg` of a sign-provable quantity that `ComplexExpand`
(sign-agnostic) leaves standing: `Arg[positive] -> 0`, `Arg[negative] -> Pi`, and
`Arg[(i c) * positive] -> +-Pi/2`.  `prov_pos` already descends `Times`/`Power`,
so `Arg[a^2]`, `Arg[2 a]`, `Arg[1/a^2]`, `Arg[I a]`, `Arg[2 I a]` all reduce under
`a > 0` (only `Arg[a]` did before).  (This does not by itself tidy the In[17]/In[12]
keyhole outputs, whose closer uses `ComplexExpand`, not `Refine`, and on which a
`PowerExpand` pass would be unsound — it would turn `Arg[-4 a^2] = Pi` into
`Arg[a^2] = 0` and drop a factor.)

## Residue `Integrate`: positivity-aware close for two-pole-pair rationals ; v0.279

**Outcome: `Integrate[1/((x^2+a^2)(x^2+b^2)), {x, 0, Infinity}, Assumptions -> a>0 && b>0,
Method -> "Residue"]` now returns `Pi/(2 a b (a+b))` (Case In[7]) instead of a
correct-but-unreadable nested-surd expression.**

### `res_close_positive` + `close_algebraic` (`src/calculus/integrate_residue.c`)

`solve_roots` returns the quartic `(x^2+a^2)(x^2+b^2)` poles unfactored, and
`close_algebraic`'s `RootReduce` canonicalises the residue sum into nested surds
(`Sqrt[(a+b)^2 (a-b)^2]`, `Sqrt[-2 a^2]`) that plain `Simplify` leaves standing. A
new `res_close_positive` helper — `Simplify[Refine[Simplify[PowerExpand[e]],
assumptions]]`, run only when every parameter is known positive (`g_inst &&
g_all_pos`) and the raw assumptions are available (`g_assume`, added in v0.278) —
collapses them: `PowerExpand` turns `Sqrt[-c^2]` into `I c` and
`Sqrt[(a+b)^2 (a-b)^2]` into `(a+b)(a-b)`, and `Refine` discharges the residual
sign choices. `close_algebraic` applies it to the `RootReduce`d form. A no-op
(plain `Simplify`) outside all-positive symbolic mode, so the numeric and
one-pole-pair cases (`1/(x^2+a^2)`, `1/(1+x^4)`, the Fourier/trig answers) are
unchanged.

**Known limitation (documented, not a regression):** two sibling cases stay
correct but unsimplified, because the needed reductions are gaps in `Simplify`/
`Refine` rather than the residue method: `Integrate[Log[x]/(x^2+a^2), {x,0,Inf},
Assumptions -> a>0]` returns an `Arg[...]`-laden form equal to `Pi Log[a]/(2a)`
(`Arg[I a]` does not reduce to `Pi/2` for a symbolic positive `a`), and

## Residue `Integrate`: symbolic-coefficient Gaussian + an `Exponent` degree bug ; v0.278

**Outcome: `Integrate[Exp[-a x^2] Cos[b x], {x, 0, Infinity}, Assumptions -> a>0 && b>0,

## Residue `Integrate`: Fourier axis-pole correctness + a `FactorTerms` zero bug ; v0.277

**Outcome: fixes a silent WRONG ANSWER.
`Integrate[Sin[a x]/(x (x^2+b^2)), {x, -Infinity, Infinity}, Assumptions -> a>0 && b>0,
Method -> "Residue"]` returned `0`; the correct value is `(Pi/b^2)(1 - e^(-a b))`.
Two independent bugs combined to produce it, one of them in a core polynomial
routine that was silently poisoning `Simplify` far beyond residues.**

### The Fourier conjugation (`src/calculus/integrate_residue.c`)

The Jordan/Fourier family already classified the removable real-axis pole at
`x=0` correctly (a weight-1 half-residue) alongside the enclosed pole at `I b`.
But in symbolic-parameter mode the `Cos`/`Sin` extraction conjugated the contour
value by `ReplaceAll[J, I -> -I]`, which rewrites only the interned `+I` symbol
and leaves a stored `-I` (`Complex[0,-1]`) atom untouched.  With a mixed-sign
residue sum (axis half-residue `+I/b^2` plus enclosed `-I e^(-a b)/b^2`) the
`e^(-a b)` term cancelled against itself and the result collapsed.  The closing
now takes `ComplexExpand[Re[J]]` (Cos) and `ComplexExpand[Im[J]]` (Sin):
`ComplexExpand` treats every free parameter as real — which they are here — so it
conjugates both `+I` and `-I` atoms correctly and returns a clean closed form.
The brittle `res_conjugate` helper is removed.

### `FactorTerms` never fabricates a `0` content (`src/poly/facpoly_factorterms.inc`)

The deeper half: the family forms `J = Simplify[Together[Pi I S]]`, and
`Simplify`'s search ran `FactorTerms` as a candidate transform.  When an upstream
`Together` fails to clear a symbolic denominator it can leave a Laurent term
(`b^-1`) inside the numerator; the nonnegative-degree coefficient extraction in
`ft_content_wrt_set` then finds no monomials and returned a **content of `0`**,
which multiplied the whole factor list down to a spurious `0`.  `Simplify` trusts
a transform's literal `0` and early-exits — so `Simplify[(I - I Exp[-a b])/b^2]`
wrongly returned `0` (any `I` coefficient + ≥2 distinct function-head variables +
a symbolic denominator triggered it).  The content of a nonzero expression is a
unit, never `0`: `ft_content_wrt_set` now returns `1` when it extracts no
monomial structure from a nonzero input.  This is reachable only on the
pathological non-polynomial (Laurent) input — a genuine polynomial always has a
nonzero coefficient — so no correct case changes.

Verified: In[14] `= (Pi/b^2)(1 - e^(-a b))` and In[15]
`Exp[I a x]/(x^2 - 2 I b x - c) = -2 Pi e^(-a b) Sin[a Sqrt[c - b^2]]/Sqrt[c - b^2]`;
the whole Fourier regression (`Cos[a x]/(x^2+b^2)`, `x Sin[a x]/(x^2+b^2)`,
`Sin[x]/x`, `Cos[a x]/(x^2+b^2)^2`, …) is unchanged; `FactorTerms`,
`FactorTermsList`, `FullSimplify`, `Together`/`Cancel`, `ratcanon`, `limit`, and
the residue suites are green.

## Residue `Integrate`: unit-circle trig with symbolic parameters (Case 16) ; v0.272

**Outcome: `Method -> "Residue"` now evaluates `Integrate[R(Cos x, Sin x), {x,0,2π},

### Coupled-assumption instantiation (`build_instantiation`, `src/calculus/integrate_residue.c`)

The symbolic-parameter mode reads pole signs at a representative point of the
assumption region.  `absorb_fact` reduces only INDEPENDENT numeric bounds, so a
