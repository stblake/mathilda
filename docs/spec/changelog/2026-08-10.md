# Changelog: week of 2026-08-10 (Mon) – 2026-08-16 (Sun)

Feature additions and fixes recorded during this week.

## Build: clear GCC 16 compiler warnings (2026-08-11)

Silenced every warning emitted by `gcc-16 -O3 -std=c99 -Wall -Wextra` across
seven files, most of them `-Wmisleading-indentation` from two statements sharing
a line. One was a latent bug rather than cosmetics:

- **`src/list/find_clusters.c`** (`-Wmaybe-uninitialized`) —
  `fc_method_gaussianmixture` read `sv[n - 1] - sv[0]` before the `n == 0`
  guard, an out-of-bounds read on empty input (`sv[-1]`). Now computed as
  `(n > 0) ? sv[n - 1] - sv[0] : 0.0`, folding the empty case into the existing
  zero-spread branch.
- **`src/calculus/series.c`** (`-Walloc-size`) — the `n < m` branch of the
  PolyGamma-at-infinity expansion passed `calloc(0, sizeof(Expr*))`;
  `build_recip_seriesdata` ignores the pointer when `len == 0` and only
  `free()`s it, so this is now `NULL`.
- **`-Wmisleading-indentation`** — split two-statements-per-line in
  `src/poly/ratcanon.c` (`rcp_igcd`/`rcp_ilcm`), `src/compile/compile_infer.c`
  (`infer_type`), `src/compile/compile_vm.c` (`VLOAD_C` case bodies),
  `src/graphics/complexplot.c` (clamp lines in both plot builders), and
  `src/graphics/densityplot.c` (cleanup path).

No built-in behavior changed. Verified by recompiling all seven files warning-free
and re-running the affected surfaces (`Series[PolyGamma[...], {x, Infinity, n}]`
including the `n < m` empty-coefficient path, and `FindClusters[..., Method ->
"GaussianMixture"]` including the all-identical degenerate case).

## Build: de-duplicate `-lgmp`/`-lmpfr` link flags (2026-08-11)

`pkg-config --libs flint` (and GMP-ECM) re-list `-lgmp`/`-lmpfr`, which the base
`LDFLAGS` and MPFR block already carry, so the raw link line repeated them and
macOS `ld` printed `ignoring duplicate libraries: '-lgmp', '-lmpfr'`. Added a
small `LDFLAGS_DEDUP` helper in `makefile` that collapses each `-l` flag to a
single copy, **keeping its last occurrence** so a provider (`-lgmp`) still
follows every consumer (`-lflint`, `-lmpfr`, `-lecm`) — the dependency order a
static-archive link needs, and the reason `FLINT_LIBS` is appended after the base
`-lgmp`. `-L` search paths and two-word `-framework X` tokens pass through
untouched. The warning is gone; the binary links and runs identically.
