# Changelog: week of 2026-09-21 (Mon) – 2026-09-27 (Sun)

## `AlgebraicNumberNorm`

New head **`AlgebraicNumberNorm[a]`** — the field norm of an algebraic number: the
product of the roots of its minimal polynomial (equivalently, the product of the
conjugates of `a` over the rationals). Faithful to the Wolfram Language and a
companion to the other `AlgebraicNumber*` heads.

- **Absolute norm, exact and cheap.** From the `qqbar` primitive integer minimal
  polynomial `c_n x^n + ... + c_0` the norm is `(-1)^n c_0 / c_n` — a two-coefficient
  read, no field build. Integers and rationals return themselves
  (`AlgebraicNumberNorm[2]` → `2`, `AlgebraicNumberNorm[-2/3]` → `-2/3`); radicals,
  roots of unity, `Root` and `AlgebraicNumber` objects all work
  (`Sqrt[2]` → `-2`, `1/Sqrt[Sqrt[2]+3]` → `1/7`, `E^(Pi I/8)` → `1`,
  `Root[-1+#1+#1^2+#1^3+#1^4&,1]` → `-1`, `AlgebraicNumber[Sqrt[2] I,{1,2}]` → `9`,
  `9+Sqrt[10]` → `71`).
- **`GoldenRatio` now algebraic in the `qqbar` layer.** The shared converter
  `to_qqbar` (and `flint_qqbar_is_constant_algebraic`) recognises `GoldenRatio` as
  `(1+Sqrt[5])/2` — the sole algebraic named constant — so `AlgebraicNumberNorm[GoldenRatio]`
  → `-1`, and `RootReduce`, `AlgebraicNumber`, `ToNumberField` and the algebraic
  comparison surface gain `GoldenRatio` for free.
- **Relative norm via `Extension -> theta`.** `AlgebraicNumberNorm[a, Extension -> theta]`
  is the norm over `Q(theta)` for `a ∈ Q(theta)`, computed by transitivity of the norm
  in the tower `Q ⊆ Q(a) ⊆ Q(theta)`:
  `N_{Q(theta)/Q}(a) = N_{Q(a)/Q}(a)^{[Q(theta):Q(a)]}` (the absolute norm raised to the
  tower index; membership decided by `qqbar_express_in_field`). So
  `AlgebraicNumberNorm[Sqrt[2], Extension -> E^(Pi I/4)]` → `4`,
  `AlgebraicNumberNorm[2 Sqrt[5], Extension -> Sqrt[5]]` → `-20`, and a norm computed
  in the compositum `Q(Sqrt[3], Sqrt[-5])` (via `ToNumberField[…, All]`) → `64`. The
  norm is multiplicative over a fixed field.
- **Attributes** `{Listable, Protected}`, default option `Extension -> None`:
  `AlgebraicNumberNorm[{2 Sqrt[2], E^(Pi I/8), 1+I}]` → `{-8, 1, 2}`, with a trailing
  `Extension` option repeated across the list.
- **Diagnostics**: a non-algebraic argument emits `AlgebraicNumberNorm::nalg`; an
  argument not in the extension field emits `AlgebraicNumberNorm::ext`; either stays
  unevaluated.

Requires FLINT (the `qqbar` engine); a `USE_FLINT=0` build leaves the head
unevaluated.

## `AlgebraicNumberTrace`

New head **`AlgebraicNumberTrace[a]`** — the field trace of an algebraic number: the
sum of the roots of its minimal polynomial (equivalently, the sum of the conjugates
of `a` over the rationals). The additive counterpart of `AlgebraicNumberNorm`, and
faithful to the Wolfram Language.

- **Absolute trace, exact and cheap.** From the `qqbar` primitive integer minimal
  polynomial `c_n x^n + ... + c_0` the trace is `-c_{n-1} / c_n` — a two-coefficient
  read, no field build. Integers and rationals return themselves
  (`AlgebraicNumberTrace[2]` → `2`, `AlgebraicNumberTrace[-2/3]` → `-2/3`); radicals,
  roots of unity, `Root` and `AlgebraicNumber` objects all work
  (`5+Sqrt[2]` → `10`, `Sqrt[1+Sqrt[2]]` → `0`, `GoldenRatio` → `1`,
  `E^(Pi I/8)` → `0`, `Root[#1^4+11#1^3+#1^2+#1+1&,1]` → `-11`,
  `AlgebraicNumber[Sqrt[2] I,{1,2}]` → `2`).
- **Relative trace via `Extension -> theta`.** `AlgebraicNumberTrace[a, Extension -> theta]`
  is the trace over `Q(theta)` for `a ∈ Q(theta)`, computed by transitivity of the
  trace in the tower `Q ⊆ Q(a) ⊆ Q(theta)`:
  `Tr_{Q(theta)/Q}(a) = [Q(theta):Q(a)] · Tr_{Q(a)/Q}(a)` (the absolute trace scaled
  by the tower index; membership decided by `qqbar_express_in_field`). So
  `AlgebraicNumberTrace[5, Extension -> Sqrt[2]]` → `10`,
  `AlgebraicNumberTrace[3, Extension -> Sqrt[2]+Sqrt[3]]` → `12`, and
  `AlgebraicNumberTrace[E^(2 Pi I/3), Extension -> ToNumberField[{2^(1/3), E^(2 Pi I/3)}, All][[1,1]]]`
  → `-3`. The trace is additive over a fixed field.
- **Attributes** `{Listable, Protected}`, default option `Extension -> None`:
  `AlgebraicNumberTrace[{5+Sqrt[2], E^(Pi I/8)}]` → `{10, 0}`, with a trailing
  `Extension` option repeated across the list.
- **Diagnostics**: a non-algebraic argument emits `AlgebraicNumberTrace::nalg`; an
  argument not in the extension field emits `AlgebraicNumberTrace::ext`; either stays
  unevaluated.

Requires FLINT (the `qqbar` engine); a `USE_FLINT=0` build leaves the head
unevaluated.

`src/poly/flint_qqbar.c` (a two-coefficient min-poly read via the new

## `AlgebraicNumberDenominator`

New head **`AlgebraicNumberDenominator[a]`** — the smallest positive integer `n`
such that `n a` is an algebraic integer. Faithful to the Wolfram Language, and the
companion to [`AlgebraicIntegerQ`](../builtins/algebra.md#algebraicintegerq)
(`AlgebraicIntegerQ[x]` is the `AlgebraicNumberDenominator[x] == 1` case).

- **Same argument surface as `AlgebraicIntegerQ`**: rationals, radicals
  (`1/Sqrt[3]` → `3`, `1/Sqrt[Sqrt[2]+3]` → `7`, `(1+3I)^(-1/3)` → `10`), `Root`
  objects (`Root[5-6#1+3#1^3&,1]` → `3`), and `AlgebraicNumber` objects
  (`AlgebraicNumber[Sqrt[2],{1/5,1}]` → `5`). An algebraic integer gives `1`.
- **Exact, and correct where the naive route is not**: computed from the minimal
  polynomial by a **per-prime valuation**, not the raw min-poly leading
  coefficient. The two diverge — `1/5 + Sqrt[2]` has primitive minimal polynomial
  `25 x^2 - 10 x - 49` (leading coefficient `25`) yet denominator `5`, because
  `5 (1/5 + Sqrt[2]) = 1 + 5 Sqrt[2]` is already an algebraic integer. Writing the
  monic minimal polynomial of `n a`, its `x^i` coefficient is `(a_i/a_n) n^{n-i}`,
  so `n` is the least integer with `denom(a_i/a_n) | n^{n-i}` for every `i`;
  `n | a_n`, so one factorisation of `a_n` plus a valuation scan is exact.
- **Attributes** `{Listable, Protected}`: `AlgebraicNumberDenominator[{Sqrt[2],
  1/Sqrt[2], 1/3}]` → `{1, 2, 3}`. By construction
  `AlgebraicIntegerQ[AlgebraicNumberDenominator[a] a]` is `True`, so `n a` (equally
  `n ToNumberField[a, theta]`) is the algebraic-integer numerator of `a = alpha/n`.
- **Diagnostics**: a non-algebraic argument (`Pi`, a free symbol) emits
  `AlgebraicNumberDenominator::nalg` and stays unevaluated.

Requires FLINT (the `qqbar` engine); a `USE_FLINT=0` build leaves the head
unevaluated.

Implementation: engine function `flint_qqbar_algebraic_number_denominator` in
`src/poly/flint_qqbar.c` (reusing `to_qqbar` and `expr_from_fmpz`, with FLINT's
`fmpz_factor`/`fmpz_remove` for the valuation), thin WL wrapper
`src/poly/algebraicnumberdenominator.c` (new, registered from `src/core.c`),
docstring in `src/info.c`, `SYM_AlgebraicNumberDenominator` in

`SKIP_EXPLOSIVE` in `tools/nd_fastpath_sweep.py` (a Listable head whose per-element
cost is a qqbar min-poly + integer factorisation, not a numeric buffer fast path).
`v0.158`.

## `NumberFieldIntegralBasis` and `AlgebraicIntegerQ`

Two new heads for algebraic-integer computations in a number field, faithful to
the Wolfram Language.

**`NumberFieldIntegralBasis[a]`** — an integral basis for the field `Q(a)`
generated by the algebraic number `a`: a list of algebraic integers generating
the ring of integers `O_K` as a module over `Z`.

- **Maximal order, not just the equation order**: forms the algebraic-integer
  generator `phi` of `Q(a)` (rescaling `a` when it is not an algebraic integer,
  e.g. `Root[2+3#^3&,2]` → `phi = 3 a`), then enlarges `Z[phi]` to `O_K` by
  **Round 2 (Pohst–Zassenhaus)** wherever it is not already maximal. So
  non-monogenic fields are correct: `Q(Sqrt[5])` gives `{1, (1+Sqrt[5])/2}` (not
  `Z[Sqrt[5]]`), and `Q(Sqrt[2]+Sqrt[3])` a genuine 4-element basis.
- **Canonical presentation**: the (arbitrarily-ordered, unreduced) Round-2 basis
  is put into the standard lower-triangular Hermite normal form in the
  theta-power basis, so the result begins with `1` and each element `omega_k` has
  degree `k`. Monogenic fields are unchanged (`{1, theta, ..., theta^(n-1)}`).
- **Result form**: each element is a canonical `AlgebraicNumber` object (or a
  plain integer/rational); apply `N` for the numeric display. `Q(a) = Q` gives
  `{1}`.
- **Attributes** `{Listable, Protected}`: `NumberFieldIntegralBasis[{a1, ...}]`
  threads to one basis per generator.
- **Diagnostics**: a non-algebraic argument, a degree over the cap, or an
  uncertifiable maximal order emits `NumberFieldIntegralBasis::nintbas` and stays
  unevaluated.

**`AlgebraicIntegerQ[x]`** — `True` iff `x` is an algebraic integer, decided
exactly: its primitive integer minimal polynomial is monic. Rational integers
qualify; non-integer rationals, non-algebraic quantities (`Pi`), symbols, and
lists do not (`Protected`, not `Listable`). Companion predicate for the integral
basis: every returned element, and every integer combination of them, is an
algebraic integer.

Both require FLINT (the `qqbar` engine plus the number-field maximal-order layer
`src/numbertheory/`); a `USE_FLINT=0` build leaves the heads unevaluated.

Implementation: engine functions `flint_qqbar_integral_basis` /
`flint_qqbar_algebraic_integer_q` in `src/poly/flint_qqbar.c` (reusing
`to_qqbar`, `algint_generator`, `poly_to_algnum`, and `nf_field_create` /
`nf_ok_basis`), thin WL wrappers `src/poly/numberfieldintegralbasis.c` and
`src/poly/algebraicintegerq.c` (new, registered from `src/core.c`), docstrings in
`src/info.c`, `SYM_NumberFieldIntegralBasis` / `SYM_AlgebraicIntegerQ` in
`src/sym_names.{c,h}`, tests in `tests/test_numberfieldintegralbasis.c`.
`NumberFieldIntegralBasis` added to `SKIP_EXPLOSIVE` in
`tools/nd_fastpath_sweep.py` (a Listable head returning symbolic objects, not a
numeric buffer fast path). `v0.157`.

## `AlgebraicNumberPolynomial`

New head **`AlgebraicNumberPolynomial[a, x]`** — the inverse view of
[`AlgebraicNumber`](../builtins/algebra.md#algebraicnumber): for
`a = AlgebraicNumber[theta, {c0, ..., cn}]` it returns the polynomial
`c0 + c1 x + ... + cn x^n`, from which `a` is recovered by `x -> theta`. Faithful
to the Wolfram Language.

- **Number passthrough**: an integer or rational `a` is the constant polynomial and
  is returned unchanged (`AlgebraicNumberPolynomial[2, x]` → `2`,
  `AlgebraicNumberPolynomial[1/2, x]` → `1/2`).
- **Polynomial build**: reads the coefficient vector already stored in the
  `AlgebraicNumber` object and assembles `c0 + c1 x + ... + cn x^n`; the evaluator
  drops zero terms and orders monomials by degree
  (`AlgebraicNumber[2^(1/3), {1,0,3}]` → `1 + 3 x^2`).
- **Attributes** `{Listable, Protected}`: threads over lists in both arguments
  (`AlgebraicNumberPolynomial[{2, AlgebraicNumber[Sqrt[2], {1,2}]}, x]` →
  `{2, 1 + 2 x}`).
- **Diagnostics**: a non-`AlgebraicNumber`, non-rational argument emits
  `AlgebraicNumberPolynomial::naobj` and stays unevaluated.
- **Use**: makes same-generator algebraic-number arithmetic explicit at the
  polynomial level — adding two `AlgebraicNumberPolynomial` results, substituting
  the generator, and `RootReduce`-ing reproduces the sum of the numbers.

Purely structural (coefficient read + polynomial build): **no FLINT** is used, so
the head is usable in a `USE_FLINT=0` build (though only a FLINT build produces the
`AlgebraicNumber` objects it consumes).

Implementation: `src/poly/algebraicnumberpolynomial.c` (new, registered from
`src/core.c`), docstring in `src/info.c`, `SYM_AlgebraicNumberPolynomial` in
`src/sym_names.{c,h}`, tests in `tests/test_algebraicnumberpolynomial.c` and the
leak gate `tests/scripts/algebraicnumberpolynomial_leakcheck.sh`. Added to
`SKIP_EXPLOSIVE` in `tools/nd_fastpath_sweep.py` (a Listable thread of a numeric
no-op, not a missing buffer fast path — the head returns a symbolic polynomial).
`v0.156`.
