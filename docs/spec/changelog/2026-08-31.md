# Changelog: week of 2026-08-31 (Mon) – 2026-09-06 (Sun)

## ReadProtected attribute removed system-wide

Mathilda is fully open source and never hides a symbol's definition, so the
`ReadProtected` attribute has been removed entirely. The flag
(`ATTR_READPROTECTED`, bit 11 of `attr.h`) is gone, `SetAttributes`/`Attributes`
no longer recognise or emit `ReadProtected` (`attr.c`, `SYM_ReadProtected`
dropped from `sym_names`), and it has been stripped from every builtin that set
it (~75 modules) and from the two `.m` tables (`IntegrateTable`,
`Integrate`CRCTable`). `Attributes[f]` for the affected heads now reads e.g.
`{Listable, NumericFunction, Protected}` (Beta, AiryAi, …), `{Protected}`
(DSolve, D, Dt, Limit, Integrate, Area, …), `{Listable, Protected}` (NextPrime).
Tests that asserted `ReadProtected` were updated; docs/reference pages refreshed
(historical changelogs left as-is).

## DSolve — no longer HoldAll

`DSolve` (and every `DSolve`<Method>`) dropped `HoldAll`; attributes are now
`Protected`, matching Mathematica. HoldAll was unnecessary — with
the dependent function undefined, `y'[x] == a Sin[x]` and point conditions
`y[0] == 5` evaluate to unevaluated `Equal[...]` on their own, so equations reach
the solver formal without holding, and the `D[...]`→`Derivative[...]` fold happens
under normal evaluation. It was also harmful: HoldAll made an equation stored in a
variable (`eq = y'[x] + y[x] == a Sin[x]; DSolve[eq, y, x]`) come through as the
bare symbol `eq` and decline; that now solves. Guarded by `t_not_holdall`.

## DSolve — FirstOrderSubstitution (1a) and AutonomousReduction (1d)

Two new methods extend the `DSolve` cascade (`DSOLVE_PLAN.md`), each producing
general solutions the substrate verifies by back-substitution.

### `DSolve`FirstOrderSubstitution` — `y'[x] == F(a x + b y + c)`

The solved-for-`y'` companion to `Homogeneous`: fires when the RHS depends on
`x` and `y` only through one linear combination — a form no earlier first-order
method (linear / separable / homogeneous / exact) recognises. Writing the RHS as
`F(x, Y)` (`Y` a plain symbol for `y[x]`), the level curves are the straight
lines of constant combination, so `F` is a function of that combination iff the
ratio `r = F_x / F_y` is constant. With `v = y + r x`,

```
v' = y' + r = F + r = H(v) + r,   H(W) := F(x, W - r x)  (free of x),
```

an autonomous separable equation solved inline by `Integrate[1/(r + H), W] == x
+ C[1]`, solved for `W = v`, then `y = v - r x`. The ratio is collapsed with
`Simplify` before the substitution (it must be textually free of `Y`), so a
proved-constant ratio that `Simplify` cannot reduce is declined rather than
corrupted.

```
In[1]:= DSolve[y'[x] == (x + y[x])^2, y[x], x]
Out[1]= {{y[x] -> -x - Tan[-C[1] - x]}}

In[2]:= DSolve[y'[x] == (2 y[x] - x)^2, y[x], x]        (* combination 2y - x, r = -1/2 *)
Out[2]= {{y[x] -> x/2 - Tanh[Sqrt[2] (C[1] + x)]/(2 Sqrt[2])}}
```

Cases whose separated antiderivative `Solve` cannot invert (e.g.
`y' == Sqrt[x+y]`, `y' == (x+2y)^3`) stay symbolic rather than shipping an
implicit/wrong answer.

### `DSolve`AutonomousReduction` — `y''[x] == f(y, y')` missing `x`

The nonlinear-higher-order case where `x` is absent. Regarding `p = y'` as a
function of `y`, `y'' = p p'(y)`, so the equation becomes the first-order ODE
`p p'(y) == f(y, p)`, solved by recursing into the scalar cascade; then
`y' == P(y)` (also autonomous, hence separable) is solved by a second recursion.
The two integration constants are kept distinct across the recursions (the first
stage's `C[1]` is frozen to a private marker and renamed `C[2]` afterward). A
degenerate `y = const` — which trivially satisfies any autonomous equation and
would pass back-substitution (cf. the M4 wrong-`Integrate` lesson) — is rejected
by requiring the final body to depend on `x`.

Runs after the linear methods, so genuinely linear autonomous equations
(`y'' == -y`, …) are claimed by the cleaner method first; this one catches the
nonlinear remainder:

```
In[3]:= DSolve[y[x] y''[x] == y'[x]^2, y[x], x]
Out[3]= {{y[x] -> C[1] E^(C[2] x)}}

In[4]:= DSolve[y[x] y''[x] == 2 y'[x]^2, y[x], x]
Out[4]= {{y[x] -> 1/(C[1] - C[2] x)}}
```

Non-elementary / elliptic reductions (`y'' == 2 y^3`, `y'' == -Sin[y]`) stay
symbolic.

### Substrate / cascade

Both methods follow the three-function contract (`_try` + `builtin_` via
`dsolve_method_builtin` + `_init`) with `ATTR_PROTECTED` and
docstrings; appended to the automatic cascade after
`ReductionOfOrder` and to the `Method ->` dispatch, callable as
`DSolve`FirstOrderSubstitution[...]` / `DSolve`AutonomousReduction[...]`.

Tests (`tests/test_dsolve.c`): per-method unit cases (specific closed forms,
named-method entry, and decline-stays-symbolic boundaries) plus randomized
stress families back-substitution-verified — `k (a x + a y + c)^2` /
`(m x + y)^2` for FirstOrderSubstitution, `a y y'' == b (y')^2` for
AutonomousReduction. Gates: `dsolve_tests` green, `make check-c99` clean,
valgrind shows no leak delta over a baseline running the same sub-engines.
